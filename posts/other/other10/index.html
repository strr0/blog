Hexo 博客搭建

strr0 2024-12-24

1 概述

快速、简洁且高效的博客框架——Hexo 是 Node.js 生态的静态博客生成器，写完 Markdown 一条 hexo generate 编译成静态站点。

与 Hugo（Hugo 博客搭建）的核心差异就在运行时：Hexo 依赖 Node + npm（主题、插件都是 npm 包，生态量大但装依赖慢、版本容易碎），Hugo 是单二进制无依赖。两者选型建议：图省心选 Hugo，需要现成 Hexo 主题（如 NexT/Butterfly 的 Hexo 版）再选 Hexo。

本文两条部署路线：3.3.1 GitHub Actions 自动构建（推代码即发布），3.3.2 hexo-deployer-git 本地构建后推 gh-pages 分支。

2 环境配置

2.1 Nodejs 环境

参考 Node.js 版本管理工具 Volta

2.2 安装 Hexo

npm install hexo-cli -g

3 博客搭建

3.1 初始化

创建博客目录

hexo init <folder>

进入博客目录

cd <folder>

下载依赖

npm install --registry=https://registry.npmmirror.com

国内直连 npm 经常超时，--registry 临时指定镜像，想一劳永逸就 npm config set registry https://registry.npmmirror.com。Node 版本交给 Volta 管（参考 2.1），避免 Hexo 依赖的原生模块在新旧 Node 间编译失败。

3.2 添加博客

添加页面

hexo new <layout> --path <path> <title>

在页面中写博客内容

运行

hexo server

3.3 部署

3.3.1 自动化部署

.github/workflows/pages.yml

name: Pages

on:
  push:
    branches:
      - main # default branch

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          token: ${{ secrets.GITHUB_TOKEN }}
          # If your repository depends on submodule, please see: https://github.com/actions/checkout
          submodules: recursive
      - name: Use Node.js 20
        uses: actions/setup-node@v4
        with:
          # Examples: 20, 18.19, >=16.20.2, lts/Iron, lts/Hydrogen, *, latest, current, node
          # Ref: https://github.com/actions/setup-node#supported-version-syntax
          node-version: "20"
      - name: Cache NPM dependencies
        uses: actions/cache@v4
        with:
          path: node_modules
          key: ${{ runner.OS }}-npm-cache
          restore-keys: |
            ${{ runner.OS }}-npm-cache
      - name: Install Dependencies
        run: npm install
      - name: Build
        run: npm run build
      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./public
  deploy:
    needs: build
    permissions:
      pages: write
      id-token: write
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

3.3.2 手动部署

安装 hexo-deployer-git

npm install hexo-deployer-git --save

--save 不能省，否则依赖没写进 package.json，下次换机器/Actions 重建时 hexo deploy 会报找不到 deployer。

在 _config.yml 中添加以下配置

deploy:
  type: git
  repo: https://github.com/<username>/<project>
  # example, https://github.com/hexojs/hexojs.github.io
  branch: gh-pages

部署

hexo clean && hexo deploy

自动化部署（3.3.1）里的 npm run build 需要项目根目录 package.json 定义了 "build": "hexo generate" 脚本；Hexo 默认只有 hexo generate，若直接跑 Actions 会报 missing script: build，要么补脚本要么把步骤改成 run: npx hexo generate。手动部署则把仓库 Settings -> Pages 的 Source 选为对应分支（如 gh-pages）。

4 小结

  • Hexo 栈 = Node + npm：先把 Node 版本用 Volta 锁好，再把 npm 换成国内镜像，不然 init 和装插件两步都会碎。
  • 写文章用 hexo new <title>（在 source/_posts 生成 md），hexo server 本地预览默认 4000 端口，hexo generate 产物在 public/。
  • 部署二选一：Actions 自动推即发布（需 package.json 有 build 脚本）；hexo-deployer-git 本地推 gh-pages（deployer 要 --save）。
  • 与 Hugo 本质区别：Hexo 功能同质但多一层 Node 依赖，构建慢、升级易碎；新建站优先 Hugo，除非已有 Hexo 主题生态需求。
