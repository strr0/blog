Hugo 博客搭建

strr0 2024-12-22

1 概述

世界上最快的网站构建框架——Hugo 把一堆 Markdown + 模板在本地编译成纯静态 HTML，单个 Go 二进制无依赖、构建秒级，天然适合 GitHub Pages 这种静态托管。

和动态博客（WordPress）或 Hexo（Node 系）相比：

HugoHexo
运行时单个 Go 二进制Node.js + npm 依赖
构建速度最快（百篇亚秒级）较慢（依赖多）
主题生态丰富，但配置语言是 TOML丰富，配置是 YAML

两个选型前先定的点：本教程用 hugo extended（带内嵌 Dart Sass，能编译主题里的 .scss，普通版不行）；主题目录推荐用 git submodule 管理，下文 3.4 的 workflow 里 submodules: recursive 就是为这个准备的。

3 博客搭建

3.1 初始化

创建博客目录

hugo new site <folder>

进入博客目录

cd <folder>

下载主题到 themes 目录，如 LoveIt

设置主题

echo "theme = 'LoveIt'" >> config.toml

运行

hugo server

3.3 添加博客

添加页面

hugo new content <path>

在页面中写博客内容

运行

hugo server

3.4 自动化部署

.github/workflows/hugo.yml

# Sample workflow for building and deploying a Hugo site to GitHub Pages
name: Deploy Hugo site to Pages

on:
  # Runs on pushes targeting the default branch
  push:
    branches: ["master"]

  # Allows you to run this workflow manually from the Actions tab
  workflow_dispatch:

# Sets permissions of the GITHUB_TOKEN to allow deployment to GitHub Pages
permissions:
  contents: read
  pages: write
  id-token: write

# Allow only one concurrent deployment, skipping runs queued between the run in-progress and latest queued.
# However, do NOT cancel in-progress runs as we want to allow these production deployments to complete.
concurrency:
  group: "pages"
  cancel-in-progress: false

# Default to bash
defaults:
  run:
    shell: bash

jobs:
  # Build job
  build:
    runs-on: ubuntu-20.04
    env:
      HUGO_VERSION: 0.108.0
    steps:
      - name: Install Hugo CLI
        run: |
          wget -O ${{ runner.temp }}/hugo.deb https://github.com/gohugoio/hugo/releases/download/v${HUGO_VERSION}/hugo_extended_${HUGO_VERSION}_linux-amd64.deb \
          && sudo dpkg -i ${{ runner.temp }}/hugo.deb
      - name: Install Dart Sass Embedded
        run: sudo snap install dart-sass-embedded
      - name: Checkout
        uses: actions/checkout@v3
        with:
          submodules: recursive
      - name: Setup Pages
        id: pages
        uses: actions/configure-pages@v3.0.0
      - name: Install Node.js dependencies
        run: "[[ -f package-lock.json || -f npm-shrinkwrap.json ]] && npm ci || true"
      - name: Build with Hugo
        env:
          # For maximum backward compatibility with Hugo modules
          HUGO_ENVIRONMENT: production
          HUGO_ENV: production
        run: |
          hugo \
            --minify \
            --baseURL "${{ steps.pages.outputs.base_url }}/"
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v1
        with:
          path: ./public

  # Deployment job
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-20.04
    needs: build
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v2

这份 workflow 几个要改的地方：branches: ["master"] 要改成你的实际分支名（很多新仓库默认是 main）；ubuntu-20.04 GitHub 已弃用，换成 ubuntu-latest；HUGO_VERSION 锁定一个与你本地一致的版本，避免 Actions 构建结果和本地预览不同步。部署完在仓库 Settings -> Pages 把 Source 选为 GitHub Actions（不是 Branch）。

4 小结

  • 安装选 hugo extended（带 Sass），否则 LoveIt 这类需要编译 SCSS 的主题会报 to resolve imports you need extended。
  • 初始化三件套：hugo new site → 主题放进 themes/ → config.toml 写 theme = '...'；跑 hugo server -D 本地预览（-D 连 draft 一起渲染）。
  • 新文章用 hugo new content posts/xxx.md，front matter 默认 draft: true，写完要改 false 才会出现在成品站。
  • 自动化部署本质是：push 触发 → Actions 装 hugo → hugo --minify 构建到 public → upload-pages-artifact → deploy-pages；前提仓库 Settings 的 Pages Source 选 GitHub Actions。
