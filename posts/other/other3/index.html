0 Overview

四套工具的定位和消费方式各不相同，选哪套取决于你手上有什么服务端/订阅：

协议/角色本地端口特点
Shadowsocksss 加密协议，client（sslocal）+ server（ssserver）SOCKS 1080单一协议，Rust 实现单二进制好部署
ShadowsocksRss 的 SSR 分支（协议/混淆插件）SOCKS 1080Python2 老项目，仅兼容存量 SSR 服务
Clash多协议代理池 + 规则分流HTTP 7890 / SOCKS 7891吃订阅、可编程分流，配合环境变量最常用
V2rayvmess 等协议，完整平台SOCKS 1080配置 JSON 手写，功能多但心智负担大

后文每种给 Regular（二进制/源码）和 Docker 两种部署方式，端口以各自默认值为准。

1 Shadowsocks

1.1 Regular

1.1.1 Download release

从 releases 页取最新版本号替换 <version>：

wget https://github.com/shadowsocks/shadowsocks-rust/releases/download/<version>/shadowsocks-<version>.x86_64-unknown-linux-gnu.tar.xz

1.1.2 Decompression

tar -xvf shadowsocks-<version>.x86_64-unknown-linux-gnu.tar.xz

1.1.3 Enter directory

cd shadowsocks-<version>.x86_64-unknown-linux-gnu

解压出来的 bin 目录里有 sslocal/ssserver/ssmanager 等可执行文件，建议整个目录拷到 /opt 后把 bin 加进 PATH，或直接 install -m755 bin/* /usr/local/bin/。

1.1.4 Client

Start local client with configuration file
# Read local client configuration from file
sslocal -c /path/to/shadowsocks.json
Socks5 Local client
# Pass all parameters via command line
sslocal -b "127.0.0.1:1080" -s "[::1]:8388" -m "aes-256-gcm" -k "hello-kitty" --plugin "v2ray-plugin" --plugin-opts "server;tls;host=github.com"

# Pass server with SIP002 URL
sslocal -b "127.0.0.1:1080" --server-url "ss://YWVzLTI1Ni1nY206cGFzc3dvcmQ@127.0.0.1:8388/?plugin=v2ray-plugin%3Bserver%3Btls%3Bhost%3Dgithub.com"
HTTP Local client
sslocal -b "127.0.0.1:3128" --protocol http -s "[::1]:8388" -m "aes-256-gcm" -k "hello-kitty"

All parameters are the same as Socks5 client, except --protocol http.

SIP002 的 ss:// URL 就是把协议、密码（base64）、服务器、插件拼成一行的订阅格式，手机客户端直接扫这个即可。-b 监听地址默认只给本机用，想让局域网设备连改成 0.0.0.0:1080 并自行保证可信网络。插件（v2ray-plugin）需要单独下载同目录放可执行路径下，否则报 plugin not found。

1.1.5 Server

Start server with configuration file
# Read server configuration from file
ssserver -c /path/to/shadowsocks.json
Start server
# Pass all parameters via command line
ssserver -s "[::]:8388" -m "aes-256-gcm" -k "hello-kitty" --plugin "v2ray-plugin" --plugin-opts "server;tls;host=github.com"

服务端与客户端的参数必须一一对应：-m/-k/插件 opts 任何一项不一致都连不上（握手失败通常只表现为 timeout，排查先比对这两侧）。aes-256-gcm 这类 AEAD 加密是底线，老的 table/rc4 方法已不安全；ssmanager 适合多用户（一个进程按 users 列表管多个端口/密码）。前台跑只适合调试，长期运行建议写成 systemd service。

1.2 Docker

This project provided Docker images for the linux/i386 and linux/amd64 and linux/arm64/v8 architectures.

⚠️ Docker containers do not have access to IPv6 by default: Make sure to disable IPv6 Route in the client or enable IPv6 access to docker containers.

1.2.1 Pull from GitHub Container Registry

Docker will pull the image of the appropriate architecture from our GitHub Packages.

docker pull ghcr.io/shadowsocks/sslocal-rust:v1.21.2
docker pull ghcr.io/shadowsocks/ssserver-rust:v1.21.2

版本号跟 releases 同步，用前先确认最新 tag。

1.2.2 Build on the local machine（Optional）

If you want to build the Docker image yourself, you need to use the BuildX.

docker buildx build -t shadowsocks/ssserver-rust:v1.21.2 -t shadowsocks/ssserver-rust:v1.21.2 --target ssserver .
docker buildx build -t shadowsocks/sslocal-rust:v1.21.2 -t shadowsocks/sslocal-rust:v1.21.2 --target sslocal .

官方 README 原文如此（-t 重复写了两遍，等价于只写一个）；在源码仓库根目录执行，. 不能漏。

1.2.3 Run the container

You need to mount the configuration file into the container and create an external port map for the container to connect to it.

docker run -d \
    --name sslocal-rust \
    --restart always \
    -p 1080:1080/tcp \
    -v /path/to/config.json:/etc/shadowsocks-rust/config.json \
    ghcr.io/shadowsocks/sslocal-rust:v1.21.2

docker run -d \
    --name ssserver-rust \
    --restart always \
    -p 8388:8388/tcp \
    -p 8388:8388/udp \
    -v /path/to/config.json:/etc/shadowsocks-rust/config.json \
    ghcr.io/shadowsocks/ssserver-rust:v1.21.2

两个容器都要把配置里的监听地址写成 0.0.0.0（容器内默认 127.0.0.1 的话外部映射无效）；ssserver 的 UDP 映射不能省，DNS 查询走 UDP。开头那条 IPv6 警告的意思是：配置写了 [::] 但容器无 IPv6 时启动报错，去掉 IPv6 相关项即可。Docker 网络、卷的通用背景见 Linux 环境下 Docker 的安装与使用。

1.3 Configuration

{
    "server": "my_server_ip",
    "server_port": 8388,
    "password": "rwQc8qPXVsRpGx3uW+Y3Lj4Y42yF9Bs0xg1pmx8/+bo=",
    "method": "aes-256-gcm",
    // ONLY FOR `sslocal`
    // Delete these lines if you are running `ssserver` or `ssmanager`
    "local_address": "127.0.0.1",
    "local_port": 1080
}

server 侧留 server/server_port/password/method，local 侧另加 local_address/local_port（注释里已标）。JSON 标准不支持 // 注释，shadowsocks-rust 宽容地允许，但换其他实现时可能被拒，建议注释单独存文档。

1.4 Usage

1.4.1 Proxychains

Install proxychains
pacman -S proxychains
Add proxychains config
# /etc/proxychains.conf

socks5 127.0.0.1 1080
Using in terminal
proxychains curl www.example.com

proxychains 的原理是 LD_PRELOAD 注入 hook 套接字库，把不支持代理环境变量的老程序（部分 apt/ssh/ping 工具）拽进 SOCKS 链；所以它对静态链接/自带代理逻辑的程序无效（curl、git 自己认 http_proxy，直接设环境变量更干净）。配置里 socks5 那行必须在 [ProxyList] 段下；上游要指向已经跑起来的 sslocal。架构上 sslocal（SOCKS 1080）是源头，proxychains/privoxy 只是不同的消费方式。

1.4.2 Privoxy

Install privoxy
pacman -S privoxy
Add privoxy config
# /etc/privoxy/config

forward-socks5 / 127.0.0.1:1080 .
listen-address  127.0.0.1:8118
Start browser with privoxy
systemctl start privoxy
chromium --proxy-server="http://127.0.0.1:8118"

Privoxy 把 SOCKS5 转成 HTTP 代理（很多工具只支持 http 代理不支持 socks5，这就是中转的意义）；forward-socks5 行末尾那个 . 是必填的 forwarder 参数占位，删了会启动失败。也可以不开浏览器参数，直接 export http_proxy=http://127.0.0.1:8118 https_proxy=http://127.0.0.1:8118 给终端用。

2 ShadowsocksR

2.1 Regular

2.1.1 Obtain source code

git clone -b manyuser https://github.com/shadowsocksr-backup/shadowsocksr.git

manyuser 是 SSR 的多用户分支（单用户用 master）；注意 SSR 是 Python2 项目，Python2 已 EOL，新系统（如新版 Arch/Ubuntu）默认没有 python2，要么装 python2 包要么直接换用 shadowsocks-rust 的 SSR 兼容实现。没有存量 SSR 服务的话，建议直接用第 1 节。

2.1.2 Enter subdirectory

cd shadowsocksr/shadowsocks

2.1.3 Running via command line

python local.py -s <server_ip> \
    -p <port> \
    -k <keyphrase> \
    -m <encryption> \
    -o <obfus> \
    -O <protocol> \
    -l <local_port>

2.1.4 Running via configuration file

python local.py -c /etc/shadowsocks.json

2.1.5 Stop or restart the daemon

python local.py -d stop/restart

-d start 后台化时依赖配置文件里写了 pid_file，否则 stop/restart 找不到进程；命令行方式（2.1.3）不带 -d 只会前台运行。SSR 特有的 -o（混淆）/-O（协议）参数必须与服务端一致，这两个不对时表现为连上但立即断流。

2.2 Docker

2.2.1 Pull from Container Registry

docker pull breakwa11/shadowsocksr:manyuser

2.2.2 Running in docker

docker run -d \
    --name ssrlocal \
    --restart always \
    -p 1080:1080/tcp \
    -v /path/to/config.json:/etc/shadowsocks.json \
    breakwa11/shadowsocksr:manyuser python local.py -c /etc/shadowsocks.json

镜像是作者当年发布的，基础镜像和 Python2 都很久没更新，仅建议参考；配置中的 protocol/obfs 两项是 SSR 区别于 SS 的核心（auth_aes128_md5 + tls1.2_ticket_auth 是常用组合，与服务端不匹配时报错和裸 SS 一样只能 timeout）。

3 Clash

3.1 Docker

3.1.1 Pull from Container Registry

docker pull dreamacro/clash:v1.18.0

3.1.2 Run the container

docker run -d \
    --name clash \
    --restart always \
    -p 7890:7890 \
    -p 7891:7891 \
    -p 7892:7892 \
    -p 9090:9090 \
    -p 5353:5353/udp \
    -p 5353:5353/tcp \
    -v /path/to/config.yaml:/root/.config/clash/config.yaml \
    dreamacro/clash:v1.18.0

3.2 Configuration

配置体量大，抓四个骨干块看：端口与模式（port/socks-port/mode）、proxies（节点定义）、proxy-groups（分组策略：relay 串联/url-test 测速择优/fallback 按优先级/load-balance 分流/select 手动）、rules（域名/IP 匹配到分组或 DIRECT/REJECT）。几个实用点：

  • allow-lan: true + bind-address: "*" 才能让手机/其他设备用这台机器的 7890，同时要确保 external-controller 设了 secret，否则任何人都能改你的分流。
  • mode: rule 下未命中规则的流量走最后的 MATCH；国内直连、其余代理的经典写法就是 GEOIP,CN,DIRECT + MATCH,Proxy。
  • dns 那段注释掉的配置在 fake-ip 模式下会让某些内网/局域网域名解析异常，遇到“域名解析对了但连不上”先把 enhanced-mode 换回 redir-host 验证。
  • 订阅转换用 proxy-providers（http 拉取 + interval 自动刷新），不用每次手动重写 proxies 列表。

3.3.1 Proxy

export https_proxy=http://127.0.0.1:7890
export http_proxy=http://127.0.0.1:7890
export all_proxy=socks5://127.0.0.1:7891

三个坑：变量名用小写（HTTP_PROXY 大写形式部分老程序不认）；这只对尊重 *_proxy 约定的程序生效（curl/git/wget/apt 认，ping、某些 CLI 自带连接的不认，那些用 proxychains 或 -c 指定）；写进 ~/.bashrc 后新 shell 才生效，临时关代理 unset http_proxy https_proxy all_proxy。长期用可以做成两个 alias（proxyon/proxyoff）避免忘关导致内网访问也走代理。

3.3.2 Dashboard

Clash 的 RESTful API（9090）可以直接查分流和切分组，配合 external-ui 指向 clash-dashboard 静态文件后有 Web 界面：

curl -H "Authorization: Bearer <secret>" http://127.0.0.1:9090/proxies

4 V2ray

4.1 Regular

4.1.1 Obtain binaries file

wget https://github.com/v2fly/v2ray-core/releases/download/<version>/v2ray-linux-64.zip

v2fly 是 v2ray 社区维护分支（原 v2ray 项目已停止公开更新）；linux-64 指 x86_64，ARM 机器下 linux-arm / linux-arm64。

4.1.2 Decompression

unzip v2ray-linux-64.zip

4.1.3 Enter subdirectory

cd v2ray-linux-64

4.1.4 Running via command line

v2ray run -c /etc/v2ray/config.json

新版二进制自带 v2ray 子命令集，v2ray uuid 可以直接生成 clients 里要的 id；配置改完用 v2ray test -config /etc/v2ray/config.json 验证语法再起进程，比起了才发现连不上省力。服务端长期运行同样建议 systemd unit。

4.2 Docker

4.2.1 Pull from Container Registry

docker pull v2fly/v2fly-core:v5.16.1

4.2.2 Run the container

docker run -d \
    --name v2ray \
    -p 10086:10086 \
    -v /path/to/config.json:/etc/v2ray/config.json \
    v2fly/v2fly-core:v5.16.1 run -c /etc/v2ray/config.json

镜像默认入口就是 v2ray run，命令尾部重复写一遍是为显式指定配置路径；--restart always 没写，宿主机重启后容器不会自起，建议补上。

4.3 Configuration

4.3.1 Server

服务端最小配置就是「一个 vmess 入口 + freedom 出口」：

{
    "inbounds": [
        {
            "port": 10086, // 服务器监听端口
            "protocol": "vmess",
            "settings": {
                "clients": [
                    {
                        "id": "b831381d-6324-4d53-ad4f-8cda48b30811"
                    }
                ]
            }
        }
    ],
    "outbounds": [
        {
            "protocol": "freedom"
        }
    ]
}

4.3.2 Client

客户端配置多了三样东西：本地 SOCKS 入口、指向服务端的 vmess 出口、以及「内网地址直连」的路由规则：

{
    "inbounds": [
        {
            "port": 1080, // SOCKS 代理端口，在浏览器中需配置代理并指向这个端口
            "listen": "127.0.0.1",
            "protocol": "socks",
            "settings": {
                "udp": true
            }
        }
    ],
    "outbounds": [
        {
            "protocol": "vmess",
            "settings": {
                "vnext": [
                    {
                        "address": "server", // 服务器地址，请修改为你自己的服务器 ip 或域名
                        "port": 10086, // 服务器端口
                        "users": [
                            {
                                "id": "b831381d-6324-4d53-ad4f-8cda48b30811"
                            }
                        ]
                    }
                ]
            }
        },
        {
            "protocol": "freedom",
            "tag": "direct"
        }
    ],
    "routing": {
        "domainStrategy": "IPOnDemand",
        "rules": [
            {
                "type": "field",
                "ip": [
                    "geoip:private"
                ],
                "outboundTag": "direct"
            }
        ]
    }
}

两侧的 id 必须一致（服务端 clients 登记、客户端 users 携带，相当于认证凭证）；geoip:private 规则让 192.168.x、127.x 这类内网目标不穿代理直连，否则局域网打印机/NAS 会被绕到服务端出去。想对比更省心的分流写法可以看第 3 节 Clash 的 rules；这里的路由能力更弱，需要域名分流要手写 domain 规则或接外置 geojson。

5 小结

  • 选型：只有自建单协议服务用 SS(rust)；吃订阅、要分流用 Clash；存量 SSR/v2ray 服务再对应选 2/4 节。
  • 链路角色要分清：客户端进程（sslocal/clash/v2ray 本地入口）产出 SOCKS/HTTP 端口，proxychains、Privoxy、*_proxy 环境变量只是三种不同的消费方式，可以叠加。
  • Docker 部署三个通用检查：监听地址写 0.0.0.0、TCP/UDP 都要映射、--restart always。
  • 排查顺序：本地端口在听吗（ss -tlnp）→ 环境变量生效了吗（curl -v 看 CONNECT）→ 服务端参数匹配吗（timeout 多半是加密/插件不一致）。
