一加 6T 刷入 Windows 及 Linux 等系统

strr0 2025-02-09

概述

一加 6T（代号 fajita，骁龙 845）刷机指南。这代旗舰硬件余量足、社区支持成熟，是「手机再利用」的热门机型：闲置手机可以变成 Windows 便携设备、Linux 掌机，或一套类原生 Android。

四条路线按用途选择：

路线目标系统核心组件适用场景
第 2 章 刷 WindowsWindows on ARM（WOA）edk2-msm UEFI + WOA-Drivers跑 ARM Win 桌面与软件
第 3 章 刷 PostmarketOS基于 Alpine 的移动 LinuxpmOS 官方移植 image移动 Linux、折腾研究
第 4 章 刷 Mobian基于 Debian 的移动系统Mobian qcom weekly image需要 Debian 生态
第 5 章 刷 PixelExperience类原生定制 ROMPE 官方包 + vbmeta/super 处理替代官方 Android 日用

所有路线的公共前置是第 1 章：装 USB 刷机驱动、开 USB 调试、解 BL 锁、刷 TWRP。动手前明确三件事：

  • 解 BL 锁会清空全部数据，且解锁后部分银行类应用会检测拒绝运行；
  • 调制解调器相关分区（fsc/fsg/modemst1/modemst2）存着基带校准数据和 IMEI，刷 Windows 路线务必先按 2.3 备份，丢失后修复基带的代价远大于刷机本身；
  • 系统与 Android 依靠 A/B slot 共存（Android 在 slot a，新系统在 slot b），理解 3.4 的切换逻辑再动手，出问题才有退路。

1 前置准备

1.1 驱动安装

一加手机可以从 daxiaamu 下载驱动

adb 与 fastboot 找不到设备问题：1. 驱动未安装（正常模式与 fastboot 模式在 Windows 里是两个不同设备实例，adb 驱动和高通 HS-USB（fastboot）驱动要分别装全）；2. 手动从 此电脑 > 管理 > 设备管理器 选择未识别的设备右键 更新驱动程序软件

1.2 开启 USB 调试

多次点击 关于手机 > 版本号 开启开发者模式

开启 系统 > 开发者选项 的 OEM 解锁 及 USB 调试

1.3 解除 BL 锁

手机连接电脑

进 fastboot 模式

adb reboot bootloader

解锁

fastboot flashing unlock

解除 BL 锁会删除数据并重启（这是安全设计：解锁后设备进入校验放宽状态），重启后重新 1.2 开启 USB 调试

1.4 刷入 TWRP

1.4.1 有 Recovery 分区

adb reboot bootloader
fastboot flash recovery twrp-<version>.img

1.4.2 无 Recovery 分区

进入临时 TWRP

adb reboot bootloader
fastboot boot twrp-<version>.img

上传加固包到手机

adb push twrp-installer-<version>.zip /tmp

在 TWRP 中 Install > Install Image 选择加固包并刷入

在新版本 Android 中取消了 Recovery 分区，加入了 A/B 分区（系统更新或卡刷 rom 时会在另一个 inactive 的分区中执行，执行完成后切换到这个分区，如果执行失败则退回原来的分区，两个分区共享一套 userdata），而 Recovery 为 Boot 分区的一个部分，需要通过卡刷的方式刷入

2 刷入 Windows

2.1 设备支持情况

查看 设备支持情况 以决定是否继续刷入

2.2 下载所需文件

Windows 路线三件套，缺一不可：edk2-msm 的 UEFI 镜像负责「让手机能像 PC 一样从 ESP 引导 Windows」（手机原生固件只认 Android 启动格式）；UUP Dump 的 ARM64 镜像是系统本体；WOA Drivers 负责补齐高通硬件驱动（Windows 自带的通用驱动认不全手机的回波消除触摸屏、传感器、GPU 等）：

从 UUP Dump 下载 Arm 版 Windows 镜像

从 WOA 下载对应设备驱动

从 edk2-msm 下载对应设备 UEFI 镜像

下载 Android Platform Tools

下载分区工具 parted

2.3 备份

后续分区操作会重格 Data，Windows 路线也可能弄坏 modem 数据，所以先把三类东西备份到电脑。手机进入 TWRP 并连接电脑，备份调制解调器（fsc/fsg 是配置区，modemst1/2 是基带数据区，四块全备，缺一不可）：

adb shell
dd if=/dev/block/by-name/fsc of=/tmp/fsc
dd if=/dev/block/by-name/fsg of=/tmp/fsg
dd if=/dev/block/by-name/modemst1 of=/tmp/bootmodem_fs1
dd if=/dev/block/by-name/modemst2 of=/tmp/bootmodem_fs2

下载备份文件到电脑

adb pull /tmp/fsc
adb pull /tmp/fsg
adb pull /tmp/bootmodem_fs1
adb pull /tmp/bootmodem_fs2

骁龙 845 及骁龙 855 设备需要配置调制解调器才能使数据及短信正常工作

在 TWRP 中 Backup 选择 Data 分区备份

下载备份文件到电脑

adb pull /sdcard/TWRP/BACKUPS

中文乱码问题：中文字体存在 Data 分区中，需提前备份

备份 boot

adb pull /dev/block/by-name/boot_a boot.img

刷 root 权限需要

2.4 分区操作

从 userdata 尾部切出两块新分区：esp（FAT32，放 Windows 引导文件）和 win（NTFS，装系统本体）。

在 TWRP 中 Mount 取消 Data 分区挂载（parted 改分区表时文件系统必须处于未挂载状态，否则有损坏风险）

上传分区工具到手机

adb push parted /tmp

授权及分区

adb shell
cd /tmp
chmod +x parted
./parted /dev/block/sda

打印分区信息

print

压缩 userdata 分区

resizepart <num>  # 如 resizepart 17 （userdata 在第 17 个分区），然后输入压缩后的 End 地址

创建 esp 分区

mkpart esp fat32 <start> <end>  # 如 mkpart esp fat32 20GB 20.3GB
set <num> esp on  # 如 set 18 esp on （esp 在第 18 个分区）

创建 win 分区

mkpart win ntfs <start> <end>  # 如 mkpart win ntfs 20.3GB -0MB

退出

quit

退出 ADB Shell 后，在 TWRP 中 Wipe > Format Data 格式化分区

重启系统查看 Android 是否正常启动，正常启动后系统中文乱码，重启到 TWRP

上传备份 Data 分区到手机

adb push BACKUPS /sdcard/TWRP

在 TWRP 中 Restore 选择备份的 Data 分区还原

再重启系统查看乱码是否正常了

重启到 TWRP，执行格式化

adb shell mkfs.ntfs -f /dev/block/by-name/win -L WIN
adb shell mkfs.fat -F32 -s1 /dev/block/by-name/esp -n ESP

2.5 安装

重启到 fastboot，用 edk2-msm 的 UEFI 镜像临时启动（releases 里的文件就叫 boot.img，本质是 UEFI 固件而非安卓内核）：

fastboot boot boot.img

在 UEFI 菜单选择 Simple Init > Mass Storage 进入大容量存储模式——手机的 esp/win 分区会以 USB 磁盘形式出现在电脑上，接下来的 DISKPART / DISM 命令全部在电脑的管理员命令提示符里执行：

进入 DISKPART

diskpart

分配盘符

lis dis                               # 获取磁盘信息
sel dis <num>                         # 如 sel dis 6 （手机磁盘为 6）
lis par                               # 获取分区信息
sel par <num>                         # 如 sel par 23 （esp 分区为 23）
format quick fs=fat32 label="System"  # 格式化
assign letter="S"                     # 分配盘符
sel par <num>                         # 如 sel par 24 （win 分区为 24）
format quick fs=ntfs label="Windows"  # 格式化
assign letter="W"                     # 分配盘符
exit

获取镜像 index（install.wim 里包含家庭版/专业版等多个版本，记下目标版本对应的编号）

dism /get-imageinfo /ImageFile:path\to\install.wim

按 index 部署镜像到 win 分区（下例 /index:1 需替换为上一步查到的实际编号）

dism /apply-image /ImageFile:<path/to/install.wim> /index:1 /ApplyDir:W:\

添加引导

bcdboot W:\Windows /s S: /f UEFI

把 WOA 驱动包离线注入镜像（相比进系统后手动装，离线注入能解决首次启动就没触摸/没显示的问题）

dism /Image:W: /Add-Driver /Driver:<path to the driver folder> /Recurse

启用测试签名及禁用自动修复（WOA 驱动没有微软签名，testsigning on 才允许加载；recoveryenabled no 防止启动失败几次后自动跳进 WinRE 循环「启动修复」）：

cd S:\EFI\Microsoft\Boot
bcdedit /store BCD /set "{default}" testsigning on
bcdedit /store BCD /set "{default}" nointegritychecks on
bcdedit /store BCD /set "{default}" recoveryenabled no

取消挂载

mountvol S: /d

2.6 启动

重启到 fastboot，启动 UEFI（和 2.5 一样用 fastboot boot 临时方式；想每次开机直接进 Windows，可后续把 UEFI 镜像刷进 boot_b 分区配合 slot 切换）

成功进入 Windows 的 OOBE 初始设置界面后，按 Shift + F10 调出命令行

oobe\bypassnro  # 设置离线安装 Win11

bypassnro 是微软官方提供的跳过开关：重启后 OOBE 多出「我没有 Internet」入口，可建本地账户完成设置——不做这步，Win11 家庭版会强制要求联网 + 微软账户才能激活。

2.7 修复

走完 Windows 流程后若发现移动网络失效（读不到卡、无法数据/短信），说明 modem 数据被改动，把 2.3 备份的文件写回原分区即可恢复基带：

重启到 TWRP，上传备份文件

adb push fsc /tmp
adb push fsg /tmp
adb push bootmodem_fs1 /tmp
adb push bootmodem_fs2 /tmp

恢复备份文件

dd if=/tmp/fsc of=/dev/block/by-name/fsc
dd if=/tmp/fsg of=/dev/block/by-name/fsg
dd if=/tmp/bootmodem_fs1 of=/dev/block/by-name/modemst1
dd if=/tmp/bootmodem_fs2 of=/dev/block/by-name/modemst2

3 刷入 PostmarketOS

PostmarketOS 是基于 Alpine Linux 的移动发行版，给手机带来「真正的 Linux」（完整包管理、可 ssh、可起服务）。fajita 有官方移植 image，流程与刷 Windows 同源：备份→分区→刷入，只是分区名和镜像不同。同类设备的 pmOS 刷机背景可参考 三星 note2 刷入 PostmarketOS 系统。

3.1 下载所需文件

下载设备对应 image

3.2 分区操作

中文乱码问题见上述刷入 Windows 的 2.4 分区操作 处理

在 TWRP 中 Mount 取消 Data 分区挂载

上传分区工具到手机

adb push parted /tmp

授权及分区

adb shell
cd /tmp
chmod +x parted
./parted /dev/block/sda

打印分区信息

print

压缩 userdata 分区

resizepart <num>  # 如 resizepart 17 （userdata 在第 17 个分区），然后输入压缩后的 End 地址

创建 systempmos 分区

mkpart systempmos ext4 <start> <end>  # 如 mkpart systempmos ext4 90GB -0MB

退出

quit

退出 ADB Shell 后，在 TWRP 中 Wipe > Format Data 格式化分区

重启到 TWRP，执行格式化

adb shell mke2fs /dev/block/by-name/systempmos

3.3 刷入镜像

重启到 fastboot 刷入镜像（boot 镜像落在 slot b 的 boot_b；erase dtbo_b 清掉原安卓 DTBO 设备树覆盖层，避免与 pmOS 的设备树冲突）：

fastboot set_active b
fastboot erase dtbo_b
fastboot flash boot <pmos-boot.img>
fastboot flash systempmos <pmos.img>

3.4 Android 与 PostmarketOS 切换

3.4.1 Android 下

重启到 TWRP

在 TWRP 中 Reboot 选择 Slot B，重启则切换到 PostmarketOS

3.4.2 PostmarketOS 下

pmOS 内用 qbootctl 切换 slot（移植包提供的命令行小工具，等价于电脑上的 fastboot set_active）：

sudo qbootctl -s a

重启则切换到 Android

Mobian 是基于 Debian 的移动系统（叠加 Phosh/GNOME Mobile 外壳），软件仓库直接吃 Debian 上游。刷机流程与第 3 章几乎相同：同样压 userdata、建 ext4 分区、占 slot b，只是分区名为 mobian、镜像换成 Mobian weekly：

4.1 下载所需文件

下载设备对应 image

chmod +x parted

5 刷入 PixelExperience

PixelExperience 是基于 AOSP 的类原生定制 ROM，性质与前四条路线不同：它不是「共存的另一系统」而是直接替换 Android 本体，所以前置准备的重点是固件同步与动态分区清理。

5.1 前置准备

5.1.1 升级系统

升级到 HydrogenOS 11 或 OxygenOS 11

5.1.2 分区固件同步

A/B 两个 slot 的 modem/dtbo 等固件分区可能不同步，刷 PE 前先执行官方同步包，否则可能出现基带异常或卡刷失败：

下载同步包 copy-partitions-20210323_1922.zip

重启到 TWRP，在 TWRP 中 Apply Update 选择 Apply from ADB，刷入同步包

adb sideload copy-partitions-20210323_1922.zip

5.1.3 初始化动态分区

PE 的 vbmeta 镜像已关闭 dm-verity/验证（不关的话刷完开机会卡在「系统已损坏」校验界面）；下面这组操作相当于把 super 动态分区在两个 slot 上各「清空」一遍再切回 a：

重启到 fastboot

刷入 vbmeta

fastboot flash vbmeta_a vbmeta.img
fastboot flash vbmeta_b vbmeta.img

刷入 recovery

fastboot flash boot <recovery_filename>.img

擦除旧分区数据

fastboot erase system_a
fastboot erase system_b
fastboot erase odm_a
fastboot erase odm_b
fastboot erase vendor_a
fastboot erase vendor_b

重启到 recovery 再进入 fastboot

刷入 super_empty

# 当前为 a 分区
fastboot wipe-super super_empty.img
fastboot set_active b
fastboot wipe-super super_empty.img
fastboot set_active a

5.2 刷入镜像

下载 PixelExperience

重启到 recovery，在 recovery 中 Apply Update 选择 Apply from ADB，刷入

adb sideload filename.zip

小结

  • 动手前：解 BL 锁清空数据；fsc/fsg/modemst1/modemst2 必须 dd 备份到电脑，基带数据丢失的修复代价远大于刷机本身。
  • Windows 路线的本质是「三件套 + 重新分区」：edk2-msm 模拟 UEFI 引导，install.wim 用 DISM 部署进 win 分区，WOA 驱动 dism /Add-Driver 离线注入，testsigning on 后才允许未签名驱动加载。
  • pmOS/Mobian 同一套路：parted 压缩 userdata 建 ext4 分区装系统镜像，boot 刷到 slot b 与 Android（slot a）共存，qbootctl -s a/b（或 TWRP 的 Slot B 菜单）完成切换。
  • PixelExperience 不建新分区，但要 copy-partitions 同步固件、刷 vbmeta 关校验、super_empty 清空两 slot 后再 sideload ROM。
  • 任何路线翻车的第一退路：fastboot 重进 TWRP → Restore Data 备份 / 写回 boot 备份 → 需要时 dd 恢复 modem 四分区。
