适用于 Windows 的 Linux 子系统

strr0 2023-04-06

1 概述

WSL（Windows Subsystem for Linux）是在 Windows 上直接运行原生 Linux 二进制可执行文件的兼容层：启动秒级、和 Windows 互访丝滑（挂载盘在 /mnt/c）、不额外占虚拟机内存。代价是需要开启虚拟化相关功能，老印象里会和 VMware/安卓模拟器冲突，这个问题现代版本已经缓解（见下）。

两代实现的差异决定了它能干什么：

WSL1WSL2
实现翻译表把 Linux 系统调用转成 Windows 调用轻量 Hyper-V 虚拟机里跑真 Linux 内核
跨文件系统 IO快慢（9P 协议）
系统调用兼容不完整（Docker、systemd、部分内核功能不可用）完整
网络与 Windows 共享 IP独立 NAT 网卡（WSL2 localhost 转发只支持 Windows→Linux 方向）

本文用 WSL2。另外纠正一个老观念：开启 WSL2 必需的功能是「虚拟机平台（Virtual Machine Platform）」而不一定是完整的 Hyper-V；VMware 15.5.6+/VirtualBox 6.1+ 已经支持和 WSL2 共存，只有更老的虚拟化软件才需要关 Hyper-V 二选一。

2 环境配置

2.1 WSL 环境

Windows 10 版本 2004 及更高版本（内部版本 19041 及更高版本）或 Windows 11 使用自动安装，否则使用手动安装

2.1.1 自动安装

管理员 PowerShell 执行安装命令

wsl --install

默认会装 WSL2 + Ubuntu 并启用所需功能；wsl --install -d <distribution> 可以直接指定发行版，wsl --list --online 看可选列表。装完重启后首次从开始菜单启动发行版会要求创建 Linux 用户和密码（这是 Linux 侧的用户，和 Windows 账号无关）。

2.1.2 手动安装

适用于老版本 Windows 或不想用默认发行版的场景，四步按顺序做：

2.1.2.1 启用“适用于 Linux 的 Windows 子系统”可选功能

管理员 PowerShell：

dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
2.1.2.2 检查运行 WSL 2 的要求

若要更新到 WSL 2，需要运行 Windows 10 对于 x64 系统：版本 1903 或更高版本，内部版本为 18362 或更高版本。 对于 ARM64 系统：版本 2004 或更高版本，内部版本为 19041 或更高版本。 或 Windows 11。

版本/内部版号用 winver 查看；同时要确认 BIOS 里虚拟化（Intel VT-x / AMD-V）已开，否则后面启动会报 虚拟化未启用。

2.1.2.3 启用“虚拟机平台”可选功能
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart

两步 dism 执行完重启电脑，否则后续命令报 WSL 2 需要更新其内核组件。

2.1.2.4 下载 Linux 内核更新包

下载最新包：适用于 x64 计算机的 WSL2 Linux 内核更新包 运行上一步中下载的更新包。

Win11/新版 Win10 这步可以省略，wsl --update 会自动处理内核；MSI 只针对还不支持 wsl --update 的老版本。

2.1.2.5 将 WSL 2 设置为默认版本
wsl --set-default-version 2

2.2 Linux 发行版

2.2.1 安装

2.2.1.1 从商店下载
  • Ubuntu 22.04 LTS
  • openSUSE Leap 15.1
  • Kali Linux
  • Debian GNU/Linux
  • Fedora Remix for WSL
  • Alpine WSL

商店安装有个坑：默认装到 C 盘且后续不能迁移，空间紧张时改用下面的手动方式 + --import 指定目标盘。

2.2.1.2 手动下载
  • Ubuntu 22.04 LTS
  • Debian GNU/Linux
  • Kali Linux
  • openSUSE Leap 15.3
  • Fedora Remix for WSL

手动下载的 .appx 改后缀 .zip 解压得到 *.distro.tar，再用 3.2.1 的 wsl --import 导入到任意目录，想把系统放 D 盘就走这条路。

2.2.2 配置

换源（Ubuntu22.04）

# /etc/apt/sources.list

# 默认注释了源码镜像以提高 apt update 速度，如有需要可自行取消注释
deb https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ jammy main restricted universe multiverse
# deb-src https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ jammy main restricted universe multiverse
deb https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ jammy-updates main restricted universe multiverse
# deb-src https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ jammy-updates main restricted universe multiverse
deb https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ jammy-backports main restricted universe multiverse
# deb-src https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ jammy-backports main restricted universe multiverse

# 以下安全更新软件源包含了官方源与镜像站配置，如有需要可自行修改注释切换
deb http://security.ubuntu.com/ubuntu/ jammy-security main restricted universe multiverse
# deb-src http://security.ubuntu.com/ubuntu/ jammy-security main restricted universe multiverse

# 预发布软件源，不建议启用
# deb https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ jammy-proposed main restricted universe multiverse
# # deb-src https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ jammy-proposed main restricted universe multiverse

jammy 是 22.04 的代号，换版本时要把代号同步改掉；改完 sudo apt update 验证。更省事的写法是 sudo sed -i 's@//archive.ubuntu.com@//mirrors.tuna.tsinghua.edu.cn@g' /etc/apt/sources.list。

3 使用

3.1 配置

/etc/wsl.conf 是发行版内部的配置入口，改完要在 Windows 侧 wsl --shutdown 重启该发行版才生效。常用两段：

屏蔽 Windows 环境变量

# /etc/wsl.conf

[interop]
enabled=false
appendWindowsPath=false

enabled=false 禁止从 Linux 调用 Windows 程序（wslview/explorer.exe 之类），appendWindowsPath=false 不把 Windows 的 PATH 拼进 Linux——PATH 里混入一堆 /mnt/c/... 会让 which java、tab 补全、命令行启动都变慢，还可能同名命令被 Windows 版抢占。需要互操作时只关 appendWindowsPath 保留 enabled 更实用。

新发行版还建议在 [boot] 里打开 systemd（WSL 0.51.7+/Win11 支持）：

[boot]
systemd=true

没开 systemd 时 systemctl start mysql 会报 System has not been booted with systemd，只能用 service mysql start 或直接跑守护进程命令；开了之后 MySQL/Redis 这类服务才能按正常 Linux 姿势管理。

3.2 基础操作

以下命令在 Windows 侧（PowerShell）执行：

查看 wsl 版本

wsl -l -v

设置 wsl 版本

wsl --set-version <distribution> 2

启动 wsl

wsl -d <distribution>

关闭 wsl

wsl --shutdown

导出 wsl

wsl --export <image> <image_path>

导入 wsl

wsl --import <image> <target_path> <image_path> --version 2

wsl 子系统安装列表

wslconfig /l

卸载子系统

wslconfig /u <distribution>

两个容易混淆的点：wsl --set-version 转换版本时要先 wsl --shutdown，过程是把虚拟磁盘导出再导入，大磁盘要等很久；--export/--import 的参数名字原稿叫 image 容易误导，实际是「发行版名、存放目录、tar 文件」三元组，export 出来的 tar 就是整个根文件系统。

3.3 其他操作

3.3.1 导入任何 Linux 发行版（CentOS）

在 Docker 中运行 CentOS 容器

docker run -t --name wsl_export centos ls /

将容器导出 tar 文件

docker export wsl_export > centos.tar

清理容器

docker rm wsl_export

将 tar 文件导入

wsl --import CentOS <target_path> centos.tar

原理就是把容器根文件系统导成 tar 再交给 WSL，所以任何能 docker export 的镜像都能变成 WSL 发行版。两个注意：导入后的发行版没有默认用户，进去永远是 root（商店版才有创建用户的流程）；CentOS/Alpine 这类非 Ubuntu 系没有 apt，换源要按对应包管理器自己处理。

3.3.2 安装 MySQL

更新可用的包

sudo apt update

安装 MySQL

sudo apt install mysql-server

验证

mysql --version

启动安全脚本提示符

sudo mysql_secure_installation

登录 MySQL 并设置 root 密码

sudo mysql -uroot
> alter user 'root'@'localhost' identified with 'caching_sha2_password' by '<password>'

Ubuntu 的 mysql-server 装完默认用 auth_socket 认证，root 能免密登录但不能改密码登录，上面那条 alter 同时改认证插件和密码；MySQL 8 的 caching_sha2_password 对老客户端不兼容的背景见 Linux 环境下 MySQL 的安装与使用。WSL 里没有 systemd（未开 3.1 的 systemd=true）时用 sudo service mysql start 启服务；另外 apt 装的 MySQL 只监听 127.0.0.1，想从 Windows 浏览器/客户端连，要么改 bind-address，要么用 WSL2 的 localhost 转发（Windows 连 WSL 内的 3306 默认就通，反向不行）。

3.3.3 安装 PostgreSQL

更新可用的包

sudo apt update

安装 PostgreSQL

sudo apt install postgresql postgresql-contrib

验证

psql --version

设置管理员密码

sudo passwd postgres

PostgreSQL 和 MySQL 的登录模型不同：apt 装完默认只有 postgres 系统用户，sudo -u postgres psql 直接进；passwd postgres 设的是 Linux 系统密码，要让远程/密码登录数据库还得进 psql 后 \password postgres 改角色密码，再改 pg_hba.conf 把 peer 换成 scram-sha-256。

3.3.4 安装 Redis

更新可用的包

sudo apt update

安装 Redis

sudo apt install redis-server

配置

# /etc/redis/redis.conf

## 允许远程访问
# bind 127.0.0.1 -::1
## 密码配置
requirepass password

apt 装的 Redis 默认 daemonize no 且由服务管理拉起，前台 redis-server 直接跑会占住终端；开了 3.1 的 systemd 后用 sudo systemctl restart redis-server 生效配置。bind 注掉后监听所有网卡，Windows 侧连同机其他设备都能连，requirepass 必须同步设置（参数含义与生产配置见 Linux 环境下 Redis 的安装与使用）。

4 小结

  • WSL2 是真内核轻量 VM：系统调用完整能跑 Docker/systemd，代价是跨文件系统 IO 慢——代码和数据放 Linux 侧家目录，不要放 /mnt/c。
  • 安装路径二选一：新版 wsl --install 一条命令；老版本走 dism 两步 + 内核 MSI + --set-default-version 2，中间必须重启。
  • wsl.conf 里 appendWindowsPath=false 和 [boot] systemd=true 是装机后最值得改的两个配置。
  • --export/--import 既是备份迁移手段，也是导入任意发行版/换盘安装的入口；商店版不能选安装目录，手动导入可以。
