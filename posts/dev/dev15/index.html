Spring 整合 Minio

Spring 整合 Minio

strr0 2024-10-12

1 概述

对象存储把数据当成带 key 的扁平对象管理，没有目录层级和 POSIX 语义，靠 S3 协议兼容即可在自建 MinIO 与云厂商 OSS/S3 之间平移。

文件存储最容易踩的坑是「业务代码直接依赖某个 SDK」：一旦从自建迁到云上，所有上传下载都要重写。因此本文的做法是先定义一个 IOssService 抽象，再用两套实现分别对接 MinIO 官方客户端和 Amazon S3 SDK，业务侧只依赖接口。

这样做的另一层收益是可测试性：单测里可以放一个内存实现替换掉真实存储。

2 环境配置

MinIO 服务端部署参考 MinIO 安装，本文假设 http://localhost:9000 已可访问，账号 admin。

3 Spring 配置

3.1 添加 application 配置

minio:
  url: http://localhost:9000
  accessKey: admin
  secretKey: password
  bucketName: xxx

3.2 定义配置类

定义 OssProperties（用于获取配置信息）：

@Component
@ConfigurationProperties("minio")
public class OssProperties {
    private String url;

    private String accessKey;

    private String secretKey;

    private String bucketName;

    //...
}

@ConfigurationProperties 依赖标准 getter/setter（省略的 //... 部分），并且需要开启配置元数据处理——用 @Component 直接注册即可，若改用 @EnableConfigurationProperties(OssProperties.class) 则不必再加 @Component。

accessKey / secretKey 这类凭据不应长期写在 application.yml 里，生产环境用环境变量或配置中心注入（accessKey: ${OSS_AK}）。

3.3 定义服务接口

定义 Oss 服务接口 IOssService：

public interface IOssService {
    /**
     * 是否存在桶
     */
    boolean existBucket(String name);

    /**
     * 创建桶
     */
    void createBucket(String name);

    /**
     * 删除桶
     */
    void removeBucket(String name);

    /**
     * 上传文件
     */
    void uploadFile(String bucket, File file);

    /**
     * 下载文件
     */
    void downloadFile(String bucket, String filename, String target);

    /**
     * 删除文件
     */
    void removeFile(String bucket, String filename);
}

接口只覆盖「桶 + 对象」的基本生命周期。刻意没有的方法（预签名 URL、列举、分片）留给实现类按需扩展，避免抽象层被某个厂商的特有能力污染。

4 实现一：MinIO 客户端

4.1 添加依赖

<dependency>
    <groupId>io.minio</groupId>
    <artifactId>minio</artifactId>
    <version>${minio.version}</version>
</dependency>

4.2 实现 IOssService 接口

public class OssMinioServiceImpl implements IOssService {
    private final String BASE_PATH = "test/";
    private final MinioClient minioClient;

    public OssMinioServiceImpl(OssProperties properties) {
        this.minioClient = MinioClient.builder()
                .endpoint(properties.getUrl())
                .credentials(properties.getAccessKey(), properties.getSecretKey())
                .build();
    }

    //...

    /**
     * 上传文件
     */
    @Override
    public void uploadFile(String bucket, File file) {
        try (FileInputStream in = new FileInputStream(file)) {
            minioClient.putObject(PutObjectArgs.builder()
                    .bucket(bucket)
                    .object(BASE_PATH + file.getName())
                    .stream(in, in.available(), -1)
                    .build());
        } catch (ErrorResponseException | InsufficientDataException | InternalException | InvalidKeyException
                | InvalidResponseException | IOException | NoSuchAlgorithmException | ServerException | XmlParserException e) {
            e.printStackTrace();
        }
    }

    /**
     * 下载文件
     */
    @Override
    public void downloadFile(String bucket, String filename, String target) {
        InputStream in = null;
        FileOutputStream out = null;
        try {
            in = minioClient.getObject(GetObjectArgs.builder()
                    .bucket(bucket)
                    .object(BASE_PATH + filename)
                    .build());
            out = new FileOutputStream(target);
            in.transferTo(out);
        } catch (ErrorResponseException | InsufficientDataException | InternalException | InvalidKeyException
                | InvalidResponseException | IOException | NoSuchAlgorithmException | ServerException | XmlParserException e) {
            e.printStackTrace();
        } finally {
            // close
            //...
        }
    }

    /**
     * 删除文件
     */
    @Override
    public void removeFile(String bucket, String filename) {
        try {
            minioClient.removeObject(RemoveObjectArgs.builder()
                    .bucket(bucket)
                    .object(BASE_PATH + filename)
                    .build());
        } catch (ErrorResponseException | InsufficientDataException | InternalException | InvalidKeyException
                | InvalidResponseException | IOException | NoSuchAlgorithmException | ServerException | XmlParserException e) {
            e.printStackTrace();
        }
    }
}

4.3 关键点

  • MinioClient 是线程安全的，可以作为单例 Bean 长期持有，不要每次请求都 build。
  • stream(in, in.available(), -1) 的长度参数要谨慎：available() 对 FileInputStream 恰好近似等于文件长度，但这是巧合而非保证。更稳妥的是传 file.length()；第三个参数 -1 表示由 SDK 自行决定分片大小（MinIO 会在长度未知时按 8 MiB 起倍增分片）。
  • 受检异常列表很长：这是 MinIO 7.x 的签名特征，8.x 起大量异常已收敛为非受检异常，升级时这段 catch 会因为「捕获不到」而编译失败，按提示精简即可。
  • BASE_PATH 前缀：MinIO 没有真实目录，test/xxx.txt 只是一个带斜杠的 key，但足以让控制台按前缀分层展示。

5 实现二：Amazon S3 客户端

5.1 添加依赖

<dependency>
    <groupId>com.amazonaws</groupId>
    <artifactId>aws-java-sdk-s3</artifactId>
    <version>${aws-java-sdk-s3.version}</version>
</dependency>

这是 AWS SDK for Java v1 的坐标，v1 已进入停维阶段，新项目建议直接用 v2（software.amazon.awssdk:s3）。本文沿用它的原因是：v1 的 endpoint 覆盖机制对 MinIO 这类 S3 兼容服务最直观。

5.2 实现 IOssService 接口

public class OssAmazonServiceImpl implements IOssService {
    private final String BASE_PATH = "test/";
    private final AmazonS3 client;

    public OssAmazonServiceImpl(OssProperties properties) {
        AwsClientBuilder.EndpointConfiguration endpointConfig = new AwsClientBuilder.EndpointConfiguration(properties.getUrl(), null);
        AWSCredentials credentials = new BasicAWSCredentials(properties.getAccessKey(), properties.getSecretKey());
        AWSCredentialsProvider credentialsProvider = new AWSStaticCredentialsProvider(credentials);
        ClientConfiguration clientConfig = new ClientConfiguration();
        clientConfig.setProtocol(Protocol.HTTP);
        AmazonS3ClientBuilder build = AmazonS3Client.builder()
                .withEndpointConfiguration(endpointConfig)
                .withClientConfiguration(clientConfig)
                .withCredentials(credentialsProvider)
                .disableChunkedEncoding()
                .enablePathStyleAccess();
        this.client = build.build();
    }

    //...

    /**
     * 上传文件
     */
    @Override
    public void uploadFile(String bucket, File file) {
        try (FileInputStream in = new FileInputStream(file)) {
            ObjectMetadata metadata = new ObjectMetadata();
            PutObjectRequest putObjectRequest = new PutObjectRequest(bucket, BASE_PATH + file.getName(), in, metadata);
            putObjectRequest.setCannedAcl(CannedAccessControlList.Private);
            client.putObject(putObjectRequest);
        } catch (IOException e) {
            e.printStackTrace();
        }
    }

    /**
     * 下载文件
     */
    @Override
    public void downloadFile(String bucket, String filename, String target) {
        InputStream in = null;
        FileOutputStream out = null;
        try {
            S3Object object = client.getObject(bucket, BASE_PATH + filename);
            in = object.getObjectContent();
            out = new FileOutputStream(target);
            in.transferTo(out);
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            // close
            //...
        }
    }

    /**
     * 删除文件
     */
    @Override
    public void removeFile(String bucket, String filename) {
        client.deleteObject(bucket, BASE_PATH + filename);
    }
}

5.3 关键点

两个开关是从 AWS 切到 MinIO 时最常见的失败原因：

  • enablePathStyleAccess()：默认走 virtual-host 风格，请求会被拼成 http://bucket.host/key，MinIO 不会解析这种二级域名，必须改成 http://host/bucket/key。
  • disableChunkedEncoding()：AWS 的 aws-chunked 流式签名并非所有兼容网关都支持，MinIO 早期版本会直接返回签名错误；关闭后改用普通 Content-Length 上传。
  • Protocol.HTTP 与 region = null：本地 HTTP 部署才这么写；上云必须用 HTTPS，部分 SDK 版本要求 region 填 us-east-1 而不是 null。
  • metadata 未填 ContentLength 与 ContentType：从流上传时 SDK 无法预知长度会退化为分块缓冲，建议 metadata.setContentLength(file.length()) 并显式设置 ContentType，否则下载时拿到的是 binary/octet-stream。
  • CannedAccessControlList.Private：对象是私有的，浏览器无法直接访问，需要预签名 URL（见 7.2）。

6 两套实现对比

维度MinIO 客户端Amazon S3 SDK
异常模型7.x 大量受检异常，需长 catch 列表运行时异常，无需显式捕获
分片上传长度给 -1 时自动分片需用 Transfer Manager / Multipart API
兼容服务适配原生需 path-style + 关 chunked encoding
桶管理 API直接提供createBucket 在自建服务上可能不被支持
依赖体积较轻（含 OkHttp）较重
适用场景只对接 MinIO需要同时兼容 AWS / 阿里云等 S3 协议服务

7 装配与配套能力

7.1 按配置切换实现

两个实现类都没有加 @Service，测试里 @Autowired IOssService 能否注入取决于是否显式装配。推荐用条件化 Bean，一套代码两套实现按需启用：

@Configuration
public class OssConfig {
    @Bean
    @ConditionalOnProperty(name = "oss.type", havingValue = "minio", matchIfMissing = true)
    public IOssService minioOssService(OssProperties properties) {
        return new OssMinioServiceImpl(properties);
    }

    @Bean
    @ConditionalOnProperty(name = "oss.type", havingValue = "amazon")
    public IOssService amazonOssService(OssProperties properties) {
        return new OssAmazonServiceImpl(properties);
    }
}

如果两个实现同时存在而没有条件区分，按类型注入会因多个候选 Bean 报错。

7.2 预签名 URL

私有对象要给前端展示，应下发有时效的签名地址，而不是把桶改成公共读：

// MinIO
String url = minioClient.getPresignedObjectUrl(GetPresignedObjectUrlArgs.builder()
        .method(Method.GET)
        .bucket(bucket)
        .object(BASE_PATH + filename)
        .expiry(10, TimeUnit.MINUTES)
        .build());

// Amazon S3 (v1)
Date expiration = new Date(System.currentTimeMillis() + 10 * 60 * 1000L);
URL url = client.generatePresignedUrl(bucket, BASE_PATH + filename, expiration);

8 测试

@SpringBootTest
class ApplicationTests {
    private final String BUCKET = "xxx";
    @Autowired
    private IOssService ossService;

    @Test
    void uploadFileTest() {
        if (!ossService.existBucket(BUCKET)) {
            ossService.createBucket(BUCKET);
        }
        File file = new File("src/test/resources/test.txt");
        ossService.uploadFile(BUCKET, file);
    }

    @Test
    void downloadFileTest() {
        ossService.downloadFile(BUCKET, "test.txt", "src/test/resources/test.txt");
    }

    @Test
    void removeFileTest() {
        ossService.removeFile(BUCKET, "test.txt");
    }
}

「先查桶、不存在再建」是幂等初始化，但桶的创建更适合放在运维脚本或启动事件中，避免应用持有建桶权限。

9 生产注意事项

  • 失败不能静默：两套实现里 MinIO 吞掉全部异常、AWS 的 removeFile 却让运行时异常传播，行为不一致。调用方无法区分「删成功」和「删失败但只打了堆栈」，正确做法是捕获后转成统一的业务异常抛出。
  • 同名覆盖：BASE_PATH + file.getName() 会让同名文件互相覆盖。上传时应生成不可重复 key（日期/UUID.后缀），并把原始文件名放进对象 metadata 或数据库。
  • 接口返回 void 表达不了结果：至少应返回最终 object key，否则调用方存不了地址。
  • 大小与类型校验：上传前限制单文件体积与 MIME 类型，避免把存储当垃圾桶。
  • 生命周期与回收：删除对象不等于清理碎片，MinIO 需配合桶生命周期规则清理未完成分片。
  • 大文件走分片或直传：应用服务器中转大文件会占满带宽与内存，前端直传（预签名 PUT 或 STS 临时凭证）更合适。
  • 网络与超时：SDK 默认超时较宽松，公网环境下应显式设置 connect / read timeout 与重试次数。

10 小结

  • 用 IOssService 把业务与 SDK 解耦，MinIO 与 S3 兼容存储可在装配层切换。
  • 接入兼容服务时的三个必查项：path-style、chunked encoding、Content-Length / ContentType。
  • 私有对象靠预签名 URL 对外暴露，不要放开桶权限。
  • 当前实现最大的问题不是功能，而是异常被吞导致失败不可感知。
