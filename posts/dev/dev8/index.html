MySQL 树形查询

strr0 2023-11-29

1 概述

菜单、部门、评论这类树形数据，在 MySQL 中通常用邻接表存储：每行记录一个 id 和它的 parent_id。表结构很简单，但「给定一个节点，取出它下面所有子孙」这样的查询，在 MySQL 5.7 及更早版本里没有递归语法，只能由应用层循环查库、逐层拼装。

本文记录两种在单条 SQL 内完成的写法：向下查所有子节点、向上查所有父节点。语句中保留了 MyBatis 的 ${treeTableName} 与 #{pid} 占位符，可以直接放进 mapper 使用。

2 向下查询：取所有子孙节点

select id from(
    select id, parent_id, if(find_in_set(parent_id, @pids) > 0, @pids := concat(@pids, ',', id), 0) ischild
    from (select id, parent_id from ${treeTableName} order by parent_id, id) t1, (select @pids := #{pid}) t2) t3
where ischild != 0

2.1 执行思路

@pids 是一个不断膨胀的「已发现节点集合」，初始值只有传入的父节点 #{pid}：

  1. 内层 t1 按 parent_id, id 排序，保证父节点一定先于其子节点被扫描到，这是整个写法成立的前提。
  2. 每扫一行，用 find_in_set(parent_id, @pids) 判断它的父亲是否已经在集合里。
  3. 命中就把本行 id 追加进 @pids，同时让 ischild 变成一个非 0 值；未命中则 ischild 为 0。
  4. 由于同一语句里的变量是边扫描边更新的，新加入的 id 会让它下一层的子节点在后续行中被判定命中，从而逐层扩散。
  5. 外层用 ischild != 0 过滤，留下的就是被扩散到的所有行。

2.2 结果边界

  • 返回的是 #{pid} 的全部子孙节点，不含 #{pid} 自身；需要包含自身时再并一次根节点。
  • 只适用于「按 parent_id 逐层向下」的邻接表，且表数据不能存在环，否则集合会反复膨胀。

3 向上查询：取所有祖先节点

select t4.* from (
    select @r _id, (select @r := parent_id from ${treeTableName} where id = _id) _pid, @l := @l + 1 _l
    from (select @r := #{id}, @l := 0) t1, ${treeTableName} t2) t3 left join ${treeTableName} t4 on t3._id = t4.id
where t3._pid is not null

3.1 执行思路

与向下查询相反，这里靠 t2 提供循环次数：t2 每出一行，就驱动一次「取当前节点的父节点」，并把 @r 向上移动一层。

  • _id：本轮开始时的当前节点。
  • _pid：当前节点的父节点，同时把 @r 更新为该父节点，供下一轮使用。
  • _l：层级计数器，仅用于观察深度。

最后用 _id 回表 left join 拿到完整行数据。

3.2 结果边界

  • 返回起点节点自身及其各级祖先，但不含最顶层的根节点：根节点的 parent_id 为 NULL，对应行被 where t3._pid is not null 过滤掉了。若需要包含根节点，可放宽该条件或额外并一次根节点。
  • 可返回的层数受 t2 的行数限制（表越大越够用，空表或小表会出现取不全的情况）。

4 使用限制与注意事项

  • 依赖求值顺序：这类写法依赖 MySQL 对「赋值与读取在同一语句中」的处理顺序。官方文档并不保证该顺序，MySQL 8.0 起还会给出告警，因此只能算经验性可用的技巧，不建议作为长期方案。
  • 派生表合并会影响结果：优化器可能把子查询合并进外层，改变变量的更新时机。必要时可加 limit 等方式阻止合并，但这会让写法更脆弱。
  • ${} 是字面拼接：${treeTableName} 直接拼进 SQL，表名必须来自可信常量，不能取自用户输入，否则会引入 SQL 注入；只有 #{} 是预编译参数。
  • 性能：向下查询会全表扫描一遍，向上查询的行数与表行数同量级，数据量大时应考虑改用嵌套集、路径枚举（path 字段 + like 'xxx%'）或在应用层缓存整棵树。

5 MySQL 8.0 的推荐写法

MySQL 8.0 支持递归 CTE，语义清晰且不依赖变量求值顺序，新版本应优先使用：

with recursive cte as (
    select id, parent_id from ${treeTableName} where id = #{pid}
    union all
    select t.id, t.parent_id from ${treeTableName} t join cte on t.parent_id = cte.id
)
select id from cte;

向上取祖先只需把连接条件换成 t.id = cte.parent_id。

6 小结

  • 5.7 及更早版本可用 find_in_set + 会话变量在单条 SQL 内完成树的向下 / 向上遍历，代价是依赖求值顺序、结果有边界（向下不含自身、向上不含根）。
  • ${} 拼接的表名必须是可信常量。
  • 升到 MySQL 8.0 后统一改用 WITH RECURSIVE。
