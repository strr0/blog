Spring 整合 Redis

strr0 2023-11-30

1 概述

同一个 Redis，Java 侧有三条接入路径，定位差别很大：

  • Spring Data Redis（RedisTemplate）：Spring 统一抽象，屏蔽底层客户端，可无缝接入 @Cacheable、Session 共享等生态，业务缓存首选。
  • Jedis：直连驱动的裸客户端，API 与 Redis 命令一一对应，适合脚本、教学或不想起抽象层的场景。
  • Redisson：把 Redis 数据结构封装成 Java 对象（分布式锁、限流器、RList、RMapCache），价值在「分布式协调」而非单纯 KV。

本文三种都走一遍，最后给选型对比与缓存使用注意点。服务端部署见 Redis 安装。

2 环境配置

参考 Redis 安装，本文假设 localhost:6379、密码 password、默认 16 个 DB 已就绪。

3 基于 Spring Data

3.1 Spring 配置

引入依赖：

<dependency>
    <groupId>org.springframework.data</groupId>
    <artifactId>spring-data-redis</artifactId>
    <version>${spring-boot.version}</version>
</dependency>

<dependency>
    <groupId>redis.clients</groupId>
    <artifactId>jedis</artifactId>
</dependency>

spring-data-redis 只是抽象层，真正的连接由客户端实现提供，这里选了 Jedis；换成 Lettuce 同理。

application 配置：

spring:
  redis:
    database: 0
    host: localhost
    port: 6379
    password: password
    jedis:
      pool:
        max-active: 8
        max-idle: 8
        max-wait: -1ms
        min-idle: 0

注意前缀的版本差异：Boot 2.x 使用 spring.redis.*，Boot 3.x 起统一迁到 spring.data.redis.*（下文 Redisson 一节用的就是新前缀）。前缀写错不会报错，只会静默回落到默认值 localhost:6379 无密码连接，排查时很容易看漏。

连接池四个参数的含义：max-active 最大连接数、max-idle 最大空闲、min-idle 最小空闲（预热用）、max-wait 获取连接的最大阻塞时长，-1ms 表示无限等待——生产环境建议设一个有限值，让连接耗尽尽快暴露而不是把请求全挂住。

3.2 注入 RedisTemplate

@Service
public class BookService {
    @Resource
    private RedisTemplate<String, Book> redisTemplate;
    // TODO
}

这里不能使用 @Autowired 注入，因为 @Autowired 是根据类型注入，而此时 RedisTemplate 指定了泛型，与原来的 RedisTemplate 不再是同一个类型，所以 Spring 不能根据类型注入，可以使用 @Resource 根据名称注入。

补充两点：

  • 更准确的说法是，自动配置注册的 Bean 是 RedisTemplate<Object, Object>，Spring 的泛型感知匹配要求声明类型兼容，RedisTemplate<String, Book> 与之不符，于是按类型找不到、按名称又因泛型解析失败，最终注入报错。
  • 靠 @Resource 绕开只是让启动通过，泛型参数并不会真的改变序列化行为。推荐做法是自己声明一个 @Bean，显式指定 key / value 序列化器，再按类型注入：
@Bean
public RedisTemplate<String, Book> bookRedisTemplate(RedisConnectionFactory factory) {
    RedisTemplate<String, Book> template = new RedisTemplate<>();
    template.setConnectionFactory(factory);
    template.setKeySerializer(new StringRedisSerializer());
    template.setValueSerializer(new GenericJackson2JsonRedisSerializer());
    template.afterPropertiesSet();
    return template;
}

这一步很重要：默认 value 序列化器是 JdkSerializationRedisSerializer，要求对象实现 Serializable，且写进 Redis 的是二进制——redis-cli 里看不到内容，其他语言的服务也无法读取。

3.3 RedisTemplate 操作 Redis

设置 key value：

public void setBook(String key, Book book) {
    redisTemplate.opsForValue().set(key, book);
}

获取 value：

public Book getBook(String key) {
    return redisTemplate.opsForValue().get(key);
}

删除 key：

public Boolean removeBook(String key) {
    return redisTemplate.delete(key);
}

opsForXxx 按数据结构分组：opsForValue（String）、opsForHash、opsForList、opsForSet、opsForZSet。设置值的同时带过期时间可以直接用重载 set(key, value, timeout, unit)，比「先 set 再 expire」安全——两条命令之间进程崩溃会留下永不过期的 key。

4 基于 Jedis 客户端

4.1 建立连接及连接测试

Jedis jedis = new Jedis("localhost", 6379);
System.out.println(jedis.ping());
jedis.close();

Jedis 实例封装了一条 Socket 连接，非线程安全，不能做成单例给多线程共用。

4.2 其他操作

设置 key value：

jedis.set("key", "value");

获取 value：

jedis.get("key");

设置过期时间：

jedis.expire("key", 100);

删除 key：

jedis.del("key");

命令名与 Redis 保持一致，expire 的单位是秒。真实项目中不应这样手写 close()，要么用 try-with-resources，要么改用 JedisPool 借还连接；只 new Jedis() 不复用，高并发下会瞬间打满连接数。

5 基于 Redisson 客户端

5.1 Spring 配置

引入依赖：

<dependency>
    <groupId>org.redisson</groupId>
    <artifactId>redisson-spring-boot-starter</artifactId>
    <version>${redisson.version}</version>
</dependency>

application 配置：

spring:
  data:
    redis:
      host: localhost
      port: 6379
      database: 0
      password: password
      timeout: 30s
      ssl.enabled: false

starter 会读取这段标准配置自动构建 RedissonClient，无需再写 redisson.yaml。

5.2 RedissonClient 操作 Redis

设置 key value：

RBucket<Integer> bucket = redissonClient.getBucket("key");
bucket.set(100);

获取 value：

RBucket<Integer> bucket = redissonClient.getBucket("key");
System.out.println(bucket.get());

删除 key：

RBucket<Integer> bucket = redissonClient.getBucket("key");
bucket.delete();

获取 list：

RList<Object> rList = redissonClient.getList("key");
List<Object> dataList = rList.readAll();

添加 list 元素：

RList<Object> rList = redissonClient.getList("key");
rList.add("something");

清空 list：

RList<Object> rList = redissonClient.getList("key");
rList.clear();

RBucket 对应一个 key，RList 对应 Redis 的 list。要注意 readAll() 会把整个列表拉到本地内存，元素多时应改用 range(index, size) 分页取。Redisson 的 API 是「Java 集合接口」风格，RList.add 看起来是本地操作，实际每次都发一条 Redis 命令，在循环里调用会成为性能瓶颈。

6 三种方式对比

维度Spring Data RedisJedisRedisson
定位Spring 统一抽象层裸客户端分布式对象与协调框架
API 风格RedisTemplate + opsForXxx与 Redis 命令同名实现 java.util 集合接口
线程安全安全（连接由工厂/池管理）单连接不安全，需池化安全
序列化控制需自行配置序列化器只处理 String/byte[]内置编解码器可配
生态集成@Cacheable、Session、MQ 支持无分布式锁、限流、布隆过滤器
适用场景常规业务缓存脚本、极简工具并发协调、复杂数据结构

7 缓存使用注意点

  • 过期时间：写入时务必带 TTL（bucket.set(100) 这类无过期写法只适合常驻数据），否则 Redis 退化为无界存储。
  • 缓存穿透：查不存在的数据每次都打到 DB，可缓存空值或前置布隆过滤器。
  • 缓存击穿：热点 key 失效瞬间大量请求落库，可用互斥锁重建或多级缓存。
  • 缓存雪崩：大批 key 同一时刻过期，TTL 应加随机抖动。
  • 双写一致性：更新数据时推荐「先更新 DB，再删除缓存」，直接双写容易出现中间态；对一致性敏感的场景考虑延迟双删或订阅 binlog。
  • 大 key：单个 value 过大（列表上万元素、字符串上百 KB）会阻塞 Redis 单线程，应拆分或用 hash 分桶。
  • key 命名：统一 业务:模块:标识 前缀，便于按模式扫描与容量治理。

8 小结

  • 常规缓存选 Spring Data Redis，但一定要显式配置序列化器，并自己声明泛型正确的 RedisTemplate Bean，而不是靠 @Resource 绕开注入问题。
  • Jedis 直连适合看清命令语义，生产使用必须池化。
  • Redisson 的强项是分布式锁等协调原语，用它当普通 KV 反而增加了「集合操作 = 网络往返」的隐性成本。
  • Boot 3 中配置前缀统一为 spring.data.redis.*。
