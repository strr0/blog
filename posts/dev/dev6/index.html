Spring 整合 MongoDB

strr0 2023-09-20

1 概述

MongoDB 是文档型非关系型数据库，适合字段结构不固定、需要按层级存储或读多写多的场景。Spring 侧有两条接入路径：

  • MongoTemplate：贴近驱动，手写查询，灵活但代码量大。
  • Spring Data MongoDB 的 Repository：继承接口即获得 CRUD 与派生查询，适合结构清晰的常规业务。

本文走第二条路径，记录从依赖到跑通读写的完整步骤。数据库本身的部署见 MongoDB 安装。

2 环境配置

服务端安装与账号准备参考 MongoDB 安装，本文假设已存在：

  • 监听 localhost:27017 的实例；
  • 业务库 testdb，以及对该库有读写权限的用户 user。

3 Spring 配置

3.1 引入依赖

<dependency>
    <groupId>org.springframework.data</groupId>
    <artifactId>spring-data-mongodb</artifactId>
    <version>${mongo.version}</version>
</dependency>

<dependency>
    <groupId>org.mongodb</groupId>
    <artifactId>mongodb-driver-sync</artifactId>
    <version>${mongo-driver.version}</version>
</dependency>

spring-data-mongodb 只提供抽象层，不会传递驱动实现，因此需要同步引入 mongodb-driver-sync（同步驱动）。若工程基于 Spring Boot，可直接改用 spring-boot-starter-data-mongodb，由 starter 统一管理两者版本。

3.2 application 配置

spring:
  data:
    mongodb:
      authentication-database: testdb
      database: testdb
      host: localhost
      port: 27017
      username: user
      password: password

各字段含义：

配置项作用
database默认操作的数据库
authentication-database执行认证（登录）的数据库，凭据创建在哪个库就填哪个，常为 admin
host / port单节点地址；副本集改用 uri 或 replica-set
username / password认证账号，未开启鉴权时可不配

也可以把以上信息合并成一串 URI：spring.data.mongodb.uri: mongodb://user:password@localhost:27017/testdb?authSource=testdb，其中 authSource 对应的就是 authentication-database。

3.3 repository 配置

public interface BookRepository extends MongoRepository<Book, Integer> {
}

泛型两个参数分别是实体类型与 ID 类型。继承后即拥有 save、findById、findAll、deleteById 等方法，无需实现类。

实体侧需要满足两点：

  • 用 @Document(collection = "book") 指定集合名，省略时按类名首字母小写推导；
  • ID 字段用 @Id 标注，类型与 MongoRepository 的第二个泛型一致。

4 测试

@SpringBootTest
class ApplicationTests {
    @Autowired
    private BookRepository bookRepository;

    @Test
    void addBookTest() {
        Book book = new Book();
        book.setId(1);
        book.setName("Spring in action");
        book.setAuthor("xxx");
        bookRepository.save(book);
        System.out.println("save book success.");
    }

    @Test
    void getBookTest() {
        bookRepository.findById(1).map(book -> {
            System.out.println("get " + book);
            return book;
        });
    }
}
  • save 是 upsert 语义：ID 已存在则整体覆盖，不存在则插入。
  • findById 返回 Optional，查不到时 map 不会执行，因此第二个用例在数据被清理后不会有任何输出，排查时容易误判为「连接有问题」。

5 注意事项

  • 索引不会自动创建：需要唯一或查询加速索引时，在字段上加 @Indexed，或显式建索引，否则数据量上来后全集合扫描。
  • 手写 ID 需自行保证唯一：本例手动 setId(1)，若交给 MongoDB 生成应使用 ObjectId/String 类型且不赋值。
  • 日期与时区：存储为 UTC，展示时注意转换。
  • 分页与复杂聚合：MongoRepository 难以表达时改用 MongoTemplate 的 Query / Aggregation。

6 小结

  • 接入只需「依赖 + 连接配置 + 继承 MongoRepository」三步，实体靠 @Document 与 @Id 映射。
  • authentication-database 与 database 是两个概念，认证失败优先检查前者。
  • 简单 CRUD 用 Repository，复杂聚合用 MongoTemplate。
