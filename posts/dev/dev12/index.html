基于 Sa-Token 实现单点登录

strr0 2024-06-16

1 概述

1.1 Sa-Token

Sa-Token 是一个轻量级 Java 权限认证框架，主要解决：登录认证、权限认证、单点登录、OAuth 2.0、分布式 Session 会话、微服务网关鉴权等一系列权限相关问题。

1.2 单点登录要解决的问题

单点登录就是一套机制将 N 个系统的认证授权互通共享，让用户在一个系统登录之后，便可以畅通无阻地访问其它所有系统。它的核心价值不只是少输一次密码，而是把「谁登录了、登入了哪个系统」收敛到一处，注销时能一并失效。

Sa-Token 单点登录的工作原理：

  1. 用户进入 A 系统，若未登录，则将当前路径作为 redirect 参数跳转到授权中心；
  2. 授权中心登录成功后颁发一个 ticket，重定向回 A 系统；
  3. A 系统拿到 ticket，向授权中心校验，校验通过即可得到授权中心的登录用户 id；
  4. 用户 id 说明其在授权中心已登录，A 系统据此执行本地登录的后续逻辑。

ticket 的校验方式有本地共享存储与 HTTP 调用两类。本文示例采用 模式三（is-http: true）：客户端通过 HTTP 请求向认证中心校验 ticket。它不要求两端共享 Redis 或 Session，可跨域、跨集群部署，代价是两端必须交换 API 调用秘钥。

2 示例

2.1 SSO 统一认证中心（服务端）

新建 sso-server 模块。

引入依赖：

<!-- Sa-Token 权限认证, 在线文档：https://sa-token.cc/ -->
<dependency>
    <groupId>cn.dev33</groupId>
    <artifactId>sa-token-spring-boot3-starter</artifactId>
    <version>1.38.0</version>
</dependency>

<!-- Sa-Token 插件：整合SSO -->
<dependency>
    <groupId>cn.dev33</groupId>
    <artifactId>sa-token-sso</artifactId>
    <version>1.38.0</version>
</dependency>

application 配置：

# 端口
server:
    port: 9000
# Sa-Token 配置
sa-token: 
    sso-server:
        # Ticket有效期 (单位: 秒)，默认五分钟
        ticket-timeout: 300
        # 所有允许的授权回调地址
        allow-url: "*"
        # 是否打开模式三
        is-http: true
    sign:
        # API 接口调用秘钥
        secret-key: kQwIOrYvnXmSDkwEiFngrKidMcdrgKor
  • ticket-timeout：ticket 的有效期，默认 300 秒。它是一次性凭证，校验成功后即失效，短有效期可以压缩被截获后的利用窗口。
  • allow-url：允许回调的地址白名单。"*" 表示任意地址都可回调，属于典型的开放重定向风险，只在调试期使用。
  • is-http：打开模式三，认证中心随即要对外提供 checkTicket 等 HTTP 接口。
  • sign.secret-key：接口调用秘钥，模式三下两端必须一致，否则校验请求会被签名验证拒绝。

新建 SsoServerController：

/**
 * Sa-Token-SSO Server端 Controller 
 */
@RestController
public class SsoServerController {
    private final RestTemplate restTemplate = new RestTemplate();

    /**
     * SSO-Server端：处理所有SSO相关请求 (下面的章节我们会详细列出开放的接口) 
     */
    @RequestMapping("/sso/*")
    public Object ssoRequest() {
        return SaSsoServerProcessor.instance.dister();
    }
    
    /**
     * 配置SSO相关参数 
     */
    @Autowired
    private void configSso(SaSsoServerConfig ssoServer) {
        // 配置：未登录时返回的View 
        ssoServer.notLoginView = () -> {
            String msg = "当前会话在SSO-Server端尚未登录，请先访问"
                    + "<a href='/sso/doLogin?name=sa&pwd=123456' target='_blank'> doLogin登录 </a>"
                    + "进行登录之后，刷新页面开始授权";
            return msg;
        };
        
        // 配置：登录处理函数 
        ssoServer.doLoginHandle = (name, pwd) -> {
            // 此处仅做模拟登录，真实环境应该查询数据进行登录 
            if("sa".equals(name) && "123456".equals(pwd)) {
                StpUtil.login(10001);
                return SaResult.ok("登录成功！").setData(StpUtil.getTokenValue());
            }
            return SaResult.error("登录失败！");
        };
        
        // 配置 Http 请求处理器 （在模式三的单点注销功能下用到，如不需要可以注释掉） 
        ssoServer.sendHttp = url -> {
            try {
                System.out.println("------ 发起请求：" + url);
                String resStr = restTemplate.getForObject(url, String.class);
                System.out.println("------ 请求结果：" + resStr);
                return resStr;
            } catch (Exception e) {
                e.printStackTrace();
                return null;
            }
        };
    }
    
}

三处回调函数就是认证中心的全部扩展点：

扩展点作用生产环境该怎么改
notLoginView未授权时给用户看的提示页换成正式的错误页或跳转登录页
doLoginHandle校验账号密码并调用 StpUtil.login改为查库 + 密码散列校验 + 登录失败次数限制
sendHttp认证中心主动回调客户端接口（单点注销用）换成带超时与连接池的 HTTP 客户端，日志走 Logger

@RequestMapping("/sso/*") 把所有 SSO 相关请求交给 SaSsoServerProcessor.instance.dister() 分发，框架内部会识别 /sso/auth、/sso/doLogin、/sso/checkTicket 等路径。

2.2 SSO 客户端

新建 sso-client 模块（或使用已有的模块）。

引入依赖：

<!-- Sa-Token 权限认证, 在线文档：https://sa-token.cc/ -->
<dependency>
    <groupId>cn.dev33</groupId>
    <artifactId>sa-token-spring-boot3-starter</artifactId>
    <version>1.38.0</version>
</dependency>

<!-- Sa-Token 插件：整合SSO -->
<dependency>
    <groupId>cn.dev33</groupId>
    <artifactId>sa-token-sso</artifactId>
    <version>1.38.0</version>
</dependency>

客户端与认证中心的依赖完全相同，差别只体现在配置前缀（sso-client 对 sso-server）和控制器里调用的 Processor 上。

application 配置：

# 端口
server:
    port: 9001
# sa-token配置 
sa-token:
    # SSO-相关配置
    sso-client:
        # SSO-Server端 统一认证地址
        auth-url: http://localhost:9000/sso/auth
        # 使用 Http 请求校验ticket (模式三)
        is-http: true
        # SSO-Server端 ticket校验地址
        check-ticket-url: http://localhost:9000/sso/checkTicket
        # 单点注销地址
        slo-url: http://localhost:9000/sso/signout
        # 查询数据地址
        get-data-url: http://localhost:9000/sso/getData
    sign:
        # API 接口调用秘钥
        secret-key: kQwIOrYvnXmSDkwEiFngrKidMcdrgKor

is-http: true 之后，后面三个 URL 才会被真正调用：check-ticket-url 用于验证 ticket，slo-url 用于单点注销，get-data-url 用于回查授权中心数据。secret-key 必须与服务端一致。

新建 SsoClientController：

/**
 * Sa-Token-SSO Client端 Controller 
 */
@RestController
public class SsoClientController {
    private final RestTemplate restTemplate = new RestTemplate();

    // 首页
    @RequestMapping("/")
    public String index() {
        String str = "<h2>Sa-Token SSO-Client 应用端</h2>" +
                "<p>当前会话是否登录：" + StpUtil.isLogin() + "</p>" +
                "<p><a href=\"javascript:location.href='/sso/login?back=' + encodeURIComponent(location.href);\">登录</a> " +
                "<a href='/sso/logout?back=self'>注销</a></p>";
        return str;
    }

    /*
     * SSO-Client端：处理所有SSO相关请求
     * 		http://{host}:{port}/sso/login			-- Client端登录地址，接受参数：back=登录后的跳转地址
     * 		http://{host}:{port}/sso/logout			-- Client端单点注销地址（isSlo=true时打开），接受参数：back=注销后的跳转地址
     * 		http://{host}:{port}/sso/logoutCall		-- Client端单点注销回调地址（isSlo=true时打开），此接口为框架回调，开发者无需关心
     */
    @RequestMapping("/sso/*")
    public Object ssoRequest() {
        return SaSsoClientProcessor.instance.dister();
    }

    // 配置SSO相关参数
    @Autowired
    private void configSso(SaSsoClientConfig ssoClient) {
        // 配置Http请求处理器
        ssoClient.sendHttp = url -> {
            System.out.println("------ 发起请求：" + url);
            String resStr = restTemplate.getForObject(url, String.class);
            System.out.println("------ 请求结果：" + resStr);
            return resStr;
        };
    }
}

客户端的 sendHttp 是必需项而非可选：模式三下它要主动请求认证中心的 checkTicket，不配置就无法完成校验。

2.3 测试及客户端自定义配置

完成上述配置后，分别启动 sso-server 和 sso-client，然后访问 http://localhost:9001 进入客户端首页，点击登录即自动跳转到授权中心。授权中心登录成功后带 ticket 重定向回 /sso/login，此路径为客户端默认登录地址，在没有额外配置的情况下，它会默认对 ticket 进行校验，并在校验成功后在客户端登录。

如果需要对客户端登录做自定义的逻辑操作，首先需要修改跳转到授权中心的 redirect 参数（即重定向地址），然后配置自定义 ticket 处理，如：

// 根据ticket进行登录
@RequestMapping("/sso/doLoginByTicket")
public SaResult doLoginByTicket(String ticket) {
    SaCheckTicketResult ctr = SaSsoClientProcessor.instance.checkTicket(ticket, "/sso/doLoginByTicket");
    // 自定义登录逻辑
    StpUtil.login(ctr.loginId, ctr.remainSessionTimeout);
    return SaResult.data(StpUtil.getTokenValue());
}

自定义的价值在于拿到 loginId 之后可以做本地账号绑定、首次登录建号、权限预加载等动作。remainSessionTimeout 让本地会话时长与授权中心对齐，避免授权中心已失效而客户端仍续着旧会话。

3 安全与运维注意事项

  • allow-url: "*" 必须收敛：任意回调地址意味着攻击者可以构造 ticket 转发到钓鱼站点，生产环境要改为精确的域名白名单。
  • secret-key 不要用示例值：文中这个秘钥来自官方文档，属于公开信息。生产要换成长随机串，并通过环境变量或配置中心注入，同时准备轮换流程。
  • 模拟登录不能上线：name=sa / pwd=123456 与硬编码的 StpUtil.login(10001) 只是演示，且 notLoginView 把带密码的登录链接直接展示给了用户。
  • 凭证走 Cookie 而非 URL 传递：登录令牌与 ticket 会出现在 URL 与日志里，需要确保 token 使用 HttpOnly + Secure Cookie，并对访问日志中的敏感参数脱敏。
  • 两端时钟与网络：模式三依赖 HTTP 同步调用，认证中心不可用时所有客户端登录都会失败，应考虑超时、熔断与降级提示。
  • 单点注销依赖回调可达：slo-url 生效要求认证中心能反向访问每个客户端，容器或跨网段部署时最容易漏配。
  • 日志替换：System.out.println 与 e.printStackTrace() 应换成日志框架，sendHttp 打印的 URL 中含 ticket，不宜进 INFO 级别日志。

4 小结

  • SSO 的本质是「一次登录，处处可信」，实现关键在于 ticket 的颁发与校验，以及两端会话生命周期的对齐。
  • 模式三（HTTP 校验）适合跨域、不共享存储的部署形态，代价是必须管理 API 秘钥并保证网络双向可达。
  • 示例代码里的 allow-url、secret-key、模拟登录三处是上线前的必改项。
