接口与抽象类

strr0 2023-04-06

1 概述

抽象类与接口是 Java 表达抽象的两条路径，日常设计与面试中都常被拿来比较。但二者的边界并不是一成不变的：Java 8 引入 default 与 static 方法、Java 9 引入 private 方法之后，接口已经能够承载实现逻辑，许多沿用 JDK 7 时代资料的结论都需要修正。

本文先给出一张按较新版本校准的对比表，再说明接口出现方法实现后带来的变化。阅读前需要对类的继承与多态有基本了解。

2 抽象类与接口的对比

对比项抽象类接口
语义定位表示 is-a，抽取子类的公共模板与状态表示 can-do，只约定能力与行为契约
方法实现可同时拥有抽象方法与具体方法Java 8 起 default / static 方法可写方法体，Java 9 起允许 private 方法；其余抽象方法仍无实现
继承与实现只能继承一个类，可同时实现多个接口可实现多个接口；接口自身也能继承一个或多个接口
构造器有构造器，供子类通过 super 调用没有构造器，也不能被实例化
成员变量与普通 Java 类一致，修饰符与可变性均不受限隐式为 public static final，声明时必须初始化且不可修改
访问修饰符成员可用 public、protected、包级私有方法默认且只能是 public（Java 9 起额外允许 private），字段恒为 public
main 方法可以定义并直接运行Java 8 起可定义 static void main，因此同样可以直接运行
静态代码块可以有不能有
新增成员的成本新增具体方法不影响已有子类新增抽象方法会迫使所有实现类改动，一般改用 default 方法提供兜底实现
调用性能历史上略快历史上因需要查找实现而略慢；现代 JVM 经过内联与接口方法树优化后，差距可忽略

常见资料里的「接口完全不存在方法实现」「接口不能有 main，所以无法运行」「接口比抽象类明显更慢」都是 JDK 7 及更早版本的说法，Java 8 之后已不再成立。

3 接口也可以有方法实现

Java 8 之后，接口中可以添加由 default 或 static 修饰的方法，它们被视为普通方法，可以直接书写方法体。例如：

@FunctionalInterface
public interface Function<T, R> {
    //...

    static <T> Function<T, T> identity() {
        return t -> t;
    }
}

子类可以不重写接口中的 static 和 default 方法，不重写的情况下，默认调用的是接口的方法实现。由此带来两条实践约束：

  1. 接口演进优先用 default：需要给接口增加能力时，提供 default 实现即可保持对既有实现类的兼容，不必一次性改动所有实现。
  2. 多实现冲突必须显式重写：当两个接口存在同名 default 方法时，编译器不会自动挑选，实现类必须重写该方法，必要时用 接口名.super.方法名() 指定调用目标。

4 如何选择

  • 需要复用字段、构造器或受保护的实现细节：选抽象类。
  • 只约定行为、且实现方可能同时具备多种能力：选接口。
  • 两者兼有时，常见做法是接口定义能力、抽象类提供骨架实现（模板方法模式），标准库中的 Collection 与 AbstractCollection 就是这种搭配。

5 小结

  • Java 8 / 9 之后接口已能承载实现，「接口必须完全抽象」不再准确。
  • 抽象类的价值在于复用状态与构造逻辑，接口的价值在于多实现与调用方解耦。
  • 面向已上线的接口做扩展时，用 default 方法避免破坏兼容。
