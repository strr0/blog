Linux 环境下 MongoDB 的安装与使用

strr0 2024-01-04

1 概述

MongoDB 是文档型数据库：集合（collection）相当于表、文档（BSON）相当于行，没有固定表结构，同一个集合里的文档字段可以不同，因此适合字段经常变化的业务对象与嵌套结构。它支持二级索引、聚合管道、事务（4.0 起副本集支持多文档事务，4.2 起支持分片集群的分布式事务，单节点实例不支持）与副本集高可用，但默认没有外键与强一致约束，数据完整性靠应用层与校验规则保证。

本文用的是社区版 7.0.16。选型时有两个必须知道的坑：MongoDB 5.0 起的二进制要求 CPU 支持 AVX，旧机器与部分云主机上会直接 Illegal instruction 退出；而 SSPL 许可证使它不能像 MySQL 那样直接当作云服务的底层卖点（云厂商因此有 DocumentDB/FerretDB 这类兼容层），自托管业务不受影响。Spring 侧的用法参考 Spring 整合 MongoDB，本文只讲部署与基础操作。

2 安装

2.1 通过二进制文件安装

2.1.1 下载

wget https://fastdl.mongodb.org/linux/mongodb-linux-x86_64-rhel80-7.0.16.tgz

包名里的系统标识是 rhel80（对应 RedHat/CentOS 8.0），不是 rhel8；写成 rhel8-7.0.16 会得到 404，而下一小节解压时目录名也必须跟着用 rhel80，否则 cp 会报路径不存在。选包时先确认发行版的 glibc：rhel80 包需要 glibc 2.28+，Ubuntu 20.04/22.04 建议直接下 ubuntu2204 包；不想自己处理这些依赖关系就用包管理器装 mongodb-org。

2.1.2 解压到指定路径

tar -xzvf mongodb-linux-x86_64-rhel80-7.0.16.tgz
sudo cp mongodb-linux-x86_64-rhel80-7.0.16/bin/* /usr/local/bin/

bin/ 下不止 mongod（服务端），还有 mongosh（shell，二进制包里没有 mongo/mongosh，需要单独下载）、mongodump/mongorestore、mongoexport/mongoimport、bsondump、mongostat/mongotop 等工具。旧版自带的 mongo 外壳在 5.0 起被废弃、6.0 移除，现在统一用 mongosh，本文的示例命令在两者里都能跑，但 use、show collections 这类外壳命令在 mongosh 中更完整。

2.1.3 创建用户及用户组

sudo groupadd mongod
sudo useradd -g mongod -s /sbin/nologin -r mongod

原稿这里被注释掉的是 groupadd，留下的却是 useradd -G mongod mongod，而 -G 是附加组——组还不存在时这条命令会直接报 group 'mongod' does not exist，所以那两行得换顺序写。-r 建系统账号、-s /sbin/nologin 禁止登录，都是服务账号该有的属性。后面所有数据/日志目录的属主要是 mongod:mongod，否则 WiredTiger 无法创建锁文件，日志里会是 Unable to lock file 或 Permission denied。

2.1.4 创建数据及日志目录

sudo mkdir -p /var/lib/mongo      # 数据目录
sudo mkdir -p /var/log/mongodb    # 日志目录
sudo chown -R mongod:mongod /var/lib/mongo
sudo chown -R mongod:mongod /var/log/mongodb

2.1.5 基础配置

# /etc/mongodb.conf

## 数据路径
dbpath=/var/lib/mongo

## 日志路径
logpath=/var/log/mongodb/mongod.log

## 端口号
# port=27017

## 远程访问
bind_ip=0.0.0.0

## 用户验证
# auth=true

这份文件有两个层面的问题。格式上，dbpath= 这种 key=value 是 2.6 之前的旧式写法，官方从 2.6 引入 YAML 后就一直在废弃它，新版解析失败时会报 Unrecognized option——建议直接改成 YAML（注意 YAML 只能用空格缩进、key: value 冒号后必须有空格、不支持行尾注释）：

# /etc/mongod.conf
storage:
  dbPath: /var/lib/mongo
systemLog:
  destination: file
  path: /var/log/mongodb/mongod.log
  logAppend: true
net:
  port: 27017
  bindIp: 0.0.0.0
security:
  authorization: enabled
processManagement:
  fork: true

安全上，bind_ip=0.0.0.0 把服务绑到所有网卡，而下面的 auth 却被注释掉了——这个组合就是历史上大量 MongoDB 勒索事件的入口（扫到 27017 就能直接读写、删库、留勒索信）。三者至少选一个：只本机访问就 bindIp: 127.0.0.1；要远程就必须 authorization: enabled 加账号密码；云上再用安全组把 27017 限到固定来源 IP。

2.1.6 启动及停止

mongod -f /etc/mongodb.conf --fork
mongod -f /etc/mongodb.conf --shutdown

--fork 必须同时指定 logpath（否则不知道把日志往哪写而直接退出），而且与 systemd 的 Type=forking 配合容易让服务状态不准，官方 unit 用的是前台模式 + journald，自己写 unit 时建议去掉 fork。--shutdown 会读同一份配置里的 dbPath 去锁住数据目录再停，因此必须带 -f，单独敲 mongod --shutdown 在默认路径环境上会停错或不生效；更通用的停服方式是 mongosh --eval "db.adminCommand('shutdown')" admin（需要当前用户有 shutdown 权限）。

2.1.7 设置用户名密码

mongod -f /etc/mongodb.conf --fork
mongosh
> use admin
> db.createUser({ user: 'admin', pwd: 'password', roles: [{ role: 'root', db: 'admin' }] })

原稿这里的 ./mongod 容易被当成“在 mongod 里输入下面的语句”：mongod 是服务端，建用户要在 mongosh（客户端） 里执行，所以必须两条命令。顺序上有个技巧：开了 authorization: enabled 之后，只要实例里还没有任何用户，MongoDB 会开放 localhost exception——从本机连上就能创建第一个管理员，不需要先关认证再重启（创建完这个例外自动失效）。root 是跨所有库的管理员角色，业务账号不要用它，按库给 readWrite 或 dbOwner 即可；密码含特殊字符时 URI 连接需要 URL 编码。

2.2 通过 Docker 安装

拉取镜像

docker pull mongo:7.0.16

运行容器

docker run -d \
    --name mongo-server \
    -p 27017:27017 \
    -v /docker/mongo/data:/data/db \
    -e MONGO_INITDB_ROOT_USERNAME=mongoadmin \
    -e MONGO_INITDB_ROOT_PASSWORD=<secret> \
    mongo:7.0.16

原稿这一段里 docker run -d 后面漏了续行符 \，直接执行会把它当成一条完整命令（没有镜像名）而报错；缩进也混用了 Tab 与空格（Docker 官方镜像的文档统一用 4 空格）。另外补一句：这个镜像的数据在 /data/db，不挂卷就和上面二进制安装把 dbPath 放在容器文件系统里一样，容器一删数据全没。

MONGO_INITDB_ROOT_USERNAME / PASSWORD 创建的是 admin 库的超级用户，且只在数据目录为空时首次初始化生效（和 RabbitMQ 的 RABBITMQ_DEFAULT_USER 同一个套路）；已有数据卷时改了这两个变量不会更新密码，得用 db.changeUserPassword()。MONGO_INITDB_DATABASE=testdb 很容易误解：它不会帮你建库，只是把初始化脚本（docker-entrypoint-initdb.d/*.js）的执行上下文切到这个库。想验证服务健康，用 docker exec mongo-server mongosh --quiet --eval "db.adminCommand('ping')"。

创建数据库及赋予权限

docker exec -it mongo-server mongosh admin
> db.auth('mongoadmin', '<secret>');
> use testdb;
> db.createUser({ user: 'user', pwd: 'password', roles: [ { role: "dbOwner", db: "testdb" } ] });

连进去先 db.auth() 认证（或一开始就用 mongosh admin -u mongoadmin -p <secret>），然后 use testdb 切库再建用户，角色里的 db 要和目标库一致。业务侧的连接串要把认证库写清楚：mongodb://user:password@host:27017/testdb?authSource=admin（账号建在哪个库，authSource 就写哪个，写错会报 Authentication failed 而不是“权限不够”）。dbOwner 包含单库读写 + 建索引 + 改集合，单库的应用账号用它比较合适；只读报表类用 read。

3 使用

3.1 集合操作

创建集合

db.createCollection("book")

删除集合

db.book.drop()

集合是“第一次插入文档时自动创建”的，createCollection 只在需要显式指定选项（如 capped: true 的固定大小日志集合、校验规则 $jsonSchema、分片配置）时才必要。db.createCollection("book") 里的引号不能省，写成 db.book 变量式访问时集合名不能含 - 或数字开头，得用 db.getCollection("order-item")。注意 drop() 会返回 true/false，而集合不存在时不报错；生产环境不要直接对业务库执行，分片集群上它还会同时清元数据。

3.2 查询语句

查询文档

db.book.find()  ## book 为表名

注意行尾的 ## 是配置文件/Shell 的注释写法，在 mongosh（JS）里不合法，复制执行会报语法错；mongosh 的行注释用 //，而 > 本身是 shell 提示符，不要一并粘进去。

条件查询（and）

db.book.find({ key1: 'value1', key2: 'value2' })

条件查询（or）

db.book.find({ $or: [{ key1: 'value1' }, { key2: 'value2' }] })

两处给值加上了引号：原来的 { key1: value1 } 在 mongosh 里会被当成引用一个名为 value1 的变量，直接报 ReferenceError: value1 is not defined，只有字符串字面量才能当查询条件。实际用得更多的形式是：db.book.find({ author: 'strr' }, { title: 1, _id: 0 })（第二个参数是投影，只返必要字段能显著减少传输），配合 .sort({ likes: -1 }).skip(20).limit(10) 分页。统计数量用 countDocuments({ ... })（带条件）而不是已废弃的 count()；估算总数（不看条件、走元数据，快很多）用 estimatedDocumentCount()。

mongo 条件语句

操作格式范例RDBMS 中的类似语句
等于{<key>:<value>}db.book.find({"by":"strr"})where by = 'strr'
小于{<key>:{$lt:<value>}}db.book.find({"likes":{$lt:50}})where likes < 50
小于或等于{<key>:{$lte:<value>}}db.book.find({"likes":{$lte:50}})where likes <= 50
大于{<key>:{$gt:<value>}}db.book.find({"likes":{$gt:50}})where likes > 50
大于或等于{<key>:{$gte:<value>}}db.book.find({"likes":{$gte:50}})where likes >= 50
不等于{<key>:{$ne:<value>}}db.book.find({"likes":{$ne:50}})where likes != 50

3.3 插入、更新与删除

插入文档

db.book.insert({ name: 'test book', author: 'strr' })

更新文档

db.book.updateOne({ _id: ObjectId('64b7f2c9d4e5f6a7b8c9d0e1') }, { $set: { name: 'test book 1' } })

删除文档

db.book.deleteOne({ _id: ObjectId('64b7f2c9d4e5f6a7b8c9d0e1') })

这一小节改了四处原稿里直接跑不通的地方：

  • insert / update / remove 都是旧版外壳留下的写法，mongosh 里虽有兼容，但官方从 3.2 起就用 insertOne/insertMany、updateOne/updateMany、deleteOne/deleteMany 取代。差别不只是名字：旧 update() 不带 multi: true 时只改第一条匹配文档，很容易被当成全量更新；旧 remove({}) 会清空整个集合，而 deleteMany({}) 至少把意图写明了。
  • 更新与删除必须用 $set/$unset 这类操作符，写成 update({name:'x'}, {name:'y'})（不带 $set）会把整个文档替换掉，其余字段全部丢失。
  • ObjectId('1') 不是合法的 ObjectId：它必须是 24 位十六进制字符串，传短串会直接报 Error: invalid objectId。新插入的文档如果不写 _id，MongoDB 会自动生成一个，所以例子里改用了一个合法值。
  • 字符串里的值同样要带引号，{ _id: ObjectId(...) } 里写成变量名会变成 ReferenceError。

插入建议直接用 insertMany([...])，它比循环 insertOne 快得多；需要“不存在就插入”时用 updateOne(filter, { $set: ... }, { upsert: true })。写入关注点（write concern）默认 w:1，要确认已落盘副本集多数节点用 w:'majority'，代价是延迟。

3.4 索引与慢查询

db.book.createIndex({ author: 1 }, { unique: false, name: 'idx_author' })
db.book.getIndexes()
db.book.find({ author: 'strr' }).explain('executionStats')

没建索引的查询会 COLLSCAN（全集合扫描），explain 输出里看到它就是慢查询的头号原因，改成 IXSCAN 才是正常的。复合索引遵循 ESR 原则（Equal 等值条件在前、Sort 排序字段居中、Range 范围条件在后），且受最左前缀限制：建了 {a:1,b:1} 就不能有效支持只查 b 的条件。唯一索引 {unique: true} 是业务约束（手机号、订单号）在 MongoDB 里真正的实现方式，相当于库内唯一约束。上线后看慢查靠 profiler：

db.setProfilingLevel(1, { slowms: 100 })
db.system.profile.find().sort({ ts: -1 }).limit(5)

级别 0 关、1 只记超过 slowms 的、2 全记（只用于短暂调试，会很快写满集合）。

3.5 备份与迁移

mongodump --uri "mongodb://mongoadmin:<secret>@127.0.0.1:27017/?authSource=admin"
mongorestore --uri "mongodb://mongoadmin:<secret>@127.0.0.1:27017/?authSource=admin" --drop dump/

mongodump/mongorestore 输出 BSON，保留类型信息（Date、ObjectId、二进制），是真正的备份手段；副本集上加 --oplog 才能拿到时间点一致的快照。mongoexport/mongoimport 面向 JSON/CSV，适合与其他系统交换数据，但会丢类型信息（Date 变成 {"$date":...} 结构），不要把 export 的 JSON 当备份。--drop 让 restore 先删同名集合，-d/-c 可以只恢复指定库表；恢复到另一个库用 --db testdb2。版本升级前的常规做法是：mongodump → 部署新版本 → mongorestore，并先在测试环境跑一遍。

4 上线检查清单

项说明
CPU 指令集5.0+ 需要 AVX，先 grep -o avx /proc/cpuinfo 确认，否则 mongod 启动即 Illegal instruction
绑定与认证不要 0.0.0.0 + 无认证；至少 authorization: enabled + 强密码 + 安全组限源
账号级别首个管理员可在 localhost exception 下创建；业务账号按库给 readWrite，不用 root
数据目录二进制安装需 mongod:mongod 属主；Docker 要挂 /data/db
配置格式新版统一 YAML，不兼容行尾注释与 Tab 缩进
副本集需要事务或多文档一致性就用副本集（单节点上事务不可用），本地开发也可 --replSet rs0 + rs.initiate()
索引上线前核对主要查询路径的 explain 不出现 COLLSCAN；写入为主的集合索引不要超过必要个数
内存WiredTiger 默认占用 (RAM - 1GB) * 0.5 作为 cache，与同机其他服务共存时可用 wiredTigerCacheSizeGB 显式限制
备份定时 mongodump --oplog 并异地存放，恢复演练过一遍；监控磁盘（WiredTiger 对磁盘满会直接停写）
监控mongostat/mongotop、db.serverStatus()，以及 profiler 的慢查阈值

5 小结

  • 二进制安装时要同时对上三件事：包名的系统标识（rhel80 而非 rhel8）、AVX 与 glibc 兼容、mongod:mongod 对数据目录的属主权限。
  • 旧式 key=value 配置已经被 YAML 取代，而 bind_ip=0.0.0.0 配没开的 auth 是勒索事故的典型开头。
  • mongod 是服务端、mongosh 是客户端，建用户、查数据全部在 mongosh 里；认证库与 authSource 不一致是“连不上”最常见的原因。
  • CRUD 示例里的 value1、ObjectId('1')、update/remove 都是旧写法或直接报错的写法，现在统一用 insertOne/updateOne/deleteOne。
  • 性能上只看两件事：查询有没有走索引（explain 里的 IXSCAN），备份能不能恢复到时间点（mongodump --oplog）。
