Linux 环境下 Redis 的安装与使用

strr0 2023-04-24

1 概述

Redis 是一个把数据放在内存里的键值存储。命令执行是单线程的（6.0 之后只是网络 I/O 多线程，命令仍然串行），因此单实例的吞吐很容易预估，也意味着一条慢命令就能堵整个服务——这个特性在后面讲 keys 和 flushall 时会反复出现。常见用法是缓存、会话存储、分布式锁、计数器与排行榜，也能用 Stream 承担轻量消息队列。

本文用的是 6.2.14。需要注意 6.2 已经不在官方维护线内，新部署建议直接上 7.x 或 8.x：7.0 引入了 Function 与多部分 AOF，8.x 又带来 hash field TTL 等能力。另外 7.4 起 Redis 的许可证从 MIT 改为 RSALv2/SSPLv2 双许可，由此产生的开源分支 Valkey 保持 BSD 许可，两者在命令与协议上完全兼容，只是自托管缓存的话可以直接互换。Spring 侧怎么用不在本文范围，参考 Spring 整合 Redis。

2 安装

2.1 通过源码安装

2.1.1 获取源码

wget https://download.redis.io/releases/redis-6.2.14.tar.gz

2.1.2 编译

编译前需要 gcc 和 make（Debian/Ubuntu 上 apt install build-essential，CentOS 上 yum groupinstall "Development Tools"）。

直接编译

tar -xzvf redis-6.2.14.tar.gz
cd redis-6.2.14
make

编译（启用 TLS 支持，需要 OpenSSL 开发库）

make BUILD_TLS=yes

两个容易误解的点：原文写的是“LTS 支持、需要下载 openssh”，实际这里说的是 TLS（传输加密），依赖的是 OpenSSL（libssl-dev / openssl-devel），和负责远程登录的 OpenSSH 无关。另外 make 的产物全部在 src/ 目录下，redis-server、redis-cli、redis-benchmark、redis-sentinel、redis-check-aof 等是同一源码树编译出来的不同入口；编译完可以先跑 make test（或 ./runtest）验证环境。

2.1.3 安装

安装到 /usr/local/bin

sudo make install

make install 就是把上一步 src/ 里的二进制拷到 /usr/local/bin，不会自动创建配置、数据目录、运行用户和 systemd unit。要交给 systemd 托管，得自己写一个 /etc/systemd/system/redis.service（ExecStart=/usr/local/bin/redis-server /etc/redis/redis.conf --daemonize no，Redis 官方的 unit 里还配了 Type=notify），再 daemon-reload 加 enable --now。如果不想手动处理这些，用包管理器安装会更省力。

2.1.4 配置

# /etc/redis/redis.conf

## 允许远程访问
# bind 127.0.0.1 -::1
## 密码配置
requirepass password

把 bind 那一行注释掉就是监听全部网卡，风险靠 requirepass 兜住。两个细节：一是 Redis 配置文件的注释符是单个 #，## 只是恰好也被当作注释，不要当成语法；二是除了 bind 还有 protected-mode（默认 yes）——它会在“没设 bind 限制且没密码”时拒绝外部连接，所以只注掉 bind 而不配 requirepass，外部依旧连不上，这个报错信息很容易让人误判成网络问题。

密码方面，requirepass 是全实例共享的一个口令且存于明文配置，所有客户端拿到相同权限。Redis 6+ 支持 ACL（aclfile 与 ACL SETUSER），可以按用户区分命令与 key 权限，多应用共用一个实例时建议上 ACL。另外 requirepass 只保护 RESP 协议，数据落盘文件（RDB/AOF）本身不加密，拿到备份文件就能直接读。

2.1.5 问题与解决

fatal error: jemalloc/jemalloc.h: No such file or directory

jemalloc 重载了 Linux 下的 ANSI C 的 malloc 和 free 函数，使用如下命令编译

make MALLOC=libc

Redis 默认用 jemalloc（内存碎片少、自带分配统计），但这个内置副本在部分平台或较新的 GCC/binutils 上会编译失败。报这个错时两条路：用上面的 MALLOC=libc 退回 glibc 自己分配器（性能差异在一般业务缓存场景下基本可以忽略）；或者先 make distclean 清掉上一轮残留的配置再重新 make，因为 MALLOC 这类变量只在首次 configure 时写入，不 distclean 的话改了也不生效。

2.2 通过 Docker 安装

2.2.1 拉取镜像

docker pull redis

不带 tag 拉到的是 latest，而 latest 会随时间漂移，同一个镜像名在不同时间构建出来的环境可能版本不同。生产建议固定版本，例如 docker pull redis:7.2-alpine。

2.2.2 运行容器

docker run -d \
    --name redis-server \
    -p 6379:6379 \
    redis --requirepass <password>

redis 镜像的 ENTRYPOINT 已经是 redis-server，所以后面那串 --requirepass <password> 是直接作为命令行参数传给服务端，优先级高于镜像内的默认配置（镜像默认只开了 protected-mode no，没有配置文件意义上的 redis.conf）。这个命令有个容易忽略的问题：没有挂载数据目录，容器一删数据就没了。持久化部署至少加两项：

docker run -d \
    --name redis-server \
    -p 6379:6379 \
    -v /docker/redis/data:/data \
    redis:7.2 --requirepass <password> --appendonly yes

/data 是镜像里的工作目录，RDB、AOF 默认都写在这里，不挂出来就等于没有备份。想沿用自定义的 redis.conf，则要把文件映射进去并把命令换成 redis-server /usr/local/etc/redis/redis.conf。进容器排查用 docker exec -it redis-server redis-cli，设了密码后在里面仍需 AUTH <password>（或直接 redis-cli -a <password> --no-auth-warning）。

3 使用

3.1 基础使用

启动

redis-server

客户端

redis-cli

获取所有 key

keys *

设置键值对

set <key> <value>

获取值

get <key>

删除键

del <key>

清空所有数据库中的数据

flushall

清空当前数据库中的数据

flushdb

上面这些命令在 redis-cli 里直接输入即可（不需要包一层 redis-cli），设了密码先 AUTH <password>，或用 redis-cli -u redis://:password@127.0.0.1:6379/1 一次性把地址、密码、库号都带上。select 1 可以切到另一个库（默认 16 个，编号 0–15），但 Redis Cluster 下只有 db0，依赖多库做隔离的应用上集群前得先拆。给单个键设过期用 expire <key> 60，或者直接 set <key> <value> ex 60 nx（ex 秒、px 毫秒、nx 仅在不存在时写入，做分布式锁就靠这两个参数）。

3.2 三个默认就能用、但很危险的习惯

用 keys * 查数据。keys 是 O(N) 且单线程执行，库里有百万级 key 时一条 keys * 能把整个实例卡住几秒，期间所有读写都排队。线上应该用游标式的 scan：

scan 0 match user:* count 100
redis-cli --scan --pattern 'user:*'

scan 一次只返一部分并给出下次游标，返回 0 代表遍历结束；它不保证一次遍历不漏不重，但不会长时间堵住服务。redis-cli --scan 已经把循环封好了，比手写方便。

随手 flushall / flushdb。这是不可逆的（能恢复的唯一路径是之前的 RDB/AOF 备份）。Redis 7 支持 flushall async 异步后台清理，至少不会卡住主线程；更可靠的做法是在 redis.conf 里用 rename-command FLUSHALL "" 把它重命名为空字符串直接禁用，并在 ACL 里不给业务账号 allcommands 权限。另外注意：FLUSHALL 会清掉所有库，FLUSHDB 只清当前库，而 SHUTDOWN 、SCRIPT FLUSH 这类命令同样危险。

用 monitor 排查线上问题。monitor 会把每条命令打印到客户端，它本身开销不大，但输出会把单线程的 CPU 和网络吃掉，高并发下能直接把实例拖到不可用，且会把密码、token 全部明文打印。线上优先用不需要常开的 slowlog get 10、info commandstats 和 info clients，配合 redis-cli --bigkeys、redis-cli --hotkeys 定位问题。

3.3 持久化与内存上限

这两块不在上面的命令里，但属于“不配就会出事”的部分。

持久化分两种：RDB 是定时全量快照（save 3600 1 这类规则，或 bgsave 手动触发），文件小、恢复快，但两次快照之间的数据会丢；AOF 是追加写命令日志，appendfsync everysec 是常用折中（默认 always 最安全也最慢）。Redis 7 的 AOF 改成多文件 + manifest 结构，rewrite 不再像旧版那样一次性写大文件。两者可以同时开，重启时优先用 AOF 重建。

内存上限必须显式配：maxmemory 不设时 Redis 会一直吃到把宿主内存压干，被 OS 的 OOM killer 挑中；maxmemory-policy 默认是 noeviction，意味着写满后所有写入直接报 OOM command not allowed when used memory > 'maxmemory'，而不是淘汰旧数据。纯缓存场景一般用 allkeys-lru（或访问频率更不均时的 allkeys-lfu，Redis 4+），有不可丢数据时选 volatile-lru 并给需要保留的 key 设 TTL。

源码安装时还有两项宿主内核参数值得配（官方部署建议）：

sysctl vm.overcommit_memory=1
echo never > /sys/kernel/mm/transparent_hugepage/enabled

前者是因为 bgsave/AOF rewrite 会 fork 出子进程，默认策略下可能因预估内存不够而拒绝 fork，表现为写入暂时不可用；后者是为了避免大页放大内存碎片并拖慢 fork。Docker 镜像里已经处理了 overcommit（启动时若不对会打警告），THP 仍然需要在宿主上关。

4 上线检查清单

项说明
bind / protected-mode / 防火墙不要将 6379 直接暴露到公网；Redis 历史上多次出现用写 crontab 挖矿的入侵案例，入口就是无密码的公网实例
requirepass 或 ACL至少一个；多应用共用时用 ACL 区分账号与命令权限
maxmemory + maxmemory-policy两者都要显式配，默认 noeviction 会让写入直接报错
RDB / AOF确认 dir 指向已挂载、已备份的目录；纯缓存可以只要 RDB，当主存储用必须开 AOF
stop-writes-on-bgsave-error默认 yes：磁盘满导致快照失败时停写。磁盘经常满的环境需要改成 no 并配监控，否则会默默停写
数据目录挂载（Docker）-v ...:/data，否则容器重建等于清库
内核参数vm.overcommit_memory=1、关 THP
危险命令rename-command 掉 FLUSHALL/FLUSHDB/CONFIG/DEBUG，或用 ACL 限制
监控info memory（used_memory、碎片率）、info stats（命中率）、slowlog、info persistence（rdb_last_bgsave_status）
禁用 keys 习惯性代码里一律用 scan，上线前在测试环境用 monitor 确认没漏网的 keys

5 小结

  • 源码安装拿到的是干净的二进制，配置、systemd unit、运行用户都得自己建；只是想快速跑起来就直接用 Docker，但一定要固定 tag 并挂载 /data。
  • 允许远程访问 = 注掉 bind + 设密码，两者缺一不可，因为 protected-mode 会把“无 bind 且无密码”的外部连接直接拒掉。
  • make BUILD_TLS=yes 要的是 OpenSSL 而不是 OpenSSH；jemalloc 编译失败时用 MALLOC=libc，改选项前先 make distclean。
  • 单线程执行命令这个前提，决定了 keys *、flushall、monitor 在线上都是危险动作，以及 maxmemory 与淘汰策略必须提前配好。
