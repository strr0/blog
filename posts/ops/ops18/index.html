Linux 环境下 MySQL 的安装与使用

strr0 2025-01-04

1 概述

MySQL 是最常用的关系型数据库，本文覆盖两种部署形态和部署后必做的几件事：

形态适合注意
通用二进制包生产/学习完整安装流程，路径与参数完全自控用户、目录、systemd 都要手工建
Docker本机开发、集成测试（如 RuoYi-Vue-Plus 框架 的依赖库）数据靠 -v 卷，镜像参数只暴露了一小部分

业务库建议统一 utf8mb4 字符集（带 emoji 字段与中文注释的 SQL 导入报 Incorrect string value 基本都是它，RuoYi-Vue-Plus 框架 2.2.2 踩过这个坑）；Canal 订阅、主从复制这类场景还依赖 binlog，默认已开启，参数见 3.4。

2 安装

2.1 通过二进制包安装

安装依赖

yum install libaio numactl

libaio 是 InnoDB 异步 IO 的硬依赖，缺了 mysqld 起不来；numactl 对应 NUMA 内存策略（官方打包要求）。没有 yum 的系统用对应的 apt 包 libaio1。

获取通用二进制包

wget https://downloads.mysql.com/archives/get/p/23/file/mysql-8.0.33-linux-glibc2.28-x86_64.tar.gz

这是 archives 页的固定文件链接，8.0.33 在 8.0 线里算稳定选择；glibc2.28 对应 RHEL8/CentOS8 及以上，老系统（glibc 更旧）要换 glibc2.17 的包，否则启动报 GLIBC_x.xx not found。

创建 MySQL 组

groupadd -g 27 -o -r mysql

创建 MySQL 用户

useradd -M -N -g mysql -o -r -d /usr/local/mysql/data -s /bin/false -c "MySQL Server" -u 27 mysql

这两个命令是官方文档的写法（GID/UID 取 27 是 MySQL 在 RHEL 系的惯例编号）：-r 建系统账号、-M 不建家目录、-s /bin/false 禁止登录。-o 允许 ID 重复只在"27 已被占用还要硬用这个号"时成立，干净的机器上把 -o 去掉更稳妥；已存在同名用户时这两行会报错，先 id mysql 确认。

解压二进制包

tar -zxvf mysql-8.0.33-linux-glibc2.28-x86_64.tar.gz
mv mysql-8.0.33-linux-glibc2.28-x86_64 /usr/local/mysql

非 root 执行时 mv 进 /usr/local 需要 sudo；目录名后续所有路径都写死了 /usr/local/mysql，改名要同步改 my.cnf 与 systemd 单元。

设置 PATH 变量

export PATH=/usr/local/mysql/bin:$PATH

这行只对当前 shell 生效，永久化写进 /etc/profile（非登录进程读不到的限制同 基础环境配置 概览的讨论），或用 alternatives 链接到 /usr/bin。

创建安全目录（用于导入导出）

cd /usr/local/mysql
mkdir mysql-files
chown mysql:mysql mysql-files
chmod 750 mysql-files

创建配置文件

cd /etc
touch my.cnf
chown root:root my.cnf
chmod 644 my.cnf

添加配置到 my.cnf 文件

[mysqld]
datadir=/usr/local/mysql/data
socket=/tmp/mysql.sock
port=3306
log-error=/usr/local/mysql/data/localhost.localdomain.err
user=mysql
secure_file_priv=/usr/local/mysql/mysql-files
local_infile=OFF

这份骨架之外建议补上生产常用的几行（字符集与连接数，utf8mb4 的理由见第 1 节）：

[mysqld]
character_set_server=utf8mb4
collation_server=utf8mb4_0900_ai_ci
max_connections=500

两个细节：log-error 的文件名在官方模板里其实带主机名（hostname 不是 localhost.localdomain 时后面的 cat 命令要换成真实文件名，或者干脆自己指定一个固定名）；secure_file_priv + local_infile=OFF 是安全基线——限制 LOAD DATA/SELECT INTO OUTFILE 只能碰指定目录，不建议为了图方便整个关掉。

创建数据目录

cd /usr/local/mysql
mkdir data
chmod 750 data
chown mysql:mysql data

初始化

cd /usr/local/mysql
bin/mysqld --defaults-file=/etc/my.cnf --initialize

--initialize 会用 mysql 用户身份初始化数据目录（所以上一步的 chown 不能漏），并生成随机 root 临时密码。注意 datadir 必须是空目录（或尚不存在），重复初始化前先确认数据不要了；临时密码写进错误日志：

初始化日志（包含初始密码）

cat /usr/local/mysql/data/localhost.localdomain.err

搜 temporary password 那一行。拿到密码后必须先启动服务、登录后改掉才能正常用库（临时密码状态下只能执行改密类语句）。

创建 service 配置文件

cd /usr/lib/systemd/system
touch mysqld.service
chmod 644 mysqld.service

添加配置到 mysqld.service 文件

[Unit]
Description=MySQL Server
Documentation=man:mysqld(8)
Documentation=http://dev.mysql.com/doc/refman/en/using-systemd.html
After=network.target
After=syslog.target

[Install]
WantedBy=multi-user.target

[Service]
User=mysql
Group=mysql

# Have mysqld write its state to the systemd notify socket
Type=notify

# Disable service start and stop timeout logic of systemd for mysqld service.
TimeoutSec=0

# Start main service
ExecStart=/usr/local/mysql/bin/mysqld --defaults-file=/etc/my.cnf $MYSQLD_OPTS

# Use this to switch malloc implementation
EnvironmentFile=-/etc/sysconfig/mysql

# Sets open_files_limit
LimitNOFILE = 10000

Restart=on-failure

RestartPreventExitStatus=1

# Set environment variable MYSQLD_PARENT_PID. This is required for restart.
Environment=MYSQLD_PARENT_PID=1

PrivateTmp=false

单元文件就是官方模板，关键行：Type=notify（8.0 的 mysqld 支持 systemd 就绪通知，配合 TimeoutSec=0 免去启动超时误判）、LimitNOFILE = 10000（默认文件描述符上限很低，连接数一多就报 open_files 警告）。写完后启动：

systemctl daemon-reload
systemctl enable --now mysqld
systemctl status mysqld

起不来时第一现场永远是错误日志（log-error 指向的那个文件），而不是 systemctl 的摘要。

2.2 通过 Docker 安装

拉取镜像

docker pull mysql:8.0.31

创建容器并启动

docker run -d \
    --name mysql-server \
    -p 3306:3306 \
    -v ./mysql:/var/lib/mysql \
    -e MYSQL_ROOT_PASSWORD=password \
    -e MYSQL_DATABASE=<db> \
    -e MYSQL_USER=<user> \
    -e MYSQL_PASSWORD=<pwd> \
    mysql:8.0.31

四个 -e 只在**数据目录为空（首次初始化）**时生效：卷里已有数据时改这些变量不会重建库/账号（想重置就换个卷目录）。镜像默认参数没开 utf8mb4 服务端配置与业务调优项，需要时再挂一份自己的 my.cnf：-v ./my.cnf:/etc/mysql/conf.d/custom.cnf:ro。-p 3306:3306 默认监听所有网卡，本机专用就写 127.0.0.1:3306:3306。

3 使用

3.1 登录

cd /usr/local/mysql
bin/mysql -uroot -p
# Enter password: (enter the random root password here)

二进制形态的 socket 在 /tmp/mysql.sock（my.cnf 里定的），同机其他客户端连接时报找不到 /var/lib/mysql/mysql.sock 就加 -S /tmp/mysql.sock 或在客户端配置里指明。Docker 形态登录则是：

docker exec -it mysql-server mysql -uroot -p

3.2 设置密码

alter user 'root'@'localhost' identified by '<password>';
# 带 caching_sha2_password 加密
alter user 'root'@'localhost' identified with 'caching_sha2_password' by '<password>';

这两行是在 mysql 提示符里执行的 SQL（不是 shell）。8.0 默认认证插件就是 caching_sha2_password，写不写都一样；只有对接老驱动/老客户端（不支持该插件，报 Authentication requires more messaging）时才需要显式换 mysql_native_password——优先升级驱动而不是降级认证。改完密码后建议顺手把测试库和远程 root 清理掉（等价于 mysql_secure_installation 做的事）。

3.3 建库建号与最小权限

应用连库不要共用 root，按库授权：

create database app character set utf8mb4 collate utf8mb4_0900_ai_ci;
create user 'app'@'%' identified by '<强密码>';
grant select, insert, update, delete, execute on app.* to 'app'@'%';
flush privileges;

要点：'app'@'%' 的主机部分控制"从哪台机器连"，生产可以收紧成具体网段（'app'@'10.0.1.%'）；DML 授权不带 grant option，DDL 交给发布流程/Liquibase（见 数据库版本管理工具 Liquibase）而不是应用账号；% 与 localhost 是两个不同的账号定义，root 默认只允许 localhost，远程管理要单独建账号而不是把 root 开放成 %。

3.4 备份与关键参数

逻辑备份（日常最常用）：

# 单库（单文件恢复友好；--single-transaction 对 InnoDB 加一致性快照，不锁表）
mysqldump -uroot -p --single-transaction --routines --triggers app > app-$(date +%F).sql

# 恢复
mysql -uapp -p app < app-2025-01-04.sql

物理备份（数据量大、需要增量）用官方 mysqlbackup/xtrabackup；要配合 binlog 做时间点恢复时，备份后记录位点（SHOW MASTER STATUS）。

和运维场景强相关的几个参数（my.cnf 里改后重启生效）：

参数默认说明
log_binON（8.0）Canal/主从的前提；binlog_format=ROW 是 Canal 要求
binlog_expire_logs_seconds2592000（30 天）磁盘紧张时缩短，别让 binlog 写满盘
max_connections151连接池总量大时先调这个，报 Too many connections 即命中
innodb_buffer_pool_size128M性能第一参数，专用机给内存的 50%~70%
character_set_serverutf8mb4（8.0）5.7 默认 latin1，升级过来的库重点检查
group_concat_max_len10245.7 多值拼接静默截断的元凶（RuoYi-Vue-Plus 框架 2.1 提过）

Canal 接入还需要一个带 REPLICATION CLIENT, REPLICATION SLAVE 权限的专用账号，见 Linux 环境下 Canal 的安装与使用。

4 小结

  • 二进制安装的四个关键台阶：libaio 依赖、mysql 系统用户、--initialize 拿临时密码、systemd 单元 + daemon-reload；卡住先看错误日志。
  • Docker 形态简单但只有"首次初始化"那套变量有效，自定义配置靠挂 conf.d 文件。
  • 登录后第一件事：改 root 密码、建最小权限的业务账号；caching_sha2_password 认证插件问题优先升驱动。
  • 备份用 mysqldump --single-transaction，Canal/主从看 binlog 参数，性能先看 buffer pool。
