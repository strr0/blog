Linux 环境下 Hadoop 的安装与使用

strr0 2025-05-20

1 概念

1.1 基本定义

Hadoop 是一个开源的分布式计算平台，允许用户在不了解分布式底层细节的情况下，开发分布式程序，充分利用集群的威力进行高速运算和存储。它主要解决两大问题：‌海量数据存储‌（通过 HDFS）和‌海量数据分析‌（通过 MapReduce）。

1.2 核心组件

1.2.1 HDFS(Hadoop Distributed File System)

分布式文件系统，将数据分割为块（默认 128 MB）并存储在不同服务器上，支持高吞吐量访问和容错。

  • NameNode‌：管理文件命名空间和元数据。

  • DataNode‌：存储实际数据块并执行读写操作。

1.2.2 MapReduce

分布式计算模型，分为 Map（映射）和 Reduce（归约）两阶段，适用于离线批处理。

1.2.3 YARN(Yet Another Resource Negotiator)

资源调度框架，分离资源管理与任务调度，支持多类型计算框架（如 Spark、Flink）。

2 安装

2.1 环境要求

  • jdk8
  • ssh

Hadoop 3.x 支持 Java 8 与 11（Hadoop 4 起才强制更高版本），本文用 JDK 8 是保守选择；ssh 是给伪分布式/集群的免密互信用的，单机模式可忽略。JDK 安装参考 基础环境配置 的 Java 环境一节。

2.2 安装

下载 hadoop-3.4.1.tar.gz

解压

mkdir /opt/apache
sudo tar -zxvf hadoop-3.4.1.tar.gz -C /opt/apache

mkdir 同样需要 root 权限（目录不存在时换成 sudo mkdir -p /opt/apache）；解压后目录名是 hadoop-3.4.1，后续配置里的路径以它为准。

2.3 配置

配置环境变量

# /etc/profile

# set to the root of your Java installation
export JAVA_HOME=/usr/java/latest

原稿只配了 JAVA_HOME。两个补充：路径要指向真实存在的目录（/usr/java/latest 是 RPM 安装的惯例路径，按 ops12 的 tar 包装法是 /usr/local/java/jdk1.8.0_431 这种）；另外把 Hadoop 自身也加进 PATH 才能不 cd 到安装目录直接用命令：

export HADOOP_HOME=/opt/apache/hadoop-3.4.1
export PATH=$PATH:$HADOOP_HOME/bin:$HADOOP_HOME/sbin

Hadoop 启动脚本强依赖 JAVA_HOME（只装了 java 但没设 JAVA_HOME 时，start-dfs.sh 会报 Error: JAVA_HOME is not set），这一步不能省。

刷新环境变量

source /etc/profile

2.4 验证

执行如下命令验证，成功则打印使用说明

bin/hadoop

想看版本号用 bin/hadoop version（同时能确认它找到的 JAVA_HOME 对不对）。到这里只是"装上了"，还没启动任何服务；下面三种模式按需求选。

3 使用

3.1 单机模式

  1. 复制配置文件作为输入
mkdir input
cp etc/hadoop/*.xml input
  1. 查找和打印所有表达式匹配的数据
bin/hadoop jar share/hadoop/mapreduce/hadoop-mapreduce-examples-3.4.1.jar grep input output 'dfs[a-z.]+'
cat output/*

两个使用细节：output 目录不能提前存在（重复跑第二次会报 Output directory ... already exists，先 rm -rf output）；这里的 output 是本地目录，单机模式没有 HDFS，MapReduce 跑在本地文件系统上。

3.2 伪分布式

3.2.1 配置

  1. 使用如下配置

etc/hadoop/core-site.xml

<configuration>
    <property>
        <name>fs.defaultFS</name>
        <value>hdfs://localhost:9000</value>
    </property>
</configuration>

etc/hadoop/hdfs-site.xml

<configuration>
    <property>
        <name>dfs.replication</name>
        <value>1</value>
    </property>
</configuration>

建议补一个 NameNode 元数据目录：不配 dfs.namenode.name.dir 时默认落在 /tmp/hadoop-<user>/dfs/name，系统重启或 tmpwatch 清理就丢整个文件系统元数据：

<configuration>
    <property>
        <name>dfs.namenode.name.dir</name>
        <value>/opt/apache/hadoop-3.4.1/dfs/name</value>
    </property>
</configuration>

3.2.2 设置 SSH

  1. 检查是否可以免密登录
ssh localhost

如果不能免密登录，执行如下命令

ssh-keygen -t rsa -P '' -f ~/.ssh/id_rsa
cat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys
chmod 0600 ~/.ssh/authorized_keys

-P '' 是不设口令（无人值守启停脚本用，带口令每次都要输）；首次 ssh localhost 会问 yes/no 确认指纹，先手动连一次或配 StrictHostKeyChecking accept-new。start-dfs.sh 本质上就是通过 ssh 到各节点执行启停命令，免密不通则脚本卡住。

3.2.3 执行

  1. 格式化文件系统
bin/hdfs namenode -format

格式化只在首次或重建集群时执行，重复格式化会生成新的 clusterID，而 DataNode 还认旧 ID，表现为 DataNode 起不来、日志里 Incompatible clusterIDs；真需要重格时先清 datanode 数据目录。

  1. 启动 NameNode 和 DataNode
sbin/start-dfs.sh

hadoop 的日志会输出到 $HADOOP_LOG_DIR 目录下

  1. NameNode 默认 web 界面在 http://localhost:9870

  2. 创建执行 MapReduce 作业所需的 HDFS 目录

bin/hdfs dfs -mkdir -p /user/<username>
  1. 复制输入文件
bin/hdfs dfs -mkdir input
bin/hdfs dfs -put etc/hadoop/*.xml input
  1. 执行 example 作业
bin/hadoop jar share/hadoop/mapreduce/hadoop-mapreduce-examples-3.4.1.jar grep input output 'dfs[a-z.]+'
  1. 检查输出文件

复制分布式文件系统的输出文件到本地检查

bin/hdfs dfs -get output output
cat output/*

或直接通过分布式文件系统检查

bin/hdfs dfs -cat output/*
  1. 完成所有作业后，可以通过如下命令停止
sbin/stop-dfs.sh

3.2.4 通过 yarn 执行

此步需要已经完成上述的前 4 步操作

  1. 配置参数如下

etc/hadoop/mapred-site.xml

<configuration>
    <property>
        <name>mapreduce.framework.name</name>
        <value>yarn</value>
    </property>
    <property>
        <name>mapreduce.application.classpath</name>
        <value>$HADOOP_MAPRED_HOME/share/hadoop/mapreduce/*:$HADOOP_MAPRED_HOME/share/hadoop/mapreduce/lib/*</value>
    </property>
</configuration>

etc/hadoop/yarn-site.xml

<configuration>
    <property>
        <name>yarn.nodemanager.aux-services</name>
        <value>mapreduce_shuffle</value>
    </property>
    <property>
        <name>yarn.nodemanager.env-whitelist</name>
        <value>JAVA_HOME,HADOOP_COMMON_HOME,HADOOP_HDFS_HOME,HADOOP_CONF_DIR,CLASSPATH_PREPEND_DISTCACHE,HADOOP_YARN_HOME,HADOOP_HOME,PATH,LANG,TZ,HADOOP_MAPRED_HOME</value>
    </property>
</configuration>
  1. 启动 ResourceManager 和 NodeManager
sbin/start-yarn.sh

  1. ResourceManager 默认 web 界面在 http://localhost:8088

  2. 执行 MapReduce 作业

  3. 完成所有作业后，可以通过如下命令停止

sbin/stop-yarn.sh

3.3 分布式

搭建 Hadoop 集群需要准备至少 2 台以上的服务器，这边我使用 docker 来模拟 3 台服务器，节点规划如下

HDFSNameNode DataNodeDataNodeDataNode
YarnNodeManagerNodeManagerResourceManager NodeManager

先保存现场，再批量造节点：刚才这个 ubuntu 容器已经把 JDK、Hadoop 和 apt 源都装好了，docker commit 把它固化成镜像，后面三个节点都用它创建，环境天然一致（改配置也是改镜像重新 commit，而不是逐个容器手工改）。

保存镜像

docker commit ubuntu hadoop:1.0
  1. 创建集群及 ssh 配置

三个节点要按主机名（hadoop1~hadoop3）互相访问，靠一个自定义 bridge 网络实现——DNS 会自动把容器名解析成容器 IP，配置文件里的 hdfs://hadoop1:9000 这类地址才能通。--net dev 引用的是下面创建的 dev 网络，必须先建网络再建容器：

docker network create dev

运行容器

docker run -itd --name hadoop1 --net dev hadoop:1.0 /bin/bash
docker run -itd --name hadoop2 --net dev hadoop:1.0 /bin/bash
docker run -itd --name hadoop3 --net dev hadoop:1.0 /bin/bash

进入容器

docker exec -it hadoop1 /bin/bash
docker exec -it hadoop2 /bin/bash
docker exec -it hadoop3 /bin/bash

如果是 root 用户，则修改配置

/etc/ssh/sshd_config

PermitRootLogin yes

启动 ssh

service ssh start

生产公私钥

ssh-keygen -t rsa -P '' -f ~/.ssh/id_rsa

-P '' 不设口令的理由和伪分布式一节相同：启停脚本是非交互执行的，带口令会卡住。密钥只在 hadoop1 上生成一次即可——ssh-copy-id 会把公钥和 known_hosts 一起分发到目标节点。

将公钥上传到其他的服务器，如 hadoop1 执行如下命令

ssh-copy-id hadoop1
ssh-copy-id hadoop2
ssh-copy-id hadoop3

hadoop2、hadoop3 同理（start-dfs.sh/start-yarn.sh 是从任意节点 ssh 到各节点启停服务的，要求节点间两两免密；如果只在 hadoop1 上分发，就只能从 hadoop1 执行启停脚本）。ssh-copy-id 首次要输一次目标节点密码；容器里 root 登录还要确认 sshd_config 的 PermitRootLogin yes 已开且重启过 sshd（service ssh restart），否则分发密钥也会 Permission denied。

3.3.2 运行

下面所有命令都在各节点的 /opt/apache/hadoop-3.4.1 目录下执行（对应节点规划表：NameNode/ResourceManager 分别只在 hadoop1/hadoop3 上启）。每启完一个进程可以用 jps 确认它活着（没装的话 apt install openjdk-8-jdk 自带；jhs/npm 这类简写命令是 Hadoop 自己的，不跨发行版）；启动失败第一现场看 $HADOOP_LOG_DIR（默认安装目录 logs/）下对应的 .log 和 .out 文件，.out 里通常是 JVM 级报错（如 JAVA_HOME 不对），.log 里是服务级报错（如端口占用、clusterID 不兼容）。

  1. 启动

首次运行 HDFS 需要执行格式化 HDFS（hadoop1）

bin/hdfs namenode -format

启动 NameNode

bin/hdfs --daemon start namenode

启动 DataNode

bin/hdfs --daemon start datanode

启动 ResourceManager

bin/yarn --daemon start resourcemanager

启动 NodeManager

bin/yarn --daemon start nodemanager

启动 WebAppProxy server

bin/yarn --daemon start proxyserver

启动 MapReduce JobHistory Server

bin/mapred --daemon start historyserver

全部启完后验证集群状态：在任意节点执行 bin/hdfs dfsadmin -report，Live datanodes 应为 3；bin/yarn node -list -all 应列出 3 个 RUNNING 的 NodeManager。Web UI 方面，NameNode 在 hadoop1:9870、ResourceManager 在 hadoop3:8088、JobHistory 在 hadoop2:19888——但容器没做端口映射，宿主机浏览器直接访问不到，两个办法选一：用容器 IP 访问（docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' hadoop1 查 IP）；或建容器时加 -p 9870:9870 -p 8088:8088 之类重新创建（元数据在容器目录里，重建前记得把 data/、dfs/ 目录拷出来或挂卷）。

  1. 停止

停止 NameNode

bin/hdfs --daemon stop namenode

停止 DataNode

bin/hdfs --daemon stop datanode

停止 ResourceManager

bin/yarn --daemon stop resourcemanager

停止 NodeManager

bin/yarn --daemon stop nodemanager

停止 WebAppProxy server

bin/yarn --daemon stop proxyserver

停止 MapReduce JobHistory Server

bin/mapred --daemon stop historyserver

4 小结

本文把 Hadoop 3.4 的三种形态走了一遍，要点回顾：

  • 单机模式解压就能跑 example，适合验证安装；没有 HDFS，用本地文件系统。
  • 伪分布式单节点跑 NameNode + DataNode，需要 SSH 免密和 hdfs namenode -format；生产演练时把 dfs.namenode.name.dir 移出 /tmp，否则重启丢元数据。
  • 全分布式用 Docker 三节点模拟：镜像化环境（commit）→ 自定义网络（主机名互访）→ 两两免密 → 按角色逐个 --daemon 启停守护进程，jps/dfsadmin -report 验证。
  • 高频坑集中在三处：JAVA_HOME 指向不存在的目录、重复 format 导致 clusterID 不兼容（DataNode 起不来）、output 目录已存在（MapReduce 作业拒绝覆盖）。
