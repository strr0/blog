Linux 环境下 SeaTunnel 的安装与使用

strr0 2023-10-17

1 概述

SeaTunnel 是一个分布式数据集成平台（Apache 项目，前身叫 Transfer）：用一个作业配置描述“从哪读、中间怎么处理、往哪写”，剩下的切分、并行、重试、一致性由引擎处理。它适合批量/实时的表与库之间同步（ETL 中的 EL 为主），不适合当复杂业务编排工具。

三个使用前的关键信息：

  • 运行模式：Local（本文用的 -e local，进程内跑，适合单机与测试）、Standalone（SeaTunnel 自带的 Zeta 引擎集群，有完整的 checkpoint、重试与 Web 管理）、以及提交到已有的 Flink / Spark 集群。单机能跑不代表能在集群跑，迁移前先看作业配置里依赖的 connector 在目标引擎上是否支持。
  • 版本：本文用 2.3.3（2023 年），SeaTunnel 迭代很快，2.3.x 后续版本与 3.x 在 connector 包名、配置字段上有不少调整（例如较新版本用 alias 代替 result_table_name/source_table_name 传递表名）。升级前重点对照 connector 兼容表与配置变更日志。
  • Java 版本：2.3.x 支持 Java 8 与 Java 11。同一集群里 Server 与客户端要用同一个 JDK，混用容易在序列化与兼容类上报奇奇怪怪的错误。

2 SeaTunnel 部署

2.1 环境需求

java 环境（java 8 或 java 11）

具体搭建方式参考 Java 环境搭建；确认 java -version 与 JAVA_HOME 已设，否则 install-plugin.sh 与启动脚本会报找不到 Java。

2.2 下载 SeaTunnel

下载并解压

wget "https://archive.apache.org/dist/seatunnel/2.3.3/apache-seatunnel-2.3.3-bin.tar.gz"
tar -xzvf "apache-seatunnel-2.3.3-bin.tar.gz"

Apache 的 archive.apache.org 保留历史版本（当前版本走 dlcdn.apache.org），国内访问慢时可用镜像站（如清华/阿里云的 apache dist）。解压后目录布局：bin/（启动与提交脚本）、config/（作业模板、hazelcast*.yaml、seatunnel.yaml、plugin_config）、connectors/（插件）、lib/（公共依赖，JDBC 驱动放这里）、starter/、logs/。

2.3 安装连接器插件

配置所需要的插件，如 jdbc 插件

# config/plugin_config

--seatunnel-connectors--
connector-jdbc
--end--

执行命令安装插件

sh bin/install-plugin.sh 2.3.3

参数是 SeaTunnel 版本号，脚本会从 Maven 仓库把 connector-jdbc 等 jar 拉到 connectors/ 下（镜像名形如 connector-jdbc-2.3.3.jar）。公司内网或不能访问 Maven Central 时，先在 ~/.m2/settings.xml 配好 mirror 再跑；下载不完整会表现为作业报 NoClassDefFoundError 或 can not find plugin jar。较新版本可以不传版本号（脚本自己读当前安装版本）。

JDBC 所依赖的驱动程序需要复制到 $SEATUNNEL_HOME/lib/ 目录下，才能保证作业正常运行

这句话背后的原因是开源协议：MySQL/PostgreSQL 之外的驱动（达梦、SQL Server、Oracle）不能随 Apache 项目分发，所以安装脚本不会帮你下。驱动要放 lib/（而不是 connectors/），放 connectors/ 会因为类加载隔离而报 ClassNotFoundException: dm.jdbc.driver.DmDriver；新增驱动后需重启作业进程。

3 运行作业

3.1 环境依赖

  • 已部署的 SeaTunnel

3.2 作业配置（Demo）

# config/v2.batch.config.template

env {
  execution.parallelism = 1
  job.mode = "BATCH"
}

source {
  FakeSource {
    result_table_name = "fake"
    row.num = 16
    schema = {
      fields {
        name = "string"
        age = "int"
      }
    }
  }
}

transform {
  FieldMapper {
    source_table_name = "fake"
    result_table_name = "fake1"
    field_mapper = {
      age = age
      name = new_name
    }
  }
}

sink {
  Console {
    source_table_name = "fake1"
  }
}

3.3 执行作业

运行如下命令执行作业

cd apache-seatunnel-2.3.3
./bin/seatunnel.sh --config ./config/v2.batch.config.template -e local

-e local 在单机模式下等价于 -e local 不起常驻集群，直接在一个 JVM 里跑完退出（生产上对应的命令是 -m 指向 Hazelcast 集群地址，而不是 local）。这个 Demo 只验证安装链路（FakeSource 造数据→Console 输出），看到 16 行 {"name":"...","age":...} 输出就说明引擎与作业解析都正常。常用参数还有 -j <jobId>（提交到集群后查状态）、--check_config（只校配置不执行）。

4 实测：达梦到达梦的批量同步

4.1 环境准备

  • 服务器配置 128 核 512g 内存
  • Java 8
  • SeaTunnel 2.3.3
  • 达梦数据库及测试数据

4.2 驱动配置

将达梦数据库驱动 DmJdbcDriver18.jar 复制到 $SEATUNNEL_HOME/lib/ 目录下

文件名里的 18 指适配 JDK 1.8；如果跑在 Java 11 上也用这个包。驱动版本要与达梦服务端版本匹配（大版本不一致时会在握手阶段报版本相关错误）。

4.3 作业配置

# config/v2.batch.config

env {
  execution.parallelism = 10  # 并行数
  job.mode = "BATCH"
}

source {
  Jdbc {
    url = "jdbc:dm://localhost:5236/xxxx"
    driver = "dm.jdbc.driver.DmDriver"
    connection_check_timeout_sec = 100
    user = "xxxx"
    password = "********"
    query = "select * from xxxx.xxxx"
    fetch_size = 10000
    # partition_column = "PART_ID"  # 分区字段
    partition_num = 40  # 分区数
  }
}

#transform {
#}

sink {
  jdbc {
    url = "jdbc:dm://localhost:5236/xxxx"
    driver = "dm.jdbc.driver.DmDriver"
    user = "xxxx"
    password = "********"
    query = "insert into xxxx.xxxx(xxxx,xxxx,xxxx) values(:xxxx,:xxxx,:xxxx)"
  }
}

4.4 执行作业

./bin/seatunnel.sh --config ./config/v2.batch.config -e local

4.5 运行结果

数据量并行数分区数设置分区字段耗时
800w1010否11 分钟
800w2020否11 分钟
800w44否11 分钟
800w440否11 分钟
800w10100否11 分钟
800w1040否10 分钟
800w1040是18 分钟

这组数据能读出三件事：

  1. 并行数堆上去基本不涨速（10→20→100 都是 11 分钟左右）。因为没配 partition_column 时只有一个 JDBC 连接在执行 select * from xxxx.xxxx，并行度只加在 transform/sink 环节，读取本身就是串行瓶颈。
  2. partition_num 单独调大无效（第 4、5 行）：分区数是跟着并行度生效的，没有分区字段时它不会自己把读操作拆成多个连接。
  3. 真分区反而更慢（最后一行 18 分钟）：partition_column 要求选一个有索引的数值/时间列，否则每个分区的 where col between ? and ? 都变全表扫描，N 个分区就是 N 次全表扫；同时连接数与达梦侧的并发压力也上去了。

要真的提速，先确认分区列上有索引，再让 execution.parallelism 与分区数对齐（而不是 40 个分区跑 4 并行）；如果源库允许，把单表拆成按主键区间的多个 source（多个 Jdbc 块 + union）比依赖 partition_column 更可控。瓶颈在源库还是在目标库的写入，则分别看 fetch_size（读取批次，默认 1024）与 sink 的 batch_size/is_batch_save。

5 SeaTunnel-Web 部署

5.1 环境要求

  • 已部署 SeaTunnel
  • MySQL

5.2 下载与安装

从 https://seatunnel.apache.org/download 下载 seatunnel web，并解压

tar -zxvf apache-seatunnel-web-1.0.0-SNAPSHOT.tar.gz

Web 端与主工程的发布节奏不同步，1.0.0-SNAPSHOT 这种带 SNAPSHOT 的包质量与版本兼容都不稳定，上生产前先备份配置并先在测试环境跑通一两个真实作业。它本身是个 Spring Boot 应用，元数据（用户、作业、实例信息）存 MySQL，而作业的运行状态靠 Hazelcast 连到 SeaTunnel 集群。

5.3 初始化数据库（MySQL）

修改 seatunnel_server_env.sh 配置

# script/seatunnel_server_env.sh

export HOSTNAME="localhost"
export PORT="3306"
export USERNAME="root"
export PASSWORD="123456"

运行命令初始化

sh script/init_sql.sh

init_sql.sh 会先 source 同目录的 seatunnel_server_env.sh 取连接信息，建库建表并插入默认账号（admin/admin）——也就是 5.5 “user does not exists” 那个坑的解药。执行前确认 MySQL 可连、账号有建库权限，并且 seatunnel 库名与 application.yml 里的 URL 一致（库名改了会默默建到另一个库，启动时报表不存在）。

5.4 配置修改

修改 application.yml 数据库连接配置

# conf/application.yml

spring:
  datasource:
    driver-class-name: com.mysql.jdbc.Driver
    url: jdbc:mysql://localhost:3306/seatunnel?useSSL=false&useUnicode=true&characterEncoding=utf-8&allowMultiQueries=true&allowPublicKeyRetrieval=true
    username: root
    password: password  # 根据实际情况修改

com.mysql.jdbc.Driver 是 Connector/J 5.x 的类名，MySQL 8 配套的驱动已经改名为 com.mysql.cj.jdbc.Driver（旧类名在新驱动里会打 deprecation 警告并在部分版本下直接加载失败），与 8.0+ 服务端一起用建议把 MySQL 驱动 jar 放进 lib/ 并改掉这一行。URL 里的参数也要核对：useSSL=false 在启用 TLS 的实例上会连不上；serverTimezone=Asia/Shanghai 缺失时 8.x 驱动可会报时区相关错误；allowMultiQueries=true 是 Web 端初始化脚本需要的，但不建议对外暴面开。

复制 hazelcast-client.yaml 到 conf/

cp $SEATUNNEL_HOME/config/hazelcast-client.yaml conf/

这一步不只是“拷个文件”：拷过来后还要把里面的 member-list（默认 127.0.0.1:5801）改成 SeaTunnel 集群实际可达的地址，并把 cluster-name 与 config/hazelcast.yaml 里的保持一致，不一致时 Web 能启动但作业列表永远为空。如果 SeaTunnel 跑在别的机器或容器里，5801 端口需要开放。 复制 plugin-mapping.properties 到 conf/

cp $SEATUNNEL_HOME/connectors/plugin-mapping.properties conf/

启动 SeaTunnel-Web

sh bin/seatunnel-backend-daemon.sh start

访问 http://127.0.0.1:8801/ui/ 即可进入 web 端（admin/admin）

三个安全与运维提醒：默认账号 admin/admin 登录后必须立刻改；bin/seatunnel-backend-daemon.sh 用 nohup 启动，日志就在当前目录的 nohup.out（跑一阵后容易长很大，配合 logrotate 或定期清理）；8801 没有 HTTPS 也不接认证代理，不要直接暴公网，参考 Linux 环境下 Nginx 的安装与使用 加一层反代并限制来源。

6 问题与修复

6.1 空指针问题

checkpoint 超时导致，可增大 timeout 解决

# config/seatunnel.yaml

seatunnel:
  engine:
    checkpoint:
      interval: 100000
      timeout: 6000000

现象通常是作业日志里一堆 NullPointerException 且伴随 checkpoint ... timeout：checkpoint 完成得比超时阈值还慢时，引擎侧状态会处于未完成中间态，引用到未初始化的上下文就报 NPE。interval 是两次 checkpoint 的间隔（毫秒），timeout 是单次允许耗时；批量作业里如果一次全量读取超过 100 秒，把 interval 拉大、timeout 拉到 6000000（100 分钟）就能消。改完需重启集群才生效。

6.2 数据重复问题

未配置 checkpoint 导致，checkpoint 用于记录数据中间状态，确保数据不会丢失和重复

准确地说，checkpoint 提供的是至少一次 + 可恢复：作业失败后从上一个完成的 checkpoint 重放，如果 sink 端没有幂等保证就会重复。真正的不重复需要两边配合：开 checkpoint（env { checkpoint.interval = ... }）+ sink 支持两阶段提交或幂等写入。JDBC sink 的 exactly_once = true 依赖数据库 XA（达梦支持但要确认账号有相应权限），否则只能靠主键/唯一约束做幂等（先 delete where ... 再 insert，或用数据库的 upsert 语法）。

6.3 作业配置问题

① source 参数和 sink 参数完全一致的情况下可以不使用 transform，sink 中的 insert 语句可以直接使用 ? 占位符

② 使用 transform 导致 ? 占位符匹配参数错位，可以使用 :param（参数名称）来指定参数

③ 作业 sink 参数个数必须与 source 参数个数一致，否者作业会执行失败，可用 transform 过滤

这三条归结为一个事实：sink 的列位置是按 schema 顺序对上的。补充两种可靠写法：不用 transform 时把 source 的 query 就写成 select a, b, c from ...，列顺序与 sink 的 :a,:b,:c 一一对应；列多或需要改名/过滤时用下面的 field_mapper 声明，比依赖默认列序安全。另外字段名大小写与达梦/Oracle 系的存储习惯相关（默认大写），不匹配时报的是列不存在而不是类型错，很容易误判。

transform {
  FieldMapper {
    source_table_name = "fake"
    result_table_name = "fake1"
    field_mapper = {
        id = id
        card = card
        name = new_name
    }
  }
}

6.4 java.net.BindException: 地址已在使用 (Bind failed)

查看端口是否占用

netstat -alnp | grep 8801

新系统上 netstat 已被 ss 取代（没装 net-tools 时直接命令不存在），等价写法是 ss -lntp | grep 8801。8801 是 Web 端口，如果 SeaTunnel 集群也在同一台机器，另外要排掉 5801（Hazelcast）被占。

如果端口被占用，执行命令杀死

kill -9 103436

原稿把“（进程号）”写在了命令里，那一行直接复制执行会报语法错误。另外优先用 sh bin/seatunnel-backend-daemon.sh stop 正常停，kill -15 给 JVM 退出机会；kill -9 会跳过 shutdown hook，可能残留 Hazelcast 成员注册与锁文件。

6.5 Web 端 404 问题

查看运行日志，可以看到 user does not exists

tail -f nohup.out

...user does not exists

user does not exists 说明后端起来了但元数据表里没有默认账号——绝大多数是 5.3 的 init_sql.sh 没跑或跑到了另一个库。先 select * from t_user; 确认（表名前缀以实际脚本为准），没数据就重新初始化一次并重启后端。

尝试通过 nginx 跳转进入

# nginx.conf

#...
# SeaTunnel-Web
server {
    listen 8808;
    server_name localhost;

    location / {
        proxy_pass http://127.0.0.1:8801;
    }

    location /ui {
        root /linewell/seatunnel/apache-seatunnel-web-1.0.0-SNAPSHOT;
        index index.html index.htm;
    }
}

重启 nginx

/usr/local/nginx/sbin/nginx -s reload -c /usr/local/nginx/conf/nginx.conf

这份 Nginx 配置本身有个经典坑：location /ui { root /linewell/seatunnel/apache-seatunnel-web-1.0.0-SNAPSHOT; } 用 root 时，Nginx 拼出的路径是 <root>/ui/index.html，而磁盘上的静态文件在 <解压目录>/index.html（不带 ui 这一层），因此 404。两种正确写法之一：改用 alias /linewell/seatunnel/apache-seatunnel-web-1.0.0-SNAPSHOT/;，或把文件放到父目录下的 ui/ 子目录里（location /ui/ 与 alias 两边斜杠要对齐）。SPA 还需要回退：try_files $uri $uri/ /ui/index.html;，否则刷新子路由也 404。另一个细节是前端资源的访问前缀要与 location /ui 匹配（不匹配时 index.html 能打开但 JS/CSS 全 404，现象是白屏），对应规则见 Linux 环境下 Nginx 的安装与使用 的 4.2。

7 小结

  • 部署上只有三件事：解压、install-plugin.sh 拉 connector、把 JDBC 驱动放 lib/（不是 connectors/），漏最后一件就会在连非 MySQL 数据库时报 ClassNotFoundException。
  • Local 模式能跑不等于集群能跑；集群侧要额外对齐 hazelcast-client.yaml 的 member-list 与 cluster-name，否则 Web 连不上集群。
  • 实测表明瓶颈在源库读取：没配 partition_column 时并行度再高也没用；配了但分区列无索引反而更慢（多次全表扫描）。
  • 数据不丢不重需要 checkpoint 与 sink 幂等（或两阶段提交）两者配合，单开 checkpoint 只能保证可恢复。
  • SeaTunnel-Web 的两个默认坑：忘跑 init_sql.sh（登录 404 / user does not exists）与默认口令 admin/admin 未改。
