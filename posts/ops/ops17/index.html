数据库版本管理工具 Liquibase

strr0 2024-12-31

1 概述

Liquibase 把数据库 schema 变更当作代码来管：变更写在版本库的 ChangeLog（XML/YAML/SQL）里，工具按顺序执行并把结果记录到两张元数据表——DATABASECHANGELOG（哪些 changeset 执行过）与 DATABASECHANGELOGLOCK（防止并发迁移）。由此获得三个能力：新环境一键建库（按 changelog 重放）、环境间差异可审计（diff 生成变更而不是口头改库）、发布可回退（rollback）。

本文走的是 Maven 插件路线（mvn liquibase:xxx），适合手工驱动的迁移与差异对比；应用侧另有 Spring Boot 自动迁移模式（启动时自动 update，见 3.2），两者共用同一套 changelog。几个概念一次对齐：

术语含义
ChangeLog变更清单文件（入口常叫 changelog.xml），用 <include> 组织多个变更文件
ChangeSet最小执行单元，id + author 全局唯一；执行过一次就不会再执行
url / referenceUrldiff 的两个对象库：主库与参照库
rollbackchangeset 配套的回滚定义（DDL 需要手写 <rollback>，不是所有变更都能自动回）

2 配置

2.1 依赖说明

插件版本
liquibase-maven-plugin4.26.0

2.2 项目配置

依赖配置

<!-- 需要用到的驱动需要添加到依赖中 -->
<dependencies>
    <dependency>
        <groupId>com.mysql</groupId>
        <artifactId>mysql-connector-j</artifactId>
    </dependency>

    <dependency>
        <groupId>org.postgresql</groupId>
        <artifactId>postgresql</artifactId>
    </dependency>
</dependencies>

<build>
    <plugins>
        <plugin>
            <groupId>org.liquibase</groupId>
            <artifactId>liquibase-maven-plugin</artifactId>
            <version>${liquibase-maven-plugin.version}</version>
            <configuration>
                <propertyFileWillOverride>true</propertyFileWillOverride>
                <!-- 指定配置文件路径 -->
                <propertyFile>src/main/resources/liquibase.properties</propertyFile>
            </configuration>
        </plugin>
    </plugins>
</build>

两个容易报错的点：驱动依赖没写 <version> 的前提是工程继承了 spring-boot-starter-parent（或导入了 BOM），普通工程里必须补版本号，否则 pom 解析阶段就失败；插件执行时用的也是本工程 classpath 上的驱动，目标库是 PG 就不能只放 mysql 驱动。propertyFileWillOverride=true 允许命令行 -D 参数覆盖 properties 文件里的值（CI 里临时切库名/密码就靠它）。

liquibase 配置

# liquibase.properties

# changeLog 路径配置
changeLogFile=src/main/resources/db/changelog.xml
outputChangeLogFile=src/main/resources/db/changelog-output.xml
diffChangeLogFile=src/main/resources/db/changelog-diff.xml

# 数据库连接配置
driver=com.mysql.cj.jdbc.Driver
url=jdbc:mysql://localhost:3306/testdb
username=root
password=password
referenceDriver=org.postgresql.Driver
referenceUrl=jdbc:postgresql://localhost:5432/postgres
referenceUsername=postgres
referencePassword=password

# 表过滤配置
# excludeObjects=table_name, table:main_.*, column:*._lock, table:primary.*
includeObjects=test_demo

# 对比配置
diffTypes=columns, foreignkeys, indexes, primarykeys, tables, uniqueconstraints, views

# 其他配置
changeSetAuthor=strr
outputFileEncoding=UTF-8
verbose=true

配置文件的分组逻辑：

  • 三个输出路径各对应一条命令：outputChangeLogFile→generateChangeLog（从现有库反向生成），diffChangeLogFile→diff（两库对比），后者没配则只打控制台。
  • url 组与 referenceUrl 组是 diff 的两端：url 是主库（通常是要被更新的那套），reference 是参照库（通常是你手工改好的开发库）。diff 产物要把主库改成和参照库一致，可能包含 DROP 列/删索引这类破坏性语句，落地前逐条人审；不在 diff 场景时 reference 四行注掉即可。
  • 对象过滤用正则时要带类型前缀（table:main_.*、column:*._lock），includeObjects 与 excludeObjects 二选一用。
  • MySQL 的 url 建议带全参数（?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai，对照 基础环境配置 4.1 里 Nacos 那段 MYSQL_SERVICE_DB_PARAM），否则生成列类型时可能因字符集/时区判断差异出意外。
  • 密码明文写进 properties 的文件不要提交仓库：用 -Dliquibase.password=... 命令行注入，或按 profile 放多份 properties 文件由 CI 选择（profile 机制见 Maven 打包配置 3.2）。

3 使用

3.1 基础操作

3.1.1 生成 ChangeLog

outputChangeLogFile 为输出文件路径，Liquibase 会根据文件后缀生成不同类型的 ChangeLog 文件

mvn liquibase:generateChangeLog

从零接入的标准第一步：把存量库反向生成 changelog 作为基线（只生成结构，数据要用 <insert>/data loader 另补）。注意它会覆盖 outputChangeLogFile 指定的文件，基线生成后应手工拆分整理（按模块/日期分文件）再提交，而不是一直维护一个巨文件。

3.1.2 执行更新

changeLogFile 为 ChangeLog 文件路径，Liquibase 会根据该文件执行更新操作

mvn liquibase:update

update 只执行 DATABASECHANGELOG 里没记录过的 changeset（按 id+author+文件名判重），重复执行安全；已执行过的 changeset 如果内容被改动，下次 update 会报 checksum 校验失败——这是保护而非 bug，正确做法是新建一个 changeset 修补，不要改历史（除非确认所有环境都还没执行过并愿意重建记录）。

3.1.3 对比数据库差异

diffChangeLogFile 为差异文件路径（未配置该路径则打印差异到控制台）

mvn liquibase:diff

典型工作流：开发库手工调完结构 → diff 对照测试/生产库生成变更 → 人审后整理成带 id/author/rollback 的 changeset 提交 → 各环境 update。diff 产物不会自动带 rollback，补上才有后面 3.1.5 的回滚能力。

3.1.4 生成数据库文档

mvn liquibase:dbDoc -Dliquibase.outputDirectory=target/docs

3.1.5 回滚

三种定位方式选一。

指定回滚条数

mvn liquibase:rollback -Dliquibase.rollbackCount=<count>

指定回滚标签

mvn liquibase:rollback -Dliquibase.rollbackTag=<version>

指定回滚日期

mvn liquibase:rollback -Dliquibase.rollbackDate=<yyyy-MM-dd>

回滚能力取决于 changeset 里写了什么：DDL（建表/加列）默认不会自动反向执行，需要配套的 <rollback> 定义（或直接给 rollback="SQL"），没写 rollback 的 changeset 回滚时直接报错；标记类（rollbackTag）需要事先用 <tag> 在 changelog 里打过标签。把"能不能回"想成发布前的检查项，而不是事后依赖。

3.2 Spring 整合

依赖配置

<dependency>
    <groupId>org.liquibase</groupId>
    <artifactId>liquibase-core</artifactId>
</dependency>

application 配置

spring:
  liquibase:
    change-log: classpath:db/changelog.xml
    database-change-log-table: DATABASECHANGELOG             # ChangeLog 表配置（可选）
    database-change-log-lock-table: DATABASECHANGELOGLOCK    # ChangeLogLock 表配置（可选）

项目启动后会自动根据 ChangeLog 执行数据库变更记录。三点补充：

  • 版本由 Spring Boot BOM 管理时不用写 <version>；Boot 3.x 自带 Liquibase 4.2x，和本文 maven 插件保持同一条产品线，避免同一套 changelog 两边解析行为不一致。
  • 多实例同时启动时靠 DATABASECHANGELOGLOCK 串行化：第一个实例迁移，其余等锁（等不到会启动失败），蓝绿/滚动发布要确认锁等待时间够用；不想让应用进程持有 DDL 权限的，把 spring.liquibase.enabled: false 关掉、改由 CI 里跑 mvn liquibase:update（接 Jenkins/GitLab CI 的流水线）。
  • changelog 拆分推荐显式 <include> 或 <includeAll path="db/changelog/"/>，文件名带日期序号（V1__xxx 风格）保证顺序确定；多环境差异用 context 控制哪些 changeset 在哪些环境执行。

一个可直接参考的 changeset 形态：

<changeSet id="20250101-add-demo-col" author="strr">
    <addColumn tableName="test_demo">
        <column name="remark" type="VARCHAR(255)"/>
    </addColumn>
    <rollback>
        <dropColumn tableName="test_demo" columnName="remark"/>
    </rollback>
</changeSet>

4 小结

  • Liquibase 的核心是两张元数据表：changeset 按 id+author 判重只执行一次，改历史会触发 checksum 保护；修补靠新 changeset。
  • Maven 插件路线五条命令各管一段：generateChangeLog 建基线、update 应用、diff 拿差异（产物含破坏性语句要人审）、dbDoc 出文档、rollback 回滚（前提是有 <rollback>）。
  • Spring 整合把 update 前置到启动阶段，多实例靠锁表串行；对 DDL 权限敏感的团队改为 CI 驱动。
  • properties 里的明文密码不进仓库，用 -D 覆盖或多文件 profile 交给 CI。
