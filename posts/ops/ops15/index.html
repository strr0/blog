Maven 打包配置

strr0 2024-10-17

1 概述

同一份代码，打包方式其实只有两种哲学，选哪种取决于部署形态：

方式产物适合代价
一体包（fat jar）单个 jar，内置全部依赖Docker/单机部署，java -jar 即跑改一行代码也要重传几十 MB 的包；依赖变更无法单独替换
代码依赖分离zip：主 jar + lib/ + config/传统虚机部署、内网增量发布（依赖不变时只替换几 KB 的主 jar）启动脚本、classpath 布局要自己维护

本文两种都给出可直接粘贴的插件配置，后面的 profile/资源过滤与常用参数章节则是各类 CI 脚本里踩坑的高发区（Jenkins、GitLab CI/CD、RuoYi-Vue-Plus 框架 都引用过这里）。

2 打包方式

2.1 常规方式（代码依赖不分离）

插件如下

插件版本备注
spring-boot-maven-plugin3.1.7项目代码打包

2.1.1 添加打包插件

<plugin>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-maven-plugin</artifactId>
    <version>${spring-boot.version}</version>
    <executions>
        <execution>
            <goals>
                <goal>repackage</goal>
            </goals>
        </execution>
    </executions>
</plugin>

关键在 repackage：普通 maven-jar-plugin 先产出只含自己类的 jar，repackage 再把它包装成 Boot 布局（依赖进 BOOT-INF/lib/，应用类与资源进 BOOT-INF/classes/，Main-Class 指向 JarLauncher）。父工程已用 spring-boot-starter-parent 时 goals 可省略，但显式写上更保险（拷到非 Boot 父工程的项目里不会失效）。

2.1.2 运行打包命令

运行打包命令，插件会自动识别启动类，并打包成一体包，直接启动即可

mvn clean package -DskipTests

启动就是 java -jar target/xxx.jar。多个 @SpringBootApplication 时插件会报 Unable to find a single main class，要显式配 <mainClass>。Dockerfile 里 COPY ./target/*.jar 的前提就是这条命令跑过（RuoYi-Vue-Plus 框架 3.2 的 COPY failed 即源于此）。

2.2 其他方式（代码依赖分离）

插件如下

插件版本备注
maven-dependency-plugin3.6.1依赖输出
maven-jar-plugin3.3.0项目代码打包（可配置包含及忽略文件）
maven-assembly-plugin3.6.0其他文件打包（如依赖及配置文件等）

2.2.1 依赖输出

插件配置

  • outputDirectory - 输出路径
  • excludeTransitive - 排除传递依赖，一般情况设置为 false
  • stripVersion - 去掉版本号
  • excludeArtifactIds - 排除指定的依赖
  • includeScope - 包含指定 scope

注意两个配置值的暗坑：excludeTransitive=false 才会把"依赖的依赖"拷全（设 true 时 lib/ 缺包，启动即 NoClassDefFoundError）；stripVersion=false 保留版本号，和 manifest 里 addClasspath 生成的条目名保持一致——如果改成 true，下面的 <classpathPrefix> 也要同步去版本，否则 Class-Path 对不上。

添加插件及设置如下配置

<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-dependency-plugin</artifactId>
    <version>${maven-dependency-plugin.version}</version>
    <executions>
        <execution>
            <id>copy-dependencies</id>
            <phase>package</phase>
            <goals>
                <goal>copy-dependencies</goal>
            </goals>
            <configuration>
                <outputDirectory>${project.build.directory}/lib</outputDirectory>
                <excludeTransitive>false</excludeTransitive>
                <stripVersion>false</stripVersion>
                <includeScope>runtime</includeScope>
            </configuration>
        </execution>
    </executions>
</plugin>

2.2.2 项目代码打包（不含依赖）

插件配置

  • mainClass - 启动类路径
  • addClasspath - 设置 classpath
  • classpathPrefix - classpath 前缀
  • excludes - 忽略文件

注意 addClasspath 生成的 Class-Path 清单指向的是 lib/xxx.jar 相对路径，所以运行时必须"解压后的目录结构不变"，不能只把 jar 拷走。

添加插件及设置如下配置

<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-jar-plugin</artifactId>
    <version>${maven-jar-plugin.version}</version>
    <configuration>
        <archive>
            <manifest>
                <mainClass>com.example.demo.DemoApplication</mainClass>
                <addClasspath>true</addClasspath>
                <classpathPrefix>lib/</classpathPrefix>
            </manifest>
        </archive>
        <excludes>
            <exclude>**/*.yml</exclude>
            <exclude>**/*.properties</exclude>
            <exclude>**/*sh</exclude>
            <exclude>**/bin</exclude>
            <exclude>**/config</exclude>
        </excludes>
    </configuration>
</plugin>

2.2.3 其他文件打包

插件配置

  • descriptor - 指定 assembly 配置文件路径

添加插件及设置如下配置

<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-assembly-plugin</artifactId>
    <version>${maven-assembly-plugin.version}</version>
    <configuration>
        <appendAssemblyId>false</appendAssemblyId>
        <outputDirectory>target/</outputDirectory>
        <descriptors>
            <descriptor>zip-desc.xml</descriptor>
        </descriptors>
    </configuration>
    <executions>
        <execution>
            <id>package-zip</id>
            <phase>package</phase>
            <goals>
                <goal>single</goal>
            </goals>
        </execution>
    </executions>
</plugin>

assembly 文件配置

<assembly>
    <id>zip-desc</id>
    <!-- 打包类型，这里设置zip，则最终输出一个zip包 -->
    <formats>
        <format>zip</format>
    </formats>
    <!-- 设置项目外目录的处理方式，一条规则一个fileSet -->
    <fileSets>
        <fileSet>
            <directory>src/main/resources</directory>
            <outputDirectory>/config</outputDirectory>
            <excludes>
                <exclude>mapper/**</exclude>
                <exclude>META-INF/**</exclude>
            </excludes>
        </fileSet>

        <fileSet>
            <directory>target/lib</directory>
            <outputDirectory>/lib</outputDirectory>
        </fileSet>

        <fileSet>
            <directory>target</directory>
            <outputDirectory>/</outputDirectory>
            <includes>
                <include>*.jar</include>
            </includes>
        </fileSet>
    </fileSets>
</assembly>

原稿 fileSet 的 excludes 写的是 src/main/resources/mapper 这种全路径：<excludes> 的匹配基准是 <directory> 本身，路径永远匹配不上，mapper 目录会被照样打进 config/（即"配置泄漏进发布包"）。已改成相对目录的 mapper/** 与 META-INF/**。把 mapper XML 排除在外是故意的：它们已经在 jar 里（classpath 资源），再拷一份到外部 config/ 只会造成"两处修改不同步"的隐患。

2.2.4 运行打包命令

运行打包命令，插件会生成一个代码和依赖分离的 zip 包

mvn clean package -DskipTests

产物在 target/ 下的 zip：解压后保持 xxx.jar + lib/ + config/ 的相对布局，启动用 java -jar xxx.jar（Class-Path 清单自动找 lib/）；外置 config/ 能被读到靠的是 Spring Boot 的配置搜索顺序（默认包含 ./ 与 ./config/），所以启动目录必须是解压目录，或者显式 --spring.config.additional-location= 指定。

3 常用参数与 profile

3.1 跳过测试的两种写法

参数效果适用
-DskipTests不执行测试，但编译测试代码日常推荐：测试代码写错了能被发现
-Dmaven.test.skip=true不执行也不编译测试代码老测试代码编译不过时的逃生门

两者与 -D 之间都不能有空格（-D maven.test.skip=true 会被拆成两个参数，静默不生效，RuoYi-Vue-Plus 框架 3.1 就是这个坑）。

3.2 Maven profile ≠ Spring profile

mvn package -P prod 选的是 Maven 的 <profiles>，它本身不会改变应用行为；只有当 pom 配了资源过滤（<resources><filtering>true</filtering>）时，application.yml 里的 @packageTime@、@profiles.active@ 这类占位才会在打包时被替换成 profile 的值。也就是说：-P prod 能不能把环境写进 jar，取决于 pom 里有没有过滤配置；而 spring.profiles.active=prod 是运行时参数，两者名字像、机制完全无关。占位符能被解析的前提还有：Spring Boot 父工程默认把过滤分隔符从 ${...} 改成了 @...@，写在 @ 之间的才有效。

3.3 多模块增量构建

mvn clean package -pl ruoyi-admin -am -DskipTests

-pl（projects list）只构建指定模块，-am（also make）把它的依赖模块一并构建；大型工程反复调一个模块时比全量 package 快得多。只改主应用 jar 的场景（代码依赖分离包）甚至可以不跑 Maven，直接替换 zip 里的主 jar。

3.4 依赖拉不下来的两类原因

  • Maven 3.8.1+ 默认封禁 HTTP 仓库：报错带 maven-default-http-blocker。首选把仓库地址改 HTTPS；内网只有 HTTP 时在 settings.xml 里声明一个 <mirror> 指向内网仓并配 <blocked>false</blocked>（覆盖默认 blocker mirror），不要在 pom 里散改。
  • 本地仓有 jar 但打包报"not downloaded from it"：见下节 4.1。

4 问题与解决

4.1 本地存在某个 jar 包，但是无法打包

因为这个 jar 包是从远程仓库获取的，所以打包的时候 maven 会自动从远程仓库获取此 jar 包，而由于某些原因可能无法从远程获取此 jar 包，导致打包失败。解决办法：从远程仓库获取的 jar 包，在本地对应的路径下会有一个 _remote.repositories 文件（标记此 jar 包是从远程获取的），删除此文件并重新打包。

原理：Maven 3 的本地仓会校验"这个构件是不是从当前配置的仓库来的"，换镜像源/仓库下线后校验失败就拒绝使用本地文件。除了删标记文件，还有两个更可控的选项：手工产物用 mvn install:install-file -Dfile=xxx.jar -DgroupId=... -DartifactId=... -Dversion=... -Dpackaging=jar 正规装进本地仓；或者临时加 -o（离线模式，只用本地仓，代价是所有新依赖都拉不到）。公司内网长期方案还是把私有构件发到 Nexus/制品库。

4.2 分离包启动报 ClassNotFoundException / NoClassDefFoundError

九成是目录布局被破坏：lib/ 没和主 jar 放同级、classpathPrefix 与实际目录名不一致、或 2.2.1 的 stripVersion 与 manifest 条目对不上。排障时直接 unzip -p xxx.jar META-INF/MANIFEST.MF 看 Class-Path 列的条目名，和 lib/ 里的文件名逐个对。

5 小结

  • Docker/单机选一体包，一条 repackage 解决；虚机/内网增量发布用分离包，三插件各司其职（dependency 拷依赖、jar 写清单、assembly 组装 zip）。
  • 分离包的前提是"解压后的相对布局不变"，Class-Path、config/ 都是相对路径机制。
  • -DskipTests 与 -Dmaven.test.skip 的差别在"编译不编译测试代码"；Maven 的 -P 只有配合资源过滤才会影响产物。
  • 依赖类报错先想两件事：3.8+ 的 HTTP 封禁，和本地仓的 _remote.repositories 来源校验。
