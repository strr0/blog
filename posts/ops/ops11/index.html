PagePlug 低代码平台

strr0 2023-12-05

1 概述

PagePlug 是 Appsmith 的中国化开源项目（行云创新开源，仓库：https://github.com/cloudtogo/pageplug），在 Appsmith 基础上做了性能优化与汉化，并集成了 Formily 表单组件、ECharts 图表组件和低代码小程序开发能力。它的定位是面向研发的前端低代码：不侵入现有架构，直接连数据源（API、DB），把后端数据变成 JS 变量配到视图组件上，快速生成 PC Web 应用和微信小程序。

理解架构对搭环境很重要，因为启动步骤就是按这几块来的：

组件技术栈默认端口本地启动方式
后端服务Java（基于 Appsmith 早期版本）8080build.sh 构建 + start-dev-server.sh
前端设计器React（CRA）3000yarn start-win / yarn start
元数据存储MongoDB27017外部依赖
缓存/任务队列Redis6379外部依赖

注意两个前提：这个仓库的构建脚本大量面向 Linux/macOS，Windows 下需要 git bash 环境；另外它基于的 Appsmith 版本较老（当前开源版基于 1.7.x），Java 11 而非新版本，升级依赖时不要直接对齐 Appsmith 最新版。

2 快速开始

2.1 环境需求

  • java 11
  • maven 3
  • mongodb
  • redis

Java/Maven 的安装与环境变量配置参考 基础环境配置，MongoDB/Redis 分别参考 MongoDB 安装 与 Redis 安装。Java 版本这里必须是 11：它用的是 Appsmith 老版本的 Spring Boot 依赖树，JDK 17 编译会报错；Maven 3.8.x 默认封禁 HTTP 仓库，依赖拉不下来时参考 Maven 打包配置。

2.2 环境搭建

2.2.1 Redis

参考 Redis 安装。Redis 在这里不只是缓存，后端的异步任务队列也依赖它，没起 Redis 时页面能打开但保存/发布应用会莫名卡住。

2.2.2 MongoDB

参考 MongoDB 安装。MongoDB 存的是全部元数据（用户、应用、页面、数据源配置），相当于平台的"库就是命"，建议搭好之后定期 mongodump（备份方法见 ops5 的备份章节）。

2.3 启动

2.3.1 后端启动

进入后端目录

cd app/server

创建环境变量文件

cp envs/dev.env.example .env

修改环境变量

# .env

APPSMITH_MONGODB_URI="你的 Mongo 实例地址（可不配置副本集）"
APPSMITH_REDIS_URL="你的 Redis 实例地址"

.env 里至少要把两个地址改成真实实例，默认值指向容器网络内的主机名，本机直跑连不上。变量前缀保留着 APPSMITH_（fork 自 Appsmith 的历史遗留命名，搜配置项时按这个前缀搜，不要按 PagePlug 搜）。本地单实例可不配副本集；生产环境如果要连副本集，URI 里要带 replicaSet 参数。

构建 java 服务

mvn clean compile
bash ./build.sh -DskipTests

build.sh 内部会再调一次 Maven 打包，前面的 mvn clean compile 是先把依赖拉齐、提前暴露编译问题，两步顺序不要倒。-DskipTests 是透传给 build.sh 内部 Maven 命令的，测试集量大、本地验证时跳过能省很多时间。

启动 java 服务

bash ./scripts/start-dev-server.sh

这个脚本除了拉起 jar，还会用 rsync 同步构建产物、用 lsof/kill 清理旧进程，所以它对 Windows 不友好：

bash 命令可以使用 git bash，rsync 命令需下载客户端，并解压到 {git 安装路径}/usr/bin 下

补一句：脚本里还依赖 lsof，git bash 默认没有，遇到 lsof: command not found 时可在 git bash 的 usr/bin 里补上，或者直接用 java -jar target/*.jar 代替整个脚本（代价是没有自动 kill 旧进程）。

2.3.2 前端启动

先进入前端路径，再配环境变量（原稿把 cp 写在 cd 之前，在仓库根目录执行会找不到 .env.example）：

cd app/client

cp .env.example .env

代理配置（可使用 nginx 代替）

yarn add http-proxy-middleware

创建 setupProxy.js

// src/setupProxy.js

const { createProxyMiddleware } = require('http-proxy-middleware');
module.exports = function (app) {
  app.use(createProxyMiddleware('/api', {
    target: 'http://localhost:8080',
    changeOrigin: true
  }))
  app.use(createProxyMiddleware('/oauth2', {
    target: 'http://localhost:8080',
    changeOrigin: true
  }))
  app.use(createProxyMiddleware('/login', {
    target: 'http://localhost:8080',
    changeOrigin: true
  }))
};

这是 CRA（create-react-app）的约定：src/setupProxy.js 会被自动加载，不用在代码里 import。三个前缀 /api、/oauth2、/login 都要代理到后端 8080，漏了 /login 会在登录时报 404。文件位置在 app/client/src/ 下，不是仓库根目录。用 nginx 代替时，本质就是把这三个前缀反代到 8080，proxy_pass 尾斜杠规则参考 Linux 环境下 Nginx 的安装与使用 的 3.2。

启动前端服务

yarn
yarn start-win

yarn 不带参数是安装依赖（等价 yarn install）；start-win 是 package.json 里为 Windows 单独准备的启动脚本（处理路径大小写敏感问题），macOS/Linux 下用 yarn start。Node 版本对 CRA 老项目建议 14/16，Node 18+ 可能报 ERR_OSSL_EVP_UNSUPPORTED（webpack4 的老问题），临时解法是 set NODE_OPTIONS=--openssl-legacy-provider，更干净的做法是用 Volta 锁死项目 Node 版本。

启动成功后访问 http://localhost:3000 即可（初次使用需要创建用户）。前后端分别监听 3000/8080，前端页面白屏时先确认 8080 活着（curl http://localhost:8080/api/v1/version），再开浏览器控制台看代理是否 404。

3 小结

  • PagePlug = Appsmith 中国化 fork：后端 Java + 前端 React(CRA)，元数据存 MongoDB、任务队列靠 Redis，四样缺一不可。
  • Java 必须是 11（老依赖树）；.env 两个地址要改成真实实例，变量前缀仍是 APPSMITH_。
  • Windows 搭环境的两个主要障碍都在后端启动脚本：rsync/lsof 需要手工补进 git bash，或者直接 java -jar 绕过脚本。
  • 前端靠 src/setupProxy.js 把 /api、/oauth2、/login 三个前缀代理到 8080；start-win 是 Windows 专用脚本，Linux/macOS 用 yarn start。
