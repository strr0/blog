基础环境配置

strr0 2024-11-11

概览

Linux 开发环境基础组件的安装手册，每个组件都按"下载 → 安装 → 环境变量 → 验证"四步组织：JDK 8/17、Maven、Git（源码编译）、Nacos（Docker 部署）与 firewalld 端口配置。命令以 RHEL/CentOS 系（yum）为准，Debian 系把 yum install 换成 apt install、/etc/profile 的做法可换成 /etc/profile.d/ 下单独建文件。环境变量统一写进 /etc/profile 是"全机生效"的简单做法，代价是所有用户共享同一套 JDK/Maven 版本；机器上要多版本共存时，建议改用版本目录 + 切换脚本，或交给 SDKMAN! 这类工具。

1 Java 环境

1.1 JDK 8

1.1.1 下载

wget https://download.oracle.com/otn/java/jdk/8u431-b10/0d8f12bc927a4e2c9f8568ca567db4ee/jdk-8u431-linux-x64.tar.gz

两个现实问题：Oracle 的 otn 下载链接带哈希串、会过期，且 Oracle JDK 商用许可需要登录接受协议，wget 经常返回 404 或授权页。生产环境建议改用免登录、开源免费的发行版（Eclipse Temurin / Dragonwell / BellSoft），替换 URL 后续步骤完全相同。另外 wget 默认断点续传会保留失败文件名，下载后用 file 或大小确认拿到的是 tar.gz 而不是 HTML。

1.1.2 安装

解压到指定路径

sudo mkdir -p /usr/local/java
sudo tar -xzvf jdk-8u431-linux-x64.tar.gz -C /usr/local/java

-p 是为了目录已存在时不报错（JDK 17 那节的同名目录会冲突，见 1.2.2 的说明）。解压后目录名是 jdk1.8.0_431，下面的 JAVA_HOME 要与之严格一致，拿不准先 ls 一下。

1.1.3 环境变量配置

修改环境变量

# /etc/profile

JAVA_HOME=/usr/local/java/jdk1.8.0_431
CLASSPATH=.:$JAVA_HOME/lib/dt.jar:$JAVA_HOME/lib/tools.jar
export JAVA_HOME
export PATH=$PATH:$JAVA_HOME/bin:$JAVA_HOME/jre/bin

新版 profile 的改动对老程序兼容，但交互 shell 才会加载它：systemd 服务、cron、GitLab Runner（见 GitLab CI/CD 的 4.1）都不会读 /etc/profile，它们报"找不到 java"时要去服务配置里补环境变量。另外 CLASSPATH 那行是 JDK 8 时代的习惯残留（dt.jar/tools.jar 现代应用基本用不到，当前目录 . 也不是必需的），只保留 JAVA_HOME 和 PATH 即可。 应用环境变量

source /etc/profile

1.1.4 验证

运行命令验证

java -version

1.2 JDK 17

1.2.1 下载

wget https://download.oracle.com/java/17/latest/jdk-17_linux-x64_bin.tar.gz

/17/latest/ 是固定 URL、内容随版本漂移：今天下到的可能是 17.0.1x，而解压后目录名跟着版本号变，直接抄 1.2.3 的 jdk-17.0.8 会造成 PATH 指向不存在的目录。稳妥做法是下完解压后 ls /usr/local/java 拿真实目录名再配 JAVA_HOME，或改用带版本号的下载路径。

1.2.2 安装

解压到指定路径

sudo mkdir -p /usr/local/java
sudo tar -xzvf jdk-17_linux-x64_bin.tar.gz -C /usr/local/java

同一台机器可以并存 JDK 8 与 17（目录互不覆盖），但 /etc/profile 里只能有一套生效的 JAVA_HOME；需要临时切换时用 export JAVA_HOME=... 覆盖当前 shell，长期共存建议上 alternatives/切换脚本。

1.2.3 环境变量配置

修改环境变量

# /etc/profile

JAVA_HOME=/usr/local/java/jdk-17.0.8
export PATH=$PATH:$JAVA_HOME/bin

应用环境变量

source /etc/profile

1.2.4 验证

运行命令验证

java -version

1.3 问题与修复

JDK 17 在精简版 Linux（常见于容器、最小化安装的服务器）上的报错基本都围绕字体库缺失，因为 AWT/图片处理（验证码、Excel 图表、PDF 导出）依赖 freetype/fontconfig：

  1. Cannot load from short array because “sun.awt.FontConfiguration.head” is null

Linux 缺失字体导致，从 jdk 1.8 的 jre/lib 复制 fontconfig.bfc 到安装的 jdk 17 的 lib 中

  1. Caused by: java.lang.UnsatisfiedLinkError: /usr/local/java/jdk-17.0.8/lib/libfontmanager.so: libfreetype.so.6: cannot open shared object file: No such file or directory

jdk 依赖缺失，安装如下依赖

yum install freetype    # yum install fontconfig

注意这行里的 # 在 bash 里是真注释：只会执行 yum install freetype，想装两个包要写 yum install freetype fontconfig。

  1. Caused by: java.lang.RuntimeException: Fontconfig head is null, check your fonts or fonts configuration

同 2，或使用 bellsoft-jdk 替换

  1. Caused by: java.lang.Error: Probable fatal error: No physical fonts found

缺失字体

yum install fontconfig

2 Maven 环境

2.1 下载

wget https://archive.apache.org/dist/maven/maven-3/3.6.3/binaries/apache-maven-3.6.3-bin.tar.gz

3.6.3 是为了兼容老项目选的保守版本；新项目建议直接用 3.8/3.9，但要注意 3.8.1 起默认封禁 HTTP 仓库，内网 Nexus/镜像如果还是 http:// 地址会报 maven-default-http-blocker，解法与镜像配置参考 Maven 打包配置。

2.2 安装

解压到指定路径

sudo mkdir -p /opt/maven
sudo tar -xzvf apache-maven-3.6.3-bin.tar.gz -C /opt/maven

2.3 环境变量配置

修改环境变量

# /etc/profile

M2_HOME=/opt/maven/apache-maven-3.6.3
export PATH=$PATH:$M2_HOME/bin

应用环境变量

source /etc/profile

装完建议顺手配国内镜像：编辑 $M2_HOME/conf/settings.xml（或用户级 ~/.m2/settings.xml）加 aliyun 的 <mirror>，否则中央仓库拉依赖会很慢。

2.4 验证

运行命令验证

mvn -version

输出里重点看两行：Java version 确认 Maven 实际用的 JDK（多版本共存时它跟随 JAVA_HOME），Maven home 确认没有装到旧副本上。

3 Git 环境

没有现成 rpm 版本、或者需要 http2/特定特性时才走源码编译；一般场景 yum install git 或 IUS 仓库的 git2xx 更省事。源码编译需要先装依赖，否则 make 阶段才报错：

# 先装编译依赖（缺哪个报哪个，容易在 make 时才暴露）
yum install gcc libcurl-devel expat-devel gettext-devel openssl-devel zlib-devel perl-ExtUtils-MakeMaker

3.1 下载

wget https://www.kernel.org/pub/software/scm/git/git-2.39.3.tar.xz

3.2 解压

tar -xvf git-2.39.3.tar.xz

3.3 编译及安装

cd git-2.39.3
make configure
./configure --prefix=/usr/local/git
make prefix=/usr/local/git
sudo make install

原稿第三行写的是 make profix=/usr/local/git（prefix 拼错）：make 会把它当成一个无意义的变量赋值，安装目录回退到默认的 /usr/local，后面 GIT_HOME=/usr/local/git 指到空目录，git --version 直接命令不存在。已按正确拼写修正，并给 make install 加了 sudo（往 /usr/local 写文件普通用户没权限）。想跳过编译文档（需要 asciidoc/xmlto）可以加 NO_GETTEXT=1 NO_TCLTK=1 ASCIIDOC_NO_OPTIONS=1，或者干脆 make prefix=/usr/local/git all doc 分开处理。

3.4 环境变量配置

修改环境变量

# /etc/profile

GIT_HOME=/usr/local/git
export PATH=$PATH:$GIT_HOME/bin

应用环境变量

source /etc/profile

3.5 验证

git --version

4 Nacos 环境

4.1 安装

4.1.1 通过 Docker 安装

拉取镜像

docker pull nacos/nacos-server:v2.3.0

创建容器前要先建好数据库：v2.x 的外置数据源模式需要 Nacos 自己的表结构，官方包里有现成脚本，先在 MySQL 里执行：

create database nacos character set utf8mb4;
-- 然后导入发行包 conf/mysql-schema.sql（github 上同名文件）

没导表就直接启动，容器会报 Unknown database 'nacos' 或表不存在相关错误并反复重启。

创建环境变量文件

# nacos.env

MODE=standalone
NACOS_AUTH_ENABLE=true
SPRING_DATASOURCE_PLATFORM=mysql
MYSQL_SERVICE_HOST=yourhost
MYSQL_SERVICE_DB_NAME=<db>
MYSQL_SERVICE_PORT=3306
MYSQL_SERVICE_USER=<user>
MYSQL_SERVICE_PASSWORD=<pwd>
MYSQL_SERVICE_DB_PARAM=characterEncoding=utf8&connectTimeout=1000&socketTimeout=3000&autoReconnect=true&useUnicode=true&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
NACOS_AUTH_IDENTITY_KEY=2222
NACOS_AUTH_IDENTITY_VALUE=2xxx
NACOS_AUTH_TOKEN=SecretKey012345678901234567890123456789012345678901234567890123456789

这份 env 里几个要注意的点：

  • MODE=standalone 是单机模式；集群部署要去掉它并配 NACOS_SERVERS 节点列表。
  • NACOS_AUTH_ENABLE=true 后，NACOS_AUTH_TOKEN 必须是长度足够的 Base64 串（v2.2.0 起该值缺失或不合法会直接启动失败），示例里那串是官方文档占位值，生产必须换成自己生成的（openssl rand -base64 48）；NACOS_AUTH_IDENTITY_KEY/VALUE 两处 2222/2xxx 同样是占位符，含义是集群节点间请求的身份标识，也要改。
  • token 改了不等于安全：nacos/nacos 默认账号要在控制台第一时间改掉，管理端口 8848 不应暴露公网。

创建容器并启动

docker run -d \
    --name nacos-server \
    -p 8848:8848 \
    -p 9848:9848 \
    -v ./nacos/logs:/home/nacos/logs \
    --env-file nacos.env \
    nacos/nacos-server:v2.3.0

端口解释：2.x 除了主端口 8848，客户端还会用 gRPC 端口 9848（= 主端口 + 1000） 做长连接，Server 之间用 9849；只开 8848 会表现为客户端报 connect to 127.0.0.1:9848 failed。gRPC 端口是自动推算的，不能通过改映射偏移，跨机部署时防火墙要把 9848/9849 一起放开（见第 5 节）。日志挂了 ./nacos/logs，数据在 MySQL 里，容器本身无状态，重建成本低。

4.2 使用

4.2.1 管理端

启动成功后使用 nacos/nacos 访问 http://localhost:8848/nacos 即可进入 web 管理页面（v2.2+ 首次登录会强制要求修改默认密码；如果开了鉴权却登录报 unknown user，检查是否忘了导 mysql-schema.sql 里的用户表数据）。改过密码后，应用侧配置里的 username/password 也要同步更新，参考 Spring 整合 Nacos。

4.2.2 Spring 整合

参考 Spring 整合 Nacos，客户端同样需要能访问 9848 gRPC 端口。

5 防火墙配置

firewalld 的端口操作区分"运行时（runtime）“与"持久（–permanent）“两套配置：带 --permanent 的修改只写进持久配置，必须 --reload（或重启服务）才对当前生效；不带则立即生效但重启后丢失。日常习惯是：--permanent 加完规则后统一 --reload。

5.1 获取所有端口

firewall-cmd --list-all

输出里 services 和 ports 两块都要看：只放行了 80/tcp 但服务走的是 8080，就是这里没对上。快速验证端口是否通：在另一台机器 telnet <ip> <port> 或 curl -v。

5.2 开放端口

firewall-cmd --zone=public --add-port=8080/tcp --permanent

协议后缀别写错：/tcp 与 /udp 是两类规则；改完记得 firewall-cmd --reload。

5.3 关闭端口

firewall-cmd --remove-port=8080/tcp --permanent

remove 只对持久配置有效；如果当初是用不带 --permanent 开的端口，得用 --remove-port=8080/tcp（不带 permanent）或在 runtime 里清理，必要时 --complete-refresh-rules 级别的重置。最简单的兜底是 firewall-cmd --reload 后确认 runtime 与 permanent 两侧都没残留。

5.4 刷新端口

firewall-cmd --reload

--reload 不中断已有连接，只重新加载规则；相比 firewall-cmd --complete-reload（会断开当前连接）安全得多，日常用前者就够。另外云服务器上除了机器内的 firewalld，还有安全组一层，两处任一没放开都连不通——排查时先 ss -lntp 确认服务真的在监听，再逐层往外查。

6 小结

  • 四步法记住两个通用坑：/etc/profile 只影响交互 shell（systemd/cron/Runner 不读它）；source 之前先确认目录名与 JAVA_HOME/M2_HOME 严格一致。
  • JDK 17 精简系统上的报错几乎都是字体库问题，yum install freetype fontconfig 一条解决大半。
  • 源码编译 Git 记得先装 devel 依赖，且 make prefix= 不能拼错（拼错不报错，只是装到默认目录）。
  • Nacos 2.x 三件事：先导 mysql-schema.sql；鉴权占位符（token/identity）要换成真实值并改默认密码；防火墙要连 gRPC 端口 9848/9849 一起放开。
  • firewalld 的 --permanent 必须配合 --reload，云端还要叠加检查安全组。
