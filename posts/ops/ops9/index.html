RuoYi-Vue-Plus 框架

strr0 2023-10-24

1 概述

RuoYi-Vue-Plus 是在 RuoYi-Vue 基础上重写的版本，面向分布式集群与多租户场景，与原框架不兼容（不是升级关系，不要直接搬配置与代码）。它把很多“自建框架时要踩的坑”预先做了：多租户过滤、数据权限、脱敏与敏感词、操作/登录日志、文件存储 OSS、定时任务、幂等与分布式锁等。

技术栈与模块划分（理解这个比记命令重要，因为启动与部署都是按模块来的）：

模块作用
ruoyi-admin主应用（对外 HTTP API，默认 8080），启动类 RuoYiApplication
ruoyi-common公共封装（satoken、redisson、mybatis、excel、oss 等各类 starter）
ruoyi-modules业务模块（system、job 等）
ruoyi-extend可选运维组件：ruoyi-monitor-admin（Spring Boot Admin）、ruoyi-powerjob-server（任务调度中心）
plus-ui前端（Vue 3 + Vite + Element Plus）

依赖的中间件：MySQL、Redis（不止是缓存，Sa-Token 的会话、分布式锁、限流都基于它，所以 Redis 挂了等于登录体系挂了），可选 MinIO/OSS、PowerJob、Elasticsearch（版本与能力以仓库 README 为准，这个项目迭代很快，本文对应 5.1.0 分支）。

2 快速开始

2.1 环境需求

  • java 17
  • mysql 5.7 8.0
  • redis 5.X 6.X 7.X
  • maven 3.6.3 3.8.X
  • nodejs >= 14
  • npm 8.X

逐项补充：Java 17 是硬要求（Spring Boot 3 不支持 JDK 11）；MySQL 5.7 需要确认 group_concat_max_len（默认 1024 会把多值拼接查询静默截断）与 sql_mode 兼容配置，8.0 默认即可；Maven 3.8.x 默认封禁 HTTP 仓库，依赖拉不下来时参考 Maven 打包配置；前端那行写的是 nodejs >= 14，但这是当时文档的值，Vite 5 已经要求 Node 18+，实际建议直接用 18/20 LTS 并考虑用 pnpm（新版前端工程对 pnpm 的 lockfile 更友好，版本管理可参考 Node.js 版本管理工具 Volta）。

2.2 初始化

2.2.1 Redis 环境搭建

参考 Linux 环境下 Redis 的安装与使用。应用侧的连接与序列化用法参考 Spring 整合 Redis。

2.2.2 MySql 环境搭建

参考 Linux 环境下 MySQL 的安装与使用。建库时把字符集定为 utf8mb4（与 Docker 安装 4.8 里那份 compose 配置一致），否则导入 SQL 时注释里的中文与 emoji 字段会报 Incorrect string value。

2.2.3 拉取代码

git clone https://gitee.com/dromara/RuoYi-Vue-Plus.git

仓库在 Gitee 与 GitHub 都有镜像，国内拉 gitee 地址快；如果你在公司代理后报证书/超时，参考 Docker 安装 4.5 的代理部分或给 git 单独配 http.proxy。

2.2.4 初始化数据

依次导入 sql 数据：

  • script/sql/ry_vue_5.X.sql
  • script/sql/test.sql
  • script/sql/powerjob.sql

三个文件的定位不一样：ry_vue_5.X.sql 是必须的（表结构与菜单/字典等基础数据）；test.sql 是演示业务表，不上测试功能可以不导；powerjob.sql 只在启用 ruoyi-powerjob-server 时需要（而且它是 PowerJob 自身的库，一般单独建一个 powerjob 库而不是和业务表混在一个 schema）。导入前先 create database 再 use，否则脚本里没带建库语句时会报“No database selected”；重复执行会因建表语句已存在而中断（部分表已建一半时先 drop database 重建比手工清表干净）。导入后重点核对：菜单表有数据（否则登录后空白页）、当前时间与时区正常（否则日志/定时任务调度错乱）。

2.3 应用启动

应用列表

  • MonitorAdminApplication 为 Admin 监控服务（非必要，可参考对应文档关闭）
  • PowerJobServerApplication 为任务调度中心服务（非必要，可参考对应文档关闭）
  • RuoYiApplication 为主应用服务

本地跑只需要起 RuoYiApplication，但前提是先把配置文件里的数据源与 Redis 地址改掉（ruoyi-admin/src/main/resources/ 下的 application.yml / application-dev.yml，按 spring.profiles.active 取值）。两个与 profile 相关的坑：一是 Maven 的 -P prod 与 Spring 的 spring.profiles.active 不是一回事，前者只切 Maven profile，能不能把环境写进 jar 取决于 pom 里的过滤配置，具体机制见 Maven 打包配置；二是 application-dev.yml 里带真实密码的配置文件容易随手提交，建议用环境变量覆盖（Spring Boot 支持 SPRING_DATASOURCE_URL、SPRING_DATA_REDIS_PASSWORD 这类松绑定变量，优先级高于配置文件）。另外 Sa-Token 的会话与登录相关能力参考 Sa-Token 单点登录。

2.4 前端

安装依赖

npm install --registry=https://registry.npmmirror.com

启动服务

npm run dev

命令要在 plus-ui 目录下执行（不是仓库根目录）。--registry 只对当次生效，长期用镜像源可 npm config set registry https://registry.npmmirror.com；依赖报 EBADENGINE 就是 Node 版本不够（见 2.1）。开发环境接口地址由 .env.development 里的 VITE_APP_BASE_API 控制（默认 /dev-api），而它能不能打到后端取决于 Vite 的 proxy 或部署时的 Nginx 配置——这一层前缀规则与反代写法参考 Linux 环境下 Nginx 的安装与使用。

3 部署

3.1 maven 打包

mvn clean package -Dmaven.test.skip=true -P prod

原稿写的是 -D maven.test.skip=true（-D 与参数名之间有空格），这样传不进去：Maven 会把 -D 解析成一个空值属性，后面的 maven.test.skip=true 会被当成另一个位置参数。参数与 -D 必须连写（或写 -DskipTests）。两者区别：-DskipTests 跳过测试执行但仍编译测试代码，-Dmaven.test.skip=true 连编译一起跳（更快，但测试代码里的编译错不会被发现）。打包整个工区耗时较长，只想重打主应用时用 mvn clean package -pl ruoyi-admin -am -P prod（-am 会把它依赖的模块一起构建）。

3.2 Admin 监控服务

构建 ruoyi-monitor-admin 镜像并启动

docker build -t ruoyi/ruoyi-monitor-admin:5.1.0 ruoyi-extend/ruoyi-monitor-admin
docker run -d \
    --name ruoyi-monitor-admin \
    -p 9090:9090 \
    ruoyi/ruoyi-monitor-admin:5.1.0

三个服务都遵循同一个套路，先说两个共性问题：

  • 先 mvn package 再 docker build。模块目录里的 Dockerfile 是 COPY ./target/*.jar，没先打包时 build 会直接报 COPY failed: no source files were specified。
  • 环境变量与配置覆盖。三个容器都不带 -v，容器内的 application.yml 指向的是仓库默认值（localhost 的 MySQL/Redis）。容器里连宿主服务时不能写 localhost（那指容器自己），要么用宿主内网 IP，要么 --network host，要么把它们放进同一个 Docker 网络用容器名互访（参考 Docker 安装 的 4.2）；正式部署建议直接挂配置或用环境变量覆盖。

监控服务（Spring Boot Admin）默认 9090，它需要能访问各应用的 actuator 端点；各应用也要把自己注册地址配好并在 application.yml 里填监控中心的账号密码才能上报。监控页面本身没有强认证，不要直接暴公网。

3.3 任务调度中心服务

构建 ruoyi-powerjob-server 镜像并启动

docker build -t ruoyi/ruoyi-powerjob-server:5.1.0 ruoyi-extend/ruoyi-powerjob-server
docker run -d \
    --name ruoyi-powerjob-server \
    -p 7700:7700 \
    -p 10086:10086 \
    -p 10010:10010 \
    ruoyi/ruoyi-powerjob-server:5.1.0

PowerJob 需要三个端口：7700 是 Server 的 Web 控制台与 OpenAPI（登录后默认账号口令要改），10086 与 10010 是 Server 与 Worker（即主应用）之间的内部通信端口。跨机器部署时这三个端口都要互通，只开 7700 会表现为“控制台看得到项目，任务下发就超时”；容器化部署时尤其要注意 server 回连 worker 时需要拿到 worker 的真实 IP，因此宿主网络模式（--network host 或明确指定 POWERJOB_WORKER akka 地址）比默认 bridge 更不容易出问题。调度中心还需要 2.2.4 里导入的 powerjob.sql 对应的数据库，否则启动即报数据源错误。

3.4 主应用服务

构建 ruoyi-admin 镜像并启动

docker build -t ruoyi/ruoyi-server:5.1.0 ruoyi-admin
docker run -d \
    --name ruoyi-server \
    -p 8080:8080 \
    ruoyi/ruoyi-server:5.1.0

注意镜像名是 ruoyi/ruoyi-server 而构建目录是 ruoyi-admin（历史遗留命名，容易在写 compose 与 CI 脚本时弄混）。主应用上还挂着上传/日志/本地缓存类目录，镜像里没有持久化，至少要把日志目录与本地上传目录挂出来；用 MinIO/OSS 时参考 Spring 整合 Minio 与 Linux 环境下 MinIO 的安装与使用。对外访问链路一般是“前端静态资源 + /prod-api/ 反代”，模板见 Linux 环境下 Nginx 的安装与使用 的 3.2。

4 部署检查清单

项说明
JDK17 是硬下限（Spring Boot 3）；镜像基础 JDK 与编译时版本一致
配置中心MySQL/Redis 地址在容器内不能写 localhost；密码优先用环境变量而不是改 yml
SQLry_vue_5.X.sql 必需；powerjob.sql 单独库；导入前建库并定 utf8mb4
Maven profile-P prod 不等于 spring.profiles.active=prod，过滤配置见 ops15
打包参数-Dmaven.test.skip=true 中不能有空格；只改主应用用 -pl ruoyi-admin -am
端口8080 主应用、9090 Admin、7700/10086/10010 PowerJob（三个都要互通）
默认账号后端管理、Admin 监控、PowerJob 控制台三套默认口令都要改
存储日志、上传目录、OSS 配置（MinIO 时注意桶与生命周期）
多租户多租户与环境变量、菜单初始化强相关，新租户要确认菜单/角色已分配
前端Node 版本（建议 18+）、VITE_APP_BASE_API 与 Nginx proxy_pass 前缀对齐

5 小结

  • 它是重写而非升级：模块拆成 ruoyi-admin（主应用）、ruoyi-modules（业务）、ruoyi-extend（可选监控与调度），启动与部署都按模块走。
  • Redis 不只是缓存，它承担会话与分布式锁，因此 Redis 不可用会直接表现为登录不上，而不只是变慢。
  • docker build 前一定要先 mvn package（Dockerfile 直接 COPY ./target/*.jar）；打包参数不能写成 -D maven.test.skip=true。
  • 三个服务共三个默认后台（Admin 监控、PowerJob 控制台、主应用），都需改口令且不应直接暴露公网。
