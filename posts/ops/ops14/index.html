Linux 环境下 MinIO 的安装与使用

strr0 2024-08-01

1 概述

MinIO 是一种高性能、S3 兼容的开源对象存储，单二进制部署、自带管理控制台，常用作应用上传文件、备份集、图片视频的用户态存储底座（RuoYi-Vue-Plus 的 OSS 模块、各类中间件的快照仓库都能指到它）。两个端口分工记清楚能避免大半天数的排障：

  • 9000：S3 API 端口，SDK、mc、应用配置里的 endpoint 都指向它
  • 9001：Web 控制台端口，浏览器管理界面（建桶、Access Key、策略）

两个选型前提：MinIO 自 2021 年起采用 AGPLv3 许可，闭源集成/二次分发场景要先过法务；另外 2024 年底之后的新版本大幅精简了控制台管理功能（建用户、改策略等被移除，官方引导用 mc admin），本文示例锁定的 RELEASE.2023-03-24 仍带完整 UI，升级前先确认自己依赖哪些控制台能力。

2 安装

2.1 二进制安装

2.1.1 下载

wget https://dl.minio.org.cn/server/minio/release/linux-amd64/minio
chmod +x minio
sudo mv minio /usr/local/bin/

严格说这是预编译二进制安装而非源码编译（原稿标题易误导）；dl.minio.org.cn 是官方国内域名，国际用 dl.min.io。下完可以用 ./minio --version 验证拿到的确实是可执行文件而不是错误页。

2.1.2 启动

MINIO_ROOT_USER=admin MINIO_ROOT_PASSWORD=password minio server /data --address ":9000" --console-address ":9001"

几点说明：

  • 两个密码要求至少 8 位（user 至少 3 位），不满足会直接启动失败报 minimum 8 characters，这是新手最常见的第一个报错。
  • 这条命令是前台运行，长期服务用 systemd 托管或至少 nohup ... &；环境变量多了以后建议写进单独 env 文件而不是行首内联。
  • /data 就是桶的根目录（单盘模式下一个桶一个子目录），服务运行期间不要手工在里面增删文件——MinIO 有自己的元数据与校验逻辑，绕过接口改目录会出脏数据。
  • admin/password 仅适用于本地验证，公网上这一对等于把存储送人（改密入口见 3.1）。

2.2 通过 Docker 安装

2.2.1 拉取镜像

docker pull minio/minio:RELEASE.2023-03-24T21-41-23Z

MinIO 没有语义化版本，tag 是构建时间戳（RELEASE.YYYY-MM-DDTHH-MM-SSZ），锁定日期 tag 是对的，latest 会在某天悄悄改变控制台能力。国内拉取慢时可用官方国内镜像仓 dl.minio.org.cn 指引的 registry。

2.2.2 运行容器

docker run -d \
    --name minio-server \
    -p 9000:9000 \
    -p 9001:9001 \
    -e MINIO_ROOT_USER=admin \
    -e MINIO_ROOT_PASSWORD=password \
    -v ./minio/data:/data \
    -v ./minio/config:/root/.minio \
    minio/minio:RELEASE.2023-03-24T21-41-23Z \
    server --address ':9000' --console-address ':9001' /data

两个 -v 是命脉：数据与配置全在容器外的这两个目录里，删了卷等于删库（容器本身的层不存业务数据，参考 Docker 安装 的数据卷章节）。建议在 docker run 前 mkdir -p ./minio/data ./minio/config，相对路径基于当前工作目录，换目录启动会凭空"丢数据"（其实只是没挂到原卷）。端口没写 IP 默认监听所有网卡，只想本机用改成 127.0.0.1:9000:9000。

3 使用

3.1 管理端

http://localhost:9001（账号密码 admin/password）

登录后常规流程：Create Bucket 建桶 → Bucket Manager 设访问策略 → Access Keys 给应用发专用密钥。第一件事是改默认口令（右上角账号 → Access Keys/改根凭证，或直接换环境变量重启）；应用侧不要用根账号，单独建只有目标桶读写策略的 Access Key。开发用 dev15 的配置值就是这里的 endpoint(9000) + Access Key。

3.2 mc 客户端与数据迁移

默认数据路径 /data。官方命令行工具 mc 需要先配 alias（把"endpoint+密钥"存成一个名字），再按别名操作：

# 安装 mc（Linux 二进制）
wget https://dl.minio.org.cn/client/mc/release/linux-amd64/mc && chmod +x mc && sudo mv mc /usr/local/bin/

# 把本地服务登记为别名 backup（走的是 9000 API，不是直接读磁盘）
mc alias set backup http://127.0.0.1:9000 admin password

备份数据到 backup

mc cp --recursive /data/mybucket backup

这条命令的真实含义是：/data/mybucket 走本地文件系统读，backup 走 S3 API 写——只在"单机、直接在存服务器上操作、桶就在 /data 下"的前提下成立。更通用的做法是两端都用别名（mc mirror local-alias/mybucket backup/mybucket-backup），mc mirror 支持增量同步与断点续传，日常同步/迁移比 cp --recursive 合适；直接往 /data 里写文件则完全绕过了鉴权和校验，永远不要这样"导入"数据。

4 问题与修复

4.1 AccessDenied

报错通常是两种语义，先分清：

  1. 匿名访问被拒（浏览器直接打开文件 URL 报 AccessDenied）：桶是私有的。登录 minio 后台，进入桶管理（Administrator > Buckets），选择指定的桶，将 Summary 下的 Access Policy 修改为 Public。但 Public 是整桶可读，适合头像/静态资源这类不在乎泄露的内容；含用户数据的桶应保持私有，由应用用 SDK 生成预签名 URL（presigned URL，带临时有效期）对外分享，用法见 Spring 整合 Minio。
  2. SDK/控制台带凭证操作被拒：按顺序检查 Access Key 是否属于根账号还是受限 Key、Key 的 policy 是否覆盖目标桶、endpoint 是否误连到了 9001（控制台端口，API 请求打过去必然失败）。

4.2 启动即退出：密码不合规

MINIO_ROOT_PASSWORD 少于 8 位时日志报 Minimum 8 characters 并拒绝启动；Docker 形态下表现是容器反复重启，docker logs minio-server 一看便知。

5 小结

  • 记住双端口分工：应用/SDK/mc 走 9000，浏览器控制台走 9001；endpoint 连错端口是最常见的"莫名失败"。
  • 两种部署形态的风险都在数据：二进制形态不要手工改 /data；Docker 形态两个 -v 卷丢了等于丢库。
  • 默认口令与 Public 桶是两个安全面：根密码改掉、应用用受限 Access Key、公开范围越小越好。
